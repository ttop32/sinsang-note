### A-1. 카드 이미지가 정사각형이 아니라 높이 400px 로 고정된다 (전 화면·전 카드)

**재현**
1. https://ttop32.github.io/sinsang-note/ 를 375×812 로 연다.
2. 첫 카드 이미지를 잰다.

**기대 vs 실제**
- 기대: `aspect-ratio:1` 대로 정사각형 (164×164)
- 실제: **164×400 (비율 2.45:1)**. 이미지가 세로로 길게 잘려 제품이 화면 밖으로 나간다.
  1280px 데스크톱에서도 255×400 (1.57:1). 측정한 **270장 전부** 비정사각형.
- 같은 그리드의 이미지 없는 카드(`.ph`)는 164×164 정사각형이라, 행마다 카드 높이가 들쭉날쭉하다.

**추정 원인**
`<img width="400" height="400">` 의 height 속성이 presentational hint 로 `height:400px` 를 만든다.
저자 CSS(`web/theme.py:33` `.c img,.ph{width:100%;aspect-ratio:1;object-fit:cover;...}`)가 `height` 를
선언하지 않아 hint 가 그대로 이기고, height 가 확정되므로 `aspect-ratio` 는 무시된다.
같은 레포의 상세 페이지 CSS(`web/pages.py:38`)에는 `height:auto` 가 들어 있어 상세 페이지만 정상이다.

**상태** 검수 도중 로컬에 `collect.py:348` 로 `.c img{height:auto;aspect-ratio:1/1;object-fit:cover}` 가 추가됐다.
배포본에는 아직 없다(2026-09-30 확인 시점 `height:auto` 0건). 다만 이 규칙은 `web/theme.py:33` 과 **두 파일에 나뉘어**
같은 셀렉터를 정의하게 되니, 정본 위치를 정리하는 게 맞다(theme.py 주석이 "색·타이포는 theme 것만 쓴다"고 못박고 있다).

**심각도** 높음 — 전 카드, 모바일에서 특히 심하다.

## B. 데이터가 틀린다

### B-1. 신제품이 아닌 것이 신제품으로 올라온다 — 300장 중 265장(88%)이 `baseline=True`

운영자가 세 번 지적한 그 문제다. 코드가 막으려던 경로를 실제로는 통과하고 있다.

**측정**
- 배포본 300장 중 **265장이 `baseline: true`** — 브랜드 합류 당일에 기준선으로 쌓은 행이다.
  `is_fresh` 주석은 이걸 "신제품이 아니다"라고 명시한다.
- 그중 **155장**은 `날짜 없음 + is_new=True` 경로로 들어왔다:
  CU 40, 세븐일레븐 38, 커피빈 28, 설빙 14, 빽다방 11, 미스터피자 9, 파파존스 4, 던킨 4, 굽네치킨 4, 프랭크버거 3.
- 300장 중 **185장(62%)은 브랜드가 준 날짜가 아예 없다.** 카드에 찍힌 `<time>` 은 우리 크롤러가 처음 본 날이다.
  커피빈 28장·미스터피자 19장·던킨 16장·설빙 14장·빽다방 11장·파파존스 6장·이마트24 4장·프랭크버거 3장은
  **전부 `2026-09-30`** — 합류일이 그대로 "출시일"로 표시된다.

**눈으로 확인한 반례**
- 커피빈 "리치 코코넛 아이스 블렌디드", "쫀득 흑임자 아이스 블렌디드" → 이미지 파일명이 `여름 3차 신메뉴`.
  "바닐라 빈 플랫화이트" → `2026 07 여름 2차 신메뉴`. **7월 여름 상품이 9월 30일 신상으로 떠 있다.**
  "함안 수박 주스", "천도복숭아 요거트 아이스 블렌디드" 도 여름 메뉴.
- 던킨 16장 중 12장은 `is_new=None` 인데 전부 2026-09-30:
  "피치 아이스티 (R)", "피치 아이스티 (K)", "초코 (R)", "아이스 초코 (S)",
  "비타슬러시 레몬/리치/펀치/믹솔로지 (R)" → **상시 메뉴판이다.**

**추정 원인**
`collect.py` `is_fresh()` 의 판정 순서.
- `collect.py:290` `if r.get("is_new") is True:` 가 맨 앞이다. 날짜가 없으면 `stamped` 가 None 이라
  `not (None and ...)` → **무조건 True**. `collect.py:315` 의 `if r.get("baseline"): return False` 가드까지 절대 도달하지 않는다.
- 브랜드의 "신메뉴" 페이지를 통째로 긁는 수집기는 그 페이지 전부에 `is_new=True` 를 붙이므로,
  합류 당일 그 브랜드의 신메뉴 탭 전체가 한 번에 쏟아진다.

**심각도** 높음 — 서비스의 핵심 약속이 깨진다.

## C. 잠재적

### C-1. `/c/디저트/`, `/c/분식/` 이 404 인데 상품 18페이지가 링크한다

- `https://ttop32.github.io/sinsang-note/c/디저트/` → **404** (상품 17페이지가 링크)
- `https://ttop32.github.io/sinsang-note/c/분식/` → **404** (상품 1페이지가 링크)
- 링크는 화면의 빵부스러기 **그리고** JSON-LD `BreadcrumbList` 양쪽에 들어간다.
  예: `docs/p/던킨-정통-보름달-도넛/index.html` 의 `"item": ".../c/디저트/"`

**추정 원인** `web/pages.py:22` `KINDS = ("편의점","카페","햄버거","피자","치킨")` 5종만 `/c/` 페이지를 만드는데
(`web/pages.py:325`), 빵부스러기·JSON-LD 는 `_kind(r)` 값을 조건 없이 링크한다(`web/pages.py:168, 203, 212`).
`collect.SECTIONS` 는 14종이라 디저트·분식·베이커리·한식 등이 어긋난다.
`web/seo.py:84` 의 `_derive()` 폴백이 쓰이면 사이트맵에도 404 URL 이 들어간다(현재는 안 쓰임).

**심각도** 중 — 사용자는 클릭해야 만나지만, 검색엔진은 구조화 데이터에서 바로 본다.
