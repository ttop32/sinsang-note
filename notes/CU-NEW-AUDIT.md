# CU 'NEW 배지' 감사 — 신상인가, 그냥 새로 등록된 것인가

측정 2026-10-02. 대상은 **그날 홈에 떠 있던 CU 338건 전수**.
재현(패치 전 기준):

```python
import json, sys; sys.path.insert(0, '.')
import rules as R
from datetime import date
rows = json.load(open('data/products.json'))['products']
R.untrust_bulk_dates(rows); R.undupe_display(rows)
print(len([r for r in R.pick(rows, date.today().isoformat()) if r['brand'] == 'CU']))  # 338
```

발단은 운영자 지적 — "CU는 기존에 있던 과자들이 신제품으로 잡힌다".
지목된 건 에이비씨초콜릿·쿠크다스초코케잌·오리온 초코칩쿠키 셋이었는데,
**셋 중 둘은 진짜 신상이었고 하나만 오탐이었다.** 대신 지목되지 않은 곳에서
오탐이 더 나왔다. 눈대중으로는 안 갈린다는 뜻이라 전수로 쟀다.

## 요약 (네 줄)

1. **CU 의 NEW 는 '신제품'이 아니라 '상품코드(gdIdx)가 새로 생겼음' 이다.** 재입점·
   포장 변경·계절 재등록이면 전부 붙는다. 1986년에 품목제조보고된 오리온 초코칩쿠키
   256g 이 NEW 를 달고 홈에 올라와 있었다.
2. **338건 중 '기존 상품'으로 확인된 건 18건(5.3%)** — 생과일·채소 14 + 포장식품 4.
   진짜 신상 확인 55건, 2026년 신제품이지만 창 밖 1건, **나머지 264건은 불명**
   (확인 못 했다는 뜻이지 오탐이 아니라는 뜻이 아니다). 근거를 전수로 찾은 과자
   55건만 보면 진짜 23 · **오탐 2** · 창밖 1 · 불명 29 다.
3. **고칠 방법은 하나만 찾았다** — 생과일·채소(CU 자체 태그로 딱 떨어진다)를 수집에서
   뺐다. **홈 CU 338 → 324, 진짜 신상 손실 0건.** 포장식품의 재등록은 CU 데이터
   안에 가를 신호가 없다(§3 에 후보 9개 전부 실측). 억지로 안 고치고 선택지와
   비용을 §5 에 숫자로 뒀다.
4. ⚠️ **운영자가 신고한 증상은 이 패치로 안 고쳐졌다.** 신고는 "기존에 있던 **과자**가
   신제품으로 잡힌다"였는데, 이번에 뺀 건 과일·채소고 **과자 오탐은 한 건도 안 줄었다.**
   `오리온)초코칩쿠키256g`·`앰지)밀카버블리90g` 은 지금도 홈에 그대로 있다.

## §1. NEW 배지의 실제 의미

**결론: CU 의 NEW 는 '신제품'이 아니라 '상품코드(gdIdx)가 새로 생겼음' 이다.**

### 1-1. 배지는 가짜가 아니다 — 세븐일레븐과 다르다

세븐일레븐 '신상품' 탭은 다른 엔드포인트로 같은 목록을 부르면 배지가 사라져서
가짜로 판명났었다. CU 는 그 수법으로 깨지지 않는다. 같은 상품을 **키워드 검색 /
기본정렬 / 최신등록순** 어느 경로로 불러도 배지가 같고, 같은 제품군의 옛
상품코드에는 안 붙는다.

```
--- kw=쿠크다스 cond=(기본)            --- kw=쿠크다스 cond=setC(최신등록순)
    gd=5195   NEW=0  크라운)쿠크다스크림      gd=28242  NEW=1  크라운)쿠크다스초코케잌
    gd=13937  NEW=0  크라운)쿠크다스커피      gd=13937  NEW=0  크라운)쿠크다스커피
    gd=28242  NEW=1  크라운)쿠크다스초코케잌   gd=5195   NEW=0  크라운)쿠크다스크림
```

상세 페이지 마크업도 그냥 'New' 한 글자뿐이다. 더 좁은 뜻이 적혀 있지 않다.

```html
<div class="prodDetail-w">
  <img src="//<CDN>/product/8802259035992.jpg" alt="8802259035992.jpg" />
  <span class="tag">
      <img src="/images/icon/tag_new.png" alt="New" />
  </span>
</div>
```

목록 카드의 개발자 주석도 종류를 둘로 못박아 둔다 —
`<!-- [D] .tag > span .new : new / .best : best -->`. 'new' 를 설명하는 문구는
사이트 어디에도 없다. 상세 페이지에 **등록일·출시일 필드는 없다**(가격·상품설명·
태그 셋뿐). CU 가 쓰는 '新'의 정의를 글로 밝힌 데가 없으므로 행동으로 확인했다.

### 1-2. 옛 상품을 새 코드로 다시 올려도 붙는다 (여기가 핵심)

| 상품 | gdIdx | 배지 | 실제 나이 |
|---|---:|:--:|---|
| 오리온)초코칩쿠키256g | 28089 | **NEW** | 바코드 8801117122409 의 식약처 **품목제조보고일 1986-02-15** |
| 오리온)초코칩쿠키 | 5194 | 없음 | 같은 제품군의 다른 용량 |
| 튀김)애플파이 | 28310 | **NEW** | 'CU)애플파이'(서울식품공업) 품목제조보고 **2020-09-25** |
| 데일리)거봉500g(팩) | 28028 | **NEW** | 거봉. 데일리)거봉컵200g(21368)이 배지 없이 이미 있다 |

식약처 바코드 조회(공개 API, 키 불필요):

```
$ curl 'http://openapi.foodsafetykorea.go.kr/api/sample/C005/json/1/20/BAR_CD=8801117122409'
{"C005":{"total_count":"1","row":[{"PRMS_DT":"19860215","PRDLST_NM":"초코칩쿠키",
```

40년 된 과자가 NEW 로 올라온다. 배지가 재는 건 상품의 나이가 아니라 **CU 카탈로그
항목의 나이**다. 재입점·재계약·포장 변경·계절 재등록이면 전부 새 코드가 나가고
전부 NEW 가 붙는다.

### 1-3. 어댑터 docstring 의 전제가 틀렸다

`collectors/cu.py` 는 이미지 Last-Modified 를 `uploaded_at` 으로 쓰면서
"사진을 재업로드하면 옛 상품이 최근 날짜를 갖는다 — **NEW 배지가 그 오염을
막아주는 구조**" 라고 적어놨다. 그 문장이 틀렸다. 배지와 날짜는 서로 독립이 아니라
**같은 것(= CU 입점 시점)을 두 번 재는 것**이다. 둘 다 출시일이 아니다.

출시와 CU 입점 사이 시차도 실제로 크다.

| 상품 | 출시 | 우리 uploaded_at | 시차 |
|---|---|---|---:|
| 오리온)스윙칩까르보불닭 | 2026-06-25 | 2026-08-24 | 60일 |
| 바프)와삭콘50G | 2026-06-10(품목제조보고) | 2026-08-05 | 56일 |

출시 99일·114일 된 상품이 '최근 60일'이라고 적힌 화면에 오른다.

## §2. 전수 판정표 (338건)

판정 기준 — **진짜**: 외부 근거로 2026-08-03(오늘−60일) 이후 출시 확인 /
**오탐**: 외부 근거로 그보다 훨씬 전부터 있던 상품 / **불명**: 근거를 못 찾음.
추측으로 메우지 않았다.

> ⚠️ **조사 범위를 그대로 밝힌다.** 과자 55건은 전수로 외부 근거를 찾았다.
> 나머지 283건은 ① 식약처 품목제조보고 바코드·제품명 조회를 **338건 전건에**
> 돌리고(이름 유사도 0.88 이상만 채택) ② 생농산물은 CU 자체 카탈로그 대조,
> ③ 405)·PB 계열은 보도자료로 확인했다. 그래도 **264건은 불명**으로 남았다.
> 불명 264건은 "오탐이 아니다"가 아니라 "확인하지 못했다"는 뜻이다.

## §3. 구분할 방법을 찾았나 — 하나만 찾았다

### 3-1. 쓸 수 있는 신호: 생과일·채소 태그

CU 가 상품마다 직접 붙인 분류 태그에 `과일`·`채소`가 있다. 농산물은 '신제품'이라는
말 자체가 성립하지 않고, CU 는 철마다 같은 품목을 새 상품코드로 올린다.

```
gd=21368 NEW=0  데일리)거봉컵200g        ← 이미 있다
gd=27978 NEW=1  데일리)거봉1kg(박스)      ← 그런데 NEW
gd=28028 NEW=1  데일리)거봉500g(팩)      ← 이것도 NEW
gd=21646 NEW=0  데일리)샤인머스캣팩500g
gd=27977 NEW=1  데일리)샤인1kg(박스)
```

**부분일치 안전성(이 레포의 단골 사고)** — 상품명이 아니라 태그 문자열을 통째로
맞춘다. CU 666건 실측:

- `과일` 16건 · `채소` 4건 = **20건, 전부 원물.** 다른 태그가 섞인 건 **0건**
  (전부 `['과일','식재료']` 또는 `['채소','식재료']`).
- 이름에 글자가 들어가는 상품은 **안 걸린다**:
  `포코피아)과일젤리` → `['소프트캔디','젤리','과자류']`,
  `CJ)솥반뿌리채소영양밥200` → `['즉석식','가공식사']`.
- 없는 이름으로도 시험했다 — 가짜 태그는 당연히 0건이고, 가짜 상품명
  (`과일맛젤리틱톡` 등)도 태그가 없어 안 걸린다.

**`정육`(4건)은 일부러 넣지 않았다.** `도드람)한돈삼겹살300g` 같은 원물과
`미트)간장삼겹살구이350g` 같은 양념 가공품이 **같은 태그**를 쓴다. 가를 신호가
없는데 넣으면 진짜 신상을 같이 떨어뜨린다. 남는 오탐 2건(도드람 한돈목살·삼겹살)은
알고 두는 것이다. **진짜 신상을 잃는 쪽이 더 위험하다.**

## §4. 고친 것과 건수 변화

`collectors/cu.py` 한 파일만 고쳤다. **판정 규칙을 어댑터와 rules.py 양쪽에 적지
않았다** — 이 레포의 단골 결함이 그거라서, 농산물은 rules 로 넘기기 전에 어댑터가
수집 단계에서 뺀다(NEW 아닌 카드를 안 담는 것과 같은 자리다).

| 바뀐 것 | 내용 |
|---|---|
| `PRODUCE_TAGS` / `PRODUCE` / `PRODUCE_ONLY` 추가 | `frozenset({"과일","채소"})`, 분류값 `"농산물"`, 공존 허용 태그 `{과일,채소,식재료}` |
| `_category()` | **좁은 태그가 과일·채소(+식재료)뿐일 때만** `"농산물"` 반환. 먼저 보고 바로 반환하면 CU 가 가공품에 '과일'을 하나 더 붙이는 날 그 상품이 말없이 사라진다 — 검수 지적으로 조건을 좁혔다 (`['과일','과즙음료']` → 음료 쪽으로 빠지지, 수집에서 사라지지 않는다) |
| `fetch()` | `category == PRODUCE` 인 것을 수집에서 제외(이미지 HEAD 전이라 요청도 그만큼 준다) |
| `RESOLVED_CATEGORIES` | `"식재료"` 제외. 옛 수집분이 식재료로 캐시돼 있어서 캐시를 태우면 **이미 받아둔 농산물에 영영 안 걸린다** |
| 모듈 docstring | "NEW 는 신제품이 아니라 CU 등록" 절 추가 + 틀렸던 "NEW 가 오염을 막아준다" 문장 정정 |

## §5. 못 고친 것 — 포장식품은 현재 신호로 구분 불가

남은 확정 오탐 4건(`오리온)초코칩쿠키256g`·`앰지)밀카버블리90g`·`튀김)애플파이`·
`튀김)콘파이`)과 불명 264건 중 섞여 있을 오탐은 **CU 데이터 안의 어떤 값으로도
진짜 신상과 갈리지 않는다**(§3 표).
`롯데)에이비씨초콜릿72g`(2026-09-11 출시)과 `오리온)초코칩쿠키256g`(1986년 상품)은
CU 가 주는 모든 필드가 같은 모양이다 — 둘 다 NEW, 둘 다 최근 사진, 둘 다 과자 태그,
둘 다 최근 gdIdx.

억지로 고치지 않았다. 선택지와 비용은 아래다. 전부 실제로 `rules.pick` 을 다시
돌려 나온 수다(농산물 제외를 적용한 324건 위에서 잰 것).

**창을 좁히는 건 정밀도를 거의 못 올린다.** 확정 오탐 4건 중 3건

확정 오탐은 **한 건도** 안 줄어든다. 30일로 줄여야 비로소 하나(초코칩쿠키256g)
빠지고, 그 대가가 카드 159장이다. 창은 정밀도가 아니라 **노출량**을 줄인다.
운영자가 '적게 뜨더라도 확실한 것만'을 원한다면 C 가 선택지이지만, 그건 정확도
개선이 아니라 노출 축소라는 걸 알고 골라야 한다.

### 쓸 수 있을 법한 길 (지금은 안 한 것)

1. **식약처 품목제조보고 바코드 대조를 '수집 때'가 아니라 '감사 때' 돌린다.**

## §6. 조사 중 따로 발견한 것 (이번엔 안 고쳤다 — 요청 범위 밖)

**`_fill_desc` 의 태그 셀렉터가 옆 상품 태그를 같이 읽는다.** `tree.css("ul.prodTag li")`
가 문서 전체를 훑는데, 상세 페이지 아래쪽 '카테고리 베스트 상품' 블록에도
`ul.prodTag` 가 있다. 자기 태그는 `ul.prodTag#taglist` 쪽이다.

```
CU 666건 실측: 전체 셀렉터 결과 ≠ 자기 태그인 상품 371건 (55.7%)
예) 데일리)거봉500g(팩)  자기 태그=['과일','식재료']  전체 셀렉터=['과일','식재료','1+1','1+1']
```

지금은 `_category()` 가 좁은 태그부터 훑기 때문에 대개 자기 태그가 먼저 이겨서
겉으로는 티가 안 난다. 하지만 자기 태그가 비는 상품이 생기면 **옆 상품의 분류를
덮어쓴다.** 이번 농산물 걸러내기도 같은 셀렉터를 쓰므로, 고칠 때 `#taglist` 로
좁히면 둘 다 안전해진다. 이번 요청 범위 밖이라 보고만 한다.

## §9. 검수와 그 결과 반영

검수 서브에이전트를 띄워 (1) 오탐 판정 독립 재확인 (2) 진짜 신상이 같이 날아갔는지
(3) 부분일치로 조용히 사라진 상품이 없는지를 맡겼다. **판정 2건이 뒤집혔고 코드
지적 2건을 받아 고쳤다.** 아래는 지적과 조치다.

### 뒤집힌 판정 2건 — 내 방법론 오류

| 상품 | 내 처음 판정 | 바뀐 판정 | 이유 |
|---|:--:|:--:|---|
| `바프)와삭콘50G` | 오탐 | **진짜** | 다나와 와삭콘 전 SKU 최초 등록이 **26.08**(50g×16봉은 26.10). 2026년 신제품 라인이다. 내가 근거로 쓴 식약처 품목제조보고 2026-06-10 은 **출시 2개월 전 사전 보고**이지 구상품 증거가 아니다 |
| `오리온)스윙칩까르보불닭` | 오탐 | **창밖** | 2026-06-25 출시가 맞고 99일째인 것도 맞지만, **2026년 진짜 신제품이다.** '기존 상품'과 같은 칸에 넣으면 숫자를 잘못 읽게 된다 |

**방법론 교훈: 품목제조보고일(PRMS_DT)은 출시일이 아니라 사전 보고일이다.**
오래된 값(1986·2020)은 '그때부터 있었다'는 강한 증거지만, 최근 값(2026-06 같은)을
'그날 출시'로 읽으면 **신제품을 구상품으로 몰게 된다.** 최근 날짜는 "그 이후 어느
날 출시"로만 읽어야 한다. 이 오류로 판정표에서 오탐을 1건 과다 계상했었다.
`해태)버터링에쉬레버터`의 날짜도 같은 이유로 09-07(보고일) → **09-21(출시 보도)**
로 고쳤다(판정은 진짜 그대로).

집계도 다시 냈다: **오탐 20 → 18**(과자 4 → 2), 진짜 54 → 55, 창밖 1 신설.

### (A) 진짜 신상 손실 → **없음** (검수자가 독립 재현)

검수자가 패치 전/후를 같은 `known` 스냅샷으로 라이브 2회 실행해 대조했고
내 수치를 전건 재현했다 — `666→646`, `홈 338→324`, 새로 붙은 것 0, 굿즈 13→13,
다른 브랜드 0. 수집에서 빠진 20건 전수도 확인 — 자몽4입·샤인머스캣컵·양배추1통·
조각수박·하우스감귤·그린키위 포함 **전부 생과일/생채소, 포장식품 0건**.

### (B) 부분일치 사고 → **없음**, 다만 장래의 조용한 소멸 경로를 지적받아 고쳤다

검수자가 `_category()` 를 읽고 태그 완전일치임을 확인했고, 가짜 이름
(`['과일맛젤리틱톡']` 등)이 안 걸리는 것도 실측했다. 다만 **설계 위험**을 짚었다 —
PRODUCE 검사가 좁은 태그 루프보다 앞에 있어서, CU 가 가공품에 '과일' 태그를 하나
더 붙이는 순간 그 상품이 말없이 사라진다는 것이다. 실증: `['과일','과즙음료']`.
'카스/카스테라' 사고와 기전은 달라도 **증상이 같다**(조용한 소멸).

**고쳤다.** 좁은 태그가 `{과일, 채소, 식재료}` 안에만 있을 때 원물로 본다
(`PRODUCE_ONLY`). 고친 뒤 재확인:

```
['과일', '식재료']              -> 농산물     ['과일', '과즙음료']   -> 식재료  (안 사라진다)
['채소', '식재료']              -> 농산물     ['채소', '즉석식']     -> 즉석식
['과일', '식재료', '1+1', '1+1'] -> 농산물     ['과일', '젤리', '과자류'] -> 과자
['정육', '식재료']              -> 식재료     ['식재료']            -> 식재료
['과일맛젤리틱톡'] / ['과일젤리'] / ['뿌리채소'] / ['없는태그'] / []  -> 전부 안 걸림
```

CU 666건 전수 재검증: 걸리는 건 **여전히 정확히 20건**(자기 태그 기준·어댑터가 쓰는
전체 셀렉터 기준 둘 다 동일). 라이브 재실행도 `666→646 / 홈 338→324 / 새로 붙은 것 0`
으로 고치기 전과 같다. **좁히면서 잃은 건 없다.**

### 그 밖에 받은 지적과 조치

| 지적 | 조치 |
|---|---|
| 주석의 "식재료 36건/일" 이 실행로그 46건과 어긋난다 | **고쳤다.** 46건/일 = 남은 식재료 26 + 매일 버리는 농산물 20. 내역까지 주석에 적었다 |
| 농산물 20건은 products.json 에 안 남아 캐시가 영영 안 생긴다 | 알고 두는 영구 비용. 주석과 §4 에 명시했다 |
| 상세 GET 이 실패하면 `_category` 가 안 불려 그 상품이 1depth('식품')로 남아 거르기를 통과한다 | **하루만 샌다.** '식품'은 `RESOLVED_CATEGORIES` 에 없어 다음날 다시 읽고 걸러진다. 기존 `_fill_desc` 의 실패 동작이라 이번엔 건드리지 않았다 |
| 분류 흔들림 | **없음.** 666건 재해석 대조 결과 차이 22건 중 20건이 의도된 농산물, 나머지 2건은 캐시를 타서 실제 변화 0 |
| '정육' 제외 판단 | 타당하다고 확인받음(4건 전부 `['정육','식재료']` 라 가를 신호가 태그에 없다) |
| **이 패치는 운영자가 신고한 증상을 안 고친다** | 맞다. 요약 4번과 §5 에 못박았다. 과자 오탐은 한 건도 안 줄었다 |
| 커밋 상태 | 검수 도중 **다른 세션**이 `70731fda 조사 에이전트 작업분 체크포인트` 로 워킹트리를 쓸어 담으면서 CU 패치가 같이 커밋됐다. 나는 커밋하지 않았다. `data/products.json` 은 아직 CU 666건이라 **다음 collect 실행 전까지 사이트에는 농산물 14장이 그대로 떠 있다** |

검수 결론은 **조건부 승인**이었고, 조건 세 가지(PRODUCE 검사 순서/범위, 주석 46건,
운영자에게 과자 오탐 잔존 고지)를 전부 반영했다.

### 남는 위험

1. **불명 264건을 확인하지 못했다.** 오탐률 5.3% 는 하한이다.
2. **`정육` 2건(도드람 한돈목살·삼겹살)은 알고 남겼다**(§3-1).

   영향을 안 받는다(두 셀렉터 모두 20건으로 실측 동일).
