### ① 삼양식품 — **채택** (라면·스낵) · 1차 판정 뒤집음

| 항목 | 실측 |
|---|---|
| 공식 도메인 | `www.samyangfoods.com` → `121.254.254.171`. 파킹 IP 쌍 아님. `samyangfood.co.kr` 도 **같은 서버**(robots 의 Sitemap 이 그 도메인을 가리킨다) |
| **신제품 신호** | **보도자료에 '제품뉴스' 전용 카테고리가 있다** — `./list.do?searchCateCd=035002`, **총 244건** |
| 수집 URL | `https://www.samyangfoods.com/kor/publicity/press/list.do?searchCateCd=035002&pageIndex=1&pageUnit=30` |
| SSR/XHR | **완전 SSR.** 116KB 원본에 `<td class="subject"><a onclick="fnView('./view.do', 1361)">제목</a></td>` + `<td>2026.08.31</td>` |
| 날짜 | **준다.** `YYYY.MM.DD`, 목록·상세 양쪽 |
| robots | **허용 — 200, 89바이트, `User-agent: * / Allow: /`** (가장 깨끗한 축) |
| 건수·빈도 | 전체 보도자료 481건 / 제품뉴스 244건. 최근 30건이 **2025-11-03 ~ 2026-08-31 = 10개월** → 월 3건 꼴 |

**1차가 왜 탈락시켰나, 왜 뒤집히나.**
`CANDIDATES-DIRECT.md` §1-2 는 "제품·PR 모두 JS 렌더(한글 노드가 내비뿐)"로 적고 **불가에 가까움**을 줬다.
그 판정은 **`/kor/brand/list.do`(제품 카탈로그) 기준으로는 지금도 맞다** — 내가 다시 열어 봤다:

```
GET /kor/brand/list.do?searchCateCd1=46   200  108,526B   (스낵)
  날짜 토큰 0 · '출시' 0 · '신제품' 0 · NEW 0
  본문 한글 텍스트: "라면 스낵 유제품 소스·간편식 냉동 간편식 전체보기 1 2 3 … Next"  ← 내비·페이저뿐
```

**그런데 보도자료 경로는 완전히 다르다.** 1차는 이 경로를 열지 않았다.

```
GET /kor/publicity/press/list.do           200  116,554B
  <title>보도자료 | 홍보관 | 삼양식품</title>
  총 481 건 / 탭: 전체뉴스 · 기업뉴스(035001) · 제품뉴스(035002) · ESG뉴스(035003) · 공지사항
```

**파라미터 (목록 하단 `<form id="searchForm" method="get">` 의 hidden 필드에서 그대로 읽었다):**

| 이름 | 뜻 | 실측 |
|---|---|---|
| `searchCateCd` | 카테고리 | `035002` = 제품뉴스 |
| `pageIndex` | 페이지 | 1부터 |
| `pageUnit` | 페이지당 건수 | 기본 12. **`pageUnit=30` 을 GET 으로 넣으면 실제로 30행이 온다**(확인함) |
| `searchCondition`·`searchKeyword` | 제목/내용 검색 | 미사용 |

상세는 `fnView('./view.do', 1361)` → **`/kor/publicity/press/view.do?seq=1361` 로 GET 이 그대로 된다.**
상세에도 제목 아래 `2026.08.31` 과 본문 전문이 SSR 로 있다.

**일괄 등록 흔적 — 없다.** 제품뉴스 최근 30건의 날짜를 전부 뽑아 중복을 셌다:
```
2026.08.31 08.25 08.04 07.01 06.23 06.22 06.19 06.08 06.05 05.29 05.26 05.11
2026.04.28 04.27 04.21 04.16 03.23 03.03 02.06 02.04 02.03
2025.12.12 12.08 12.05 11.27 11.26 11.19 11.14 11.06 11.03
→ 중복 날짜 0건. 동서식품 `regDt` 같은 묶음이 없다.
```

**⚠️ 함정 3개 (어댑터가 반드시 걸러야 한다).**
1. **'제품뉴스' ≠ '출시'.** 244건 카테고리지만 최근 30건 중 실제 신제품 출시는 **8건 정도**다.
   나머지는 수상(레드닷·iF·미각상), 팝업/행사, 캠페인 조회수, 브랜드 론칭, 캐릭터 플랫폼 오픈이다.
   `CANDIDATES-DIRECT.md` §2-③ 의 역필터("돌파"·"성료"·"수상"·"조회수")가 **여기서도 필요**하다.
2. **해외 전용 신제품이 섞인다.** `삼양식품, 日 신제품 '불닭카레' 2종 출시`(2026.03.23) — 일본 전용이다.
   국내 편의점 화면에 올리면 거짓이 된다. `日`·`美`·`글로벌`·`수출` 토큰 역필터가 필요하다.
3. **없는 `seq` 도 200 에 껍데기를 준다.** `view.do?seq=1399` 가 **200 / 108,500B** 인데 본문·제목·날짜가 전부 없다.
   동서식품과 **같은 함정**이다(2차 §함정). 상태코드로 검증하지 마라 — 제목 노드 유무로 판정해야 한다.

### ② 크라운제과 — **채택** (과자) · 1차 판정 뒤집음 · ⚠️**대역폭 지뢰**

**1차가 왜 탈락시켰나, 왜 뒤집히나.**
`CANDIDATES-DIRECT.md` §1-1 은 `/product/index` 를 보고 "카탈로그 JS 렌더", "홈 날짜 27개는 전부 이미지 파일명"
이라며 **"불가에 가까움"** 을 줬다. **카탈로그가 JS 라는 전제부터 틀렸다.** 다시 열어 보니 SSR 이다:

```
GET /product/index?searchCateCd=1478063302   200  26,106B   (스낵)
  총 12 건
  C콘칲 군옥수수맛 / C콘칲 초당옥수수 / C콘칲 골드 / 참쌀 설병·선과 / 못말리는 신짱 /
  못말리는신짱 가마솥 누룽지맛 / 죠리퐁 / 콘초·콘치 / 콘피쵸 / 카라멜콘 땅콩 / 메이플콘 / 츄러스
  ← 상품명·한 줄 설명이 전부 원본 HTML 안에 있다
```

**그리고 카테고리 탭 맨 앞에 '신제품' 이 따로 있다.** 1차가 이걸 못 봤다 —
탭이 `<a href="javascript:searchCate('1478063307')">` 라서 `href` 만 긁으면 안 보인다. 코드에서 직접 읽어냈다:

```html
<ul class="ul_tab">
  <li><a href="javascript:searchCate('1478063307');" role="button">신제품</a></li>
  <li><a href="javascript:searchCate('all');">전체</a></li>
  <li><a href="javascript:searchCate('1478063272');">비스킷</a></li>
  …
</ul>
```

**`searchCateCd` 를 GET 쿼리로 그대로 넣으면 열린다**(POST 폼인데 GET 도 받는다). 실측:

```
GET /product/index?searchCateCd=1478063307   200  21,283B
  총 3 건
  <li class="item" onclick="view('395')"> … <strong>카라멜콘 크로아상</strong><div>버터 크로아상 풍미 가득</div>
  <li class="item" onclick="view('394')"> … <strong>빅파이 제주레몬허니</strong><div>제주 레몬 100%의 상큼함</div>
  <li class="item" onclick="view('393')"> … <strong>초코 츄러스</strong><div>깊고 진한 가나슈 초코에 츄러스가 DIP!</div>
```

**파라미터:**
- 목록: `GET /sns/news?currentPageNo=N` — **POST 폼인데 GET 으로도 페이지가 넘어간다**(page2 실측: 1,650,344B, 날짜 `2026-05-26 …`)

- 상품 상세: `onclick="view('395')"` → 목록의 `idx` 를 쓰는 같은 구조(미확인, §확인 못 한 것)

**⚠️⚠️ 대역폭 지뢰 — 이게 이 브랜드의 진짜 비용이다.**
`/sns/news` 1페이지가 **10,821,476 바이트(10.8MB)** 다. 행은 10개뿐인데.
원인을 찾았다: **썸네일이 전부 `data:image/jpeg;base64,…` 인라인**이다(페이지당 10개).
행 하나에 약 1MB 가 붙어 있다.

```
bytes 10,821,476 / tr 11개 / data:image 10개
```

- **전수 수집하면 520건 ÷ 10 = 52페이지 × 평균 ~1.6~10MB = 수백 MB** 다. 하지 마라.
- **증분 수집(1페이지만)이라도 매 실행 10.8MB** 다. 다른 브랜드 전체 합보다 크다.
- 상세는 **건당 3.2MB**. 본문이 필요하면 더 든다.
- **권고: 제목+날짜만 쓰고 상세를 열지 마라.** 그래도 1페이지 10.8MB 는 피할 수 없다.
  `/product/index?searchCateCd=1478063307`(신제품, **21KB**)을 주 소스로 쓰고
  보도자료는 날짜 보완용으로 **빈도를 낮춰** 도는 쪽을 권한다.

**⚠️ 이미지 파일명의 숫자를 날짜로 쓰지 마라 — 출시일이 아니다.**
신제품 3건의 이미지 경로에 `YYMMDD` 가 박혀 있다:
```

/upload/system/product/…_260430 빅파이 제주레몬5.6k_입체이미지 copy.jpg
/upload/system/product/…_260416 초코 츄러스1…
```
**`초코 츄러스` 의 파일명은 260416 인데 보도자료 출시일은 2026-06-16 이다 — 두 달 차이다.**
파일명 날짜는 **디자인 시안 날짜**지 출시일이 아니다.
롯데칠성 어댑터가 쓰는 "이미지 경로 = 업로드 시각" 규칙을 **여기 그대로 가져오면 틀린다.**
크라운의 날짜 출처는 **보도자료뿐**이다.

**robots — 판정 불가.**
```
GET /robots.txt  →  404  1,986B  Content-Type: text/html;charset=UTF-8
<!doctype html><html lang="ko"><head> … <title>크라운제과</title> …   ← 사이트 공용 에러 페이지
```
0바이트가 아니라 **HTML 에러 페이지**다. 규칙 부재인지 서버 설정 문제인지 **구분할 수 없다**.
2차가 세운 분류 그대로 "404 + HTML = 판정 불가" 다. 운영자 판단이 필요하다(§판단 필요).

**⚠️ 역필터 필요**: 크라운과 같은 지주(크라운해태) 기사가 섞인다 —

50건 중 대략 10건이 메세나·행사다. 그리고 **해외 전용**도 있다(`가루비감자칩 연어초밥맛` = 일본 미식 콘셉트지만 국내 출시).

**robots — 판정 불가 (새 유형: 200 + SPA 셸).**
```
GET /robots.txt                   200  3,849B  Content-Type: text/plain;charset=UTF-8   md5 5e27b0b11ed9
GET /zzz-does-not-exist-12345     200  3,849B  Content-Type: text/html;charset=UTF-8    md5 5e27b0b11ed9
```
**바이트 단위로 완전히 같은 응답**이다. 즉 robots.txt 는 존재하지 않고 **SPA 가 모든 경로에 공용 셸을 준다.**
`Content-Type` 만 `text/plain` 으로 바꿔 주는데 **내용은 HTML** 이다 — 1차가 "Content-Type 이 거짓말"이라 적은 그것이다.
2차 §5-4 의 "robots 자리에 HTML" 목록에 **"404 가 아니라 200 으로 주는 변종"** 으로 보태야 한다.
판정 방법도 같이 적어 둔다: **존재할 수 없는 경로를 한 번 더 때려 md5 를 비교하면 1회 요청으로 확정된다.**

- 참고로 페이지 `<meta name="Robots" content="INDEX, FOLLOW">` 는 **색인 허용**을 선언한다.
  robots.txt 가 모호할 때 meta 가 반대 방향은 아니라는 보조 근거는 된다.

### ⑩ 대상(청정원) — **보류 유지** · 2차 §8-9 "응답 스키마 미확인" 을 **해소했다**

2차 §1-3 의 판정("밀도가 낮다")은 **유지한다**. 다만 2차가 열지 못한 두 가지를 열었으니 기록한다.

**① `POST /proc/boardListJson.jsp` 의 파라미터를 찾았다.**
페이지 인라인에는 없다. **`/common/js/notice.js` 안에 있다:**
```js
$.ajax({ url: "/proc/boardListJson.jsp", type: "POST",
  data : {"b_id":"notice", "page":cpage, "cate":cate, "sch_type":sch_type, "sch_word":sch_word, "lng":lng},
  dataType: 'json', … });
```
**핵심은 `b_id` 가 `news` 가 아니라 `notice` 라는 것이다.** 뉴스/공지 구분은 **`cate`** 가 한다.
`b_id=news` 로 보내면 `totalCount: 0` 이 조용히 돌아온다(에러가 아니다 — **빈 결과로 위장한다**).
```
b_id=news  cate=news   → totalCount 0   ← 함정
b_id=notice cate=news  → totalCount 271 ✅
b_id=notice cate=''    → totalCount 271
```
⚠️ 응답 `Content-Type` 은 **`text/html; charset=UTF-8` 인데 본문은 JSON** 이다. 앞에 공백이 70여 자 붙어 있다.

**② 응답 스키마 전체 (2차 §8-9 미확인 해소):**
```json
{"number":0,
 "pagination":{"lng":"kr","isPre":"false","totalPage":"…","start":"1","end":"6",
               "pageStart":"1","pageEnd":"…","isNext":"…","currentPage":"1"},
 "boardList":[{
   "idx":"3284", "b_id":"notice", "cate":"news", "catename":"뉴스",
   "title":"대상, 추석 앞두고 400억 원 규모 협력사 대금 조기 지급",
   "reg_ymd":"2026.09.08", "reg_dt":"2026-09-08 13:59:23", "mod_dt":"2026-09-08 13:59:23",
   "contents":"<p>대상이 추석 명절을 앞두고 …</p>",        ← 본문 전문이 목록에 온다
   "thum_1":"1788843561696.jpg", "thum_1_name":"[대상 보도사진] ….jpg",
   "file_1"~"file_4", "view_yn":"Y", "del_yn":"", "rnum":"1", "reg_ip":"172.30.21.65"}],
 "totalCount":271}
```
⚠️ **`reg_ip` 로 사내 사설 IP(`172.30.21.65`)가 그대로 노출된다.** 쓰지 마라. 로그에도 남기지 마라.
이미지는 `/common/popup/download.jsp?realName=1788843561696.jpg` 로 받는다.

**③ 밀도를 30건으로 다시 쟀다 — 2차 판정이 맞다.**
`2026-01-06 ~ 2026-09-08` **9개월 30건 중 출시 3건**:
`청정원 알룰로스 3종`(08.10) · `청정원 피클링소스`(04.22) · `청정원 화이트식초`(04.06).
나머지는 기부·협약·포럼·박람회·할인기획전·수상이다. **3개월에 1건** 꼴이라 2차가 적은 "2개월 1건"보다도 낮다.

**④ `reg_ymd` 는 보도일이 아니라 등록일이다. 묶음이 있다.**
```
2026.09.08 ×4  (13:30:30 · 13:31:57 · 13:41:38 · 13:59:23)  ← 29분 안에 4건 일괄 등록
2026.04.30 ×3  (09:10:52 · 09:24:22 · 09:44:06)
2026.08.10 ×2 · 2026.06.15 ×2 · 2026.04.13 ×2 · 2026.04.03 ×2 · 2026.01.15 ×2
```
그리고 09.08 등록 기사의 본문은 **"…7일 밝혔다"** 라고 쓴다 — **등록이 하루 늦다.**
동서식품 `regDt` 만큼 심하지는 않지만 **`reg_ymd` = 보도일이 아니다**. 쓰려면 ±1일을 감수해야 한다.

**결론: 밀도가 낮아 단독 브랜드로 올릴 값은 없다. 다만 '날짜 보강 소스'로는 깨끗하다**(본문 전문까지 온다).
`CANDIDATES-DIRECT.md` §2-③ 이 제안한 "편의점 항목의 `released_at` 보강" 용도에 가장 잘 맞는 후보 중 하나다.

**🔴 도메인 함정 — `syfood.co.kr` 은 삼육식품이 아니다.**
사명 약자로 추측해서 먼저 쳤던 `www.syfood.co.kr` 은 **다른 회사 것**이다:
```
www.syfood.co.kr  →  111.92.189.12
  HTTPS: SSLError  Hostname mismatch — certificate is not valid for 'www.syfood.co.kr'
  인증서 subject = CN=www.cbe.co.kr,  SAN = www.cbe.co.kr, cbe.co.kr      ← 남의 회사
  평문 HTTP: 200 / 680바이트 euc-kr 껍데기(제목이 깨진 ':: ���� ::')
```
2차 §4 가 남긴 "SAN 이 제3자라고 바로 파킹으로 단정하면 살아 있는 사이트를 버린다(태극당)" 는 경고 때문에
**평문 HTTP 로도 받아 봤는데 680바이트 껍데기**였다 — 태극당과 달리 **진짜 아무것도 없다.**
`syfood.kr`(다른 TLD)도 쳐 봤는데 `*.syfood.kr` 인증서에 **3,208바이트**뿐이라 역시 아니다.
→ **정답은 `sahmyook.co.kr` 이다.** 다음 사람이 또 `syfood` 로 헤매지 않게 적는다.

**탈락 사유 3가지:**
1. **목록 날짜에 연도가 없다** — `07-31`. 그누보드 기본 설정(올해 글은 MM-DD, 작년 이전은 YY-MM-DD)이라
   **연말·연초 경계에서 틀린다.** 상세를 열어야 연도를 안다.
2. **상위 3건이 전부 `07-31`** — 일괄 등록 흔적.
3. **밀도가 낮다.** 보이는 글이 `독일 첫 수출`·`약국 건강 나눔`·`재활용 캠페인`·`보건절제주간 특별 강연` —
   **신제품 기사가 없다.** 두유 단일 품목이라 신상 회전 자체가 느리다.

## 판단이 필요한 것 (운영자 몫)

**① robots 판정 불가 4곳을 어떻게 다룰 것인가.**
이번 라운드에서 `robots.txt` 가 **규칙을 주지 않는** 곳이 네 곳인데, **방식이 서로 다르다.**

| 브랜드 | 응답 | 판정 |
|---|---|---|
| 크라운제과 | **404 + HTML** 1,986B (사이트 공용 에러 페이지) | 2차가 쓰던 분류 그대로 |
| 해태제과식품 | **200 + SPA 셸** 3,849B — **존재하지 않는 경로와 md5 가 같다** | **새 유형** |
| 사조그룹 | **200 + 「서비스 오류 안내」** 3,861B — **존재하지 않는 경로와 md5 가 같다** | **새 유형** |
| 삼육식품 | **302 → `html.gethompy.com/404.html`**(외부 호스팅사) | **새 유형** |
| (참고) 한성기업 | **404 + Apache 기본 404** 208B | 서버가 진짜 없다고 말한다 — 가장 "부재"에 가깝다 |

2차가 세운 "404+0바이트 = 진짜 부재 / 404+HTML = 판정 불가" 두 칸으로는 모자란다. **세 칸이 더 필요하다.**
그리고 **판정법은 똑같다**: `GET /zzz-does-not-exist-12345` 를 한 번 더 때려 **md5 를 비교**하면
"robots 가 없는 것"인지 "robots 자리에 뭔가 있는 것"인지 1회 요청으로 갈린다. 이번에 해태·사조를 그렇게 확정했다.

**② 매일유업 — `*` 그룹이 없는 robots 를 허용으로 볼 것인가.**
`User-agent: Yeti / Allow:/` 24바이트가 전부다. RFC 상으로는 우리에게 적용되는 규칙이 없으니 **금지가 아니다.**
1차가 같은 질문을 던졌고 **아직 답이 없다.** 유제품 축에서 실질적으로 유일하게 쓸 만한 곳이라 결정이 필요하다.

**③ 동원F&B — 1페이지(8건)만 받는 걸 수용할 것인가.**
목록 2페이지 이후가 Ajax 이고 robots 가 `/*Ajax*` 를 금지한다. **증분 수집은 되고 백필은 안 된다.**
수용하면 바로 붙일 수 있다. 수용 안 하면 보류다.

**④ 크라운제과 — 매 실행 10.8MB 를 감당할 것인가.**
보도자료 1페이지가 10.8MB(인라인 base64 썸네일 10개)다. 전체 브랜드 수집량을 혼자 뒤집는다.
- 대안 A: 신제품 카테고리(21KB)만 매일 돌고 보도자료는 **주 1회**
- 대안 B: 보도자료를 버리고 신제품 카테고리만 쓴다 → **날짜를 포기**해야 한다(이미지 파일명은 못 쓴다, 본문 참조)

**⑤ 계열사·비식품을 어디까지 받을 것인가.** 이번에 채택한 8곳 중 **6곳이 계열사 기사를 섞어 보낸다.**

| 브랜드 | 섞이는 것 |
|---|---|
| 풀무원 | 풀무원헬스케어·건강생활(**건기식**) · 푸드앤컬처(**급식·공항 라운지**) · 올가홀푸드 |
| 사조그룹 | 사조푸디스트(**휴게소·급식**) · **사조펫(펫푸드)** · 사조동아원(제분) |
| 동원F&B | **펫푸드**(뉴트리플랜) · **건기식**(GNC·천지인) |
| 크라운·해태 | **크라운해태 메세나**(국악·조각·도서) — 보도자료의 절반 |

## 이번 라운드가 보탠 함정 (다음 사람을 위해)

**1. "카탈로그가 JS 다" ≠ "보도자료도 JS 다".** 1차가 이 추론으로 **삼양식품·크라운제과·해태제과 셋을 접었다.**
   셋 다 보도자료는 SSR(또는 깨끗한 JSON API)이었다. **브랜드당 경로를 최소 두 개는 봐라** — 카탈로그와 보도자료.

**2. 날짜 정규식에 한글 포맷을 넣어라.** 풀무원이 `2026년 9월 23일` 을 쓴다.
   1차가 "날짜 토큰 1개"로 읽고 난이도 **어려움**을 준 유일한 이유가 이것이다.
   → `\d{4}년\s*\d{1,2}월\s*\d{1,2}일` 을 스캔에 추가.

**3. 이미지 파일명의 날짜는 어느 쪽으로도 틀린다.** 이번에 양방향 반례를 둘 다 잡았다.
   - **크라운**: 파일명 `260416` ↔ 보도 `2026-06-16` → **파일명이 2개월 빠르다**(디자인 시안 날짜)
   - **해태**: 파일명 `20261001152853` ↔ 보도 `2026-09-30` → **파일명이 하루 늦다**(업로드 시각)
   → 롯데칠성 어댑터의 "이미지 경로 = 업로드 시각" 규칙을 **다른 브랜드에 복사하지 마라.**

**4. 일괄 등록은 '분 단위 정밀도' 로 위장한다.** 일화 `<li class="time" title="2026-07-29 09:02">` 가
   18건 전부 **6분 안(08:56~09:02)** 이었다. 동서식품 `regDt` 와 같은 사고다.
   → **같은 날짜가 N건 이상이면 시각까지 보고, 시각도 몰려 있으면 버려라.**

**5. 숨겨진 탭은 `href` 를 긁어선 안 보인다.** 크라운의 **신제품 카테고리**가
   `<a href="javascript:searchCate('1478063307')">` 라서 링크 수집에 안 걸렸다. 1차가 놓친 이유다.
   → `javascript:` 핸들러 안의 인자도 긁어야 한다.

**6. 틀린 파라미터가 에러 대신 빈 결과를 준다.** 대상 `b_id=news` 는 **200 + `totalCount:0`** 이다.
   "데이터가 없네" 로 읽고 브랜드를 접기 딱 좋다. **0건이면 파라미터를 의심해라.**

**7. 선언된 sitemap 이 없을 수 있다.** 삼양식품 robots 가 `Sitemap: http://www.samyangfood.co.kr/sitemap.xml`
   을 선언하는데 그 URL 은 **404(Apache 기본 209B)** 다. 사이트맵은 **선언이 아니라 실측으로 확인해라.**

**8. 파킹 IP 쌍 규칙이 3라운드 연속 적중했다.** `13.248.169.48` + `76.223.54.146`.
   이번엔 `www.ilhwa.com`. **`dig` 는 HTTP 요청 0회다. 계속 먼저 쳐라.**
