# 브랜드 후보 조사 — 얇은 분류 메우기 (분식 · 샐러드 · 도시락 · 한식 · 일식 · 중식)

`notes/CANDIDATES-KOREAN.md` · `CANDIDATES-DIRECT2.md` 와 같은 형식이다. **어댑터는 없다.** 조사 결과일 뿐이다.

- 조사일: **2026-10-01**
- 조사 동기: 화면의 외식 세부분류가 얇다. 분식 4곳(화면 1장) · 샐러드 1곳 · 도시락 1곳 · 일식 2곳이고,
  **한식 5곳은 전부 본아이에프 한 회사**다. 한 회사가 한 분류를 통째로 차지하는 건 분류가 있는 게 아니다.
- 조사 방법:
  - **HTTP 전에 `dig` + TLS 핸드셰이크(SAN·발급자·만료)로 먼저 걸렀다**(`CANDIDATES-DIRECT2.md` §4 선례).
    이 단계에서만 자체서명 1건·파킹 다수를 요청 0회 또는 1회로 잡았다.
  - 화면과 원본이 어긋날 수 있는 곳은 **브라우저로 실제 열어서 `offsetParent` 까지 확인**했다.
    노티드·푸르밀·원할머니의 "주석 배지" 사고가 세 번 났던 곳이라 배지는 전부 렌더 기준으로 셌다.
  - robots 는 상태코드와 본문 종류(0바이트 / HTML / 403)를 구분해 적었다.
- **추측으로 채운 칸은 없다. 못 본 것은 "미확인"이라고 적었다.** §9 에 따로 모았다.
- `collectors/base.py` 의 `BRANDS` 61곳은 다시 제안하지 않았다.
  이미 탈락 판정이 난 곳은 근거를 읽고, **뒤집을 새 근거가 있을 때만** 다시 올렸다(§7).

> 이 문서만 내 소유다. `CANDIDATES-MAKER.md`·`CANDIDATES-ALCOHOL.md`·`REVIEW.md` 는 건드리지 않았다.

## 3. 브랜드별 실측

> §0 우선순위 표와 §1 전체 표는 조사가 끝난 뒤 맨 앞에 붙인다. 이 절은 브랜드 하나를 끝낼 때마다 덧붙였다.

### 3-1. 스쿨푸드 — **살아 있는 NEW 배지. 전체 2순위(분식)**

`(주)에스에프이노베이션` 운영. 공정위 마스터 `분식` 에는 없고 `기타 외식`/직영 위주라 안 잡혔던 브랜드다.
**앞선 조사 어느 문서에도 없다.** 처음 본다.

| 항목 | 실측 |
|---|---|
| URL | `http://www.schoolfood.co.kr/menu/menu.html` |
| 상품 수 | **81건** (`ul.menu_list > li`) |
| 신제품 신호 | ✅ **`<span class="new">new</span>` 배지 — 81건 중 14건** |
| BEST 배지 | 13건 (같은 `.type_txt` 안. 신상과 구분됨) |
| SSR/XHR | **완전 SSR.** 1요청(77KB)에 상품명·설명 전부 |
| 날짜 | ⚠️ **간접.** 상품 이미지 파일명이 `_YYYYMMDDHHMMSS.jpg` |
| robots | `http://www.schoolfood.co.kr/robots.txt` → **200, 25바이트, `User-agent: * / Allow: /`** |
| 약관 | 미확인 (푸터에 이용약관 링크를 못 찾았다) |
| 상품별 URL | 🚫 **없다.** 카드의 `<a>` 에 `href` 가 아예 없다(`anyHref: [null,null,null]`) |

**배지가 진짜인지 브라우저로 확인했다.** 원본에서 센 14건과 렌더에서 센 14건이 같고, `offsetParent !== null` 이다.

```js
{"newBadges":14,"bestBadges":13,"products":81,
 "firstNew":[{"txt":"new","vis":true,"name":"짱아치 충무마리"},
```

#### 날짜를 이미지 파일명에서 뽑을 수 있다 (⚠️ 단서 있음)

#### ⚠️ 함정 2개 — 둘 다 이 레포가 이미 겪은 종류다

1. **HTTPS 가 자체서명이다. http 로 받아야 한다.**
   `www.schoolfood.co.kr:443` 인증서가 **nginx 기본 더미**다.
   ```
   s:C=GB, ST=Berkshire, L=Newbury, O=My Company Ltd
   i:C=GB, ST=Berkshire, L=Newbury, O=My Company Ltd   (self-signed)
   sigalg: md5WithRSAEncryption
   NotAfter: Mar 20 00:34:41 2117 GMT
   ```
   `*.gabia.io`(태극당)·`*.blueweb.co.kr`(노브랜드)와 **같은 계열의 함정인데 지문이 또 다르다** —
   호스팅사 와일드카드가 아니라 **OpenSSL 예제 인증서 그대로**(`My Company Ltd` / Newbury / md5 서명 / 100년 만료).
   curl 은 exit 60, 브라우저도 거부한다. **`http://` 로는 전부 200 이고 내용이 진짜다.**
   태극당과 똑같이 "HTTPS 만 가짜"인 경우다. 여기서 버리면 1순위 후보를 버린다.

2. **상품 이미지 90장이 전부 `http://` 절대경로다.**
   ```
   src="http://www.schoolfood.co.kr/upload/product/..."   90건
   src="https://..."                                        5건
   ```
   에그드랍 73장이 빈 네모였던 그 건과 **완전히 같다.** 우리 https 페이지에 그대로 꽂으면 전부 차단된다.
   이미지는 프록시하거나 스킴을 올려서 넣어야 하는데, **이 호스트는 https 가 자체서명이라
   `https://` 로 바꿔치기해도 안 뜬다.** 이미지를 우리 쪽으로 받아 재호스팅하는 수밖에 없다.

#### 신메뉴 탭이 '행사 매대'가 아닌지 확인했다 (세븐일레븐 함정 점검)

즉 **상품별 배지가 아니라 큐레이션된 별도 목록**이다(빽다방·던킨형). 그런데 **버리면 안 되는 이유가 있다.**

| 신메뉴 6건 | `data-idx` |
|---|---|
| 꼬마김밥 | 149 |
| 물쫄면 | 151 |
| 뚝배기불고기 | 154 |
| 찐만두 | 155 |
| 어린이돈까스 | 156 |
| 함박정식 | **157** |

**카탈로그 전체에서 가장 큰 idx 6개가 정확히 신메뉴 6건이다.** (일반 카테고리 최대는 148 이하)
`data-idx` 는 단조 증가하는 상품 일련번호이고, 신메뉴 목록이 그 상위 N 과 일치한다.
"신메뉴 탭 = 실제로 가장 최근 등록된 상품" 이 **수치로 확인된** 셈이다.
`CANDIDATES-PIZZA-FASTFOOD.md` 가 잇샌드에 적어 둔 "연번 신호는 있으나 날짜 없음" 과 같은 급이다.

#### ⚠️ 이미지 경로의 날짜는 출시일이 아니다 — **반례를 잡았다**

이미지 URL 이 `/upload/menu_01/2026_05_19/hero_MQQsj_2026_05_19_18_06_22.png` 꼴이라
"날짜가 공짜로 들어온다"고 쓰고 싶어지는데, **그러면 틀린다.**

```
등심돈까스   idx=45   이미지 2026_05_19     ← idx 45 면 2022년대 상품이다
부대찌개     idx=90   이미지 2026_09_30     ← 어제 날짜
순두부찌개   idx=20   이미지 2026_09_30
매콤철판해물볶음밥 idx=138 이미지 2026_09_30
```

`idx=20` 짜리 오래된 상품의 이미지 날짜가 **어제**다. 사진만 교체해도 갱신된다는 뜻이다.
**업로드 시각이지 출시일이 아니다.** 이 반례는 §3-1 스쿨푸드의 이미지 타임스탬프에도 그대로 경고가 된다 —
두 사이트 모두 같은 종류의 "파일명 날짜"고, 여기서는 그게 틀렸음이 증명됐다.
**스쿨푸드 쪽도 `released_at` 으로 쓰면 안 된다.**

#### 상품별 URL 이 없다 — PC·모바일 둘 다 확인했다

카드가 `<a href="#none" class="view-anchor" data-idx="149">` 다. JS 모달이다.
검색엔진 색인에 `?board=menu_01&sca=2&idx=102` 같은 주소가 남아 있어 상세가 있는 줄 알았는데,
**직접 받아 보니 `idx` 를 무시하고 목록을 그대로 돌려준다.** 모바일(`/m/board/...&idx=102`)도 같다
(`<title>김밥류 | 메뉴 :: 김가네`, 목록 11건). 검색 색인에 남은 건 크롤 흔적일 뿐이다.
**카드 링크는 `SITES` 폴백(신메뉴 페이지)으로 걸어야 한다.**

#### 갱신 주기 — 이게 유일한 약점

최대 idx 157 의 이미지가 `2026_05_20` 이다. **신메뉴가 4개월 반째 그대로**라는 뜻일 수 있다.
다만 이미지 날짜는 위에서 못 믿는다고 했으니 **단정하지 않는다.** 붙인 뒤 idx 가 올라가는지 관찰해야 한다.
(사이트 자체는 어제 날짜로 이미지가 갱신될 만큼 살아 있다.)

**판정: 채택 — 전체 4순위(분식).** 신호가 명시적이고(전용 카테고리), 그 신호가 연번과 교차검증된다.

#### 소식 게시판이 사실상 신제품 피드다

제목에 `[NEW]` 가 붙어 있고 본문이 출시 공지다. **역필터가 거의 필요 없다.**

```
News  육회포케 출시 10일만에 1만개 판매 돌파!
News  [NOTICE] 포케와 한식의 만남! 8/24(월) 육회포케 출시!
News  [NEW] 두 가지 고기를 한번에! 더블프로틴 보울 2종 출시
News  [NEW] 스프 신메뉴 3종 출시
News  [NEW] T.H.E SALAD 신메뉴 4종 출시
News  [NEW] 마이픽포케 출시
```

`[EVENT]`·`[NOTICE]` 가 섞여 있지만 접두사로 갈린다. 샘표·아워홈 보도자료보다 밀도가 높다.
**다만 항목이 "스프 신메뉴 3종"처럼 묶음 단위**라 1글=1상품이 아니다
(`CANDIDATES-BAKERY.md` 가 적은 "시리즈 단위" 문제와 같다). 글 하나를 카드 하나로 쓸지 쪼갤지는 운영자 판단이다.

#### 메뉴 페이지에 상품별 플래그 필드가 있는데 `new` 값은 안 쓴다

gnuboard 확장필드가 `data-wr_9` 로 노출된다. **값을 전수 세어 봤다.**

```
''(빈값) 36 · 'best' 5 · '비건' 3 · 'hot' 2       ← 'new' 는 0건
```

`best`/`hot`/`비건` 은 쓰는데 **`new` 는 한 번도 안 쓴다.** 메뉴 페이지만 보면 신상 구분이 없다는 뜻이고,
그래서 **소식 게시판이 이 브랜드의 진짜 신호**다. `New Line up` 캐러셀 9건은 테마에 손으로 박아 둔
정적 HTML(`/images/ccon2_02_p1.png` 고정 경로)이라 보조로만 써야 한다.

**판정: 채택 1순위(샐러드).** 날짜·상세 URL·`[NEW]` 태그가 전부 있는 이 조사 유일의 조합이다.
샐러디 1곳뿐인 샐러드 분류를 2곳으로 만든다.

## 4. 분류를 어디에 넣을 것인가

### 4-1. 먼저: **디저트 트렌드 축은 채택이 0건이다.** 지금은 분류를 만들 이유가 없다

지시받은 디저트 트렌드 축 결과를 한 줄로 모으면 이렇다.

| 브랜드 | 결과 |
|---|---|
| 달콤왕가탕후루 | **탈락** — NEW 가 14/14 전수(장식) + 신메뉴 게시판 2025-01-07 정지 |
| 카페요아정 | **기존 판정 유지** — 신호 없음(조합 구성기). 사이트 안 바뀜 |
| 흑화당(밀크티) | **탈락** — 공지 최신 2024-05-10 |
| 공차(밀크티) | **불가** — 443 미개방, 1차와 동일 |
| 쥬씨(생과일주스) | **보류** — 날짜는 있으나 최신 2026-04-13, 월 1건 미만 |
| 크로플·베이글·소금빵·약과·두바이초콜릿·마라탕 | **미확인** (§5) |

**"요거트 탕후루 업체 있어?" 의 답은 "업체는 있는데 붙일 게 없다" 다.**
탕후루는 신호가 둘 다 가짜고, 요아정은 1차가 이미 "신호 없음"으로 끝낸 곳이다.
**분류 신설·부활은 채택 브랜드가 생긴 뒤에 하는 게 맞다.** 지금 만들면 빈 분류가 하나 더 생긴다.

### 4-2. 그래도 되살린다면 — **`RETIRED` 스텁은 손댈 필요가 없다. 이미 조건부다**

지시에 "되살리면 RETIRED 스텁을 빼야 한다"고 적혀 있었는데, **코드를 읽어 보니 그렇지 않다.**
`web/pages.py` 의 생성 루프가 이렇게 돼 있다.

```python
for kind in KINDS:                      # 실제 상품이 있는 유형만 목록 페이지를 만든다
    rows = by_kind.get(kind)
    if not rows: continue
    …kind_page(…)

for kind, goes in RETIRED.items():      # 비워진 유형만 안내 스텁을 만든다
    if kind not in by_kind:
        …retired_page(…)
```

`by_kind` 는 **실제 수집된 행**에서 채워진다(`for k in _kinds_of(r): by_kind.setdefault(k, …)`).
그러니 `디저트` 에 상품이 하나라도 들어오면

- `"디저트" in by_kind` 가 **참** → 안내 스텁은 **안 만들어진다**
- `KINDS` 안에 있으면 → 진짜 목록 페이지가 **만들어진다**

**"같은 주소에 안내 페이지와 실제 목록이 둘 다" 생기는 일은 구조적으로 안 일어난다.**
`RETIRED` 항목은 남겨 두는 게 오히려 안전하다 — 나중에 디저트가 다시 비면 스텁이 자동으로 돌아온다.

단, `KINDS` 는 `collect.SECTIONS` → `collect.SUBS` 에서 나오므로 **`SUBS` 에 `"디저트"` 를 넣어야** 목록 페이지가 생긴다.
(`web/pages.py` 의 `_kinds()` 주석이 "유형 목록은 collect.SECTIONS 가 정본이다"라고 못 박아 뒀다.)

### 4-3. 그래서 어디에 넣나 — 세 갈래 제안

1단은 5개로 꽉 찼으므로(375px 실측 291px) **전부 2단(`SUBS`) 안에서 푼다.**

| 상황 | 제안 | 이유 |
|---|---|---|
| **지금 (디저트 채택 0건)** | **아무것도 안 만든다** | 빈 분류를 늘리지 않는다. `/c/디저트/` 스텁 그대로 둔다 |
| **탕후루류가 1곳이라도 생기면** | **`빙수` 에 넣는다** | 탕후루·탕빙수·사고펄은 "차갑고 과일인 간식"이고 설빙이 이미 `빙수` 다. 새 분류보다 싸다 |
| **요거트아이스크림이 생기면** | **`아이스크림` 에 넣는다** | 배스킨라빈스가 이미 `아이스크림` 이고 요아정의 본체가 요거트 아이스크림이다 |
| **밀크티·버블티가 2곳 이상 생기면** | **`음료` 가 아니라 새 2단 `밀크티`** | `음료` 는 지금 제조사 RTD(롯데칠성) 축이다. 매장 음료를 섞으면 "어디서 사나"가 흐려진다 |
| **디저트 부활** | **권하지 않는다** | 던킨→`도넛`, 배스킨라빈스→`아이스크림` 으로 쪼갠 판단이 옳았다. 되돌리면 그 둘이 다시 뭉개진다 |

**이번 조사에서 실제로 필요한 2단 변경은 디저트가 아니라 이쪽이다.**

- `분식` — 스쿨푸드·얌샘김밥·김가네 3곳 추가 → **4곳 → 7곳.** 분류는 이미 있다. **변경 불필요**
- `샐러드` — 슬로우캘리(+포케올데이) 추가 → **1곳 → 2~3곳.** 분류는 이미 있다. **변경 불필요**
- `도시락` — 토마토도시락 추가 → **1곳 → 2곳.** 분류는 이미 있다. **변경 불필요**
- ⚠️ **`포케` 를 `샐러드` 에 넣을지만 정하면 된다.** 슬로우캘리·포케올데이는 둘 다 포케가 주력이다.
  별도 분류를 만들 만큼 브랜드가 없으니 **`샐러드` 로 묶는 쪽**을 제안한다.

**즉 채택안을 전부 반영해도 `SUBS` 는 한 글자도 안 바뀐다.** 1단 5개 문제도 건드릴 필요가 없다.

## 6. 어댑터를 쓸 사람에게

1. **스쿨푸드는 `http://` 로 받아라.** https 가 자체서명(`O=My Company Ltd`)이다. `verify=False` 로 풀 일이 아니다
   (`CANDIDATES-DIRECT2.md` §3-1 의 판단을 따른다). 그리고 **이미지 90장이 `http://`** 라 우리 페이지에 바로 못 건다.
   에그드랍 73장 빈 네모 사고와 같은 건이고, **여기선 `https://` 로 바꿔치기해도 자체서명이라 안 뜬다.**
   받아서 재호스팅하는 방법밖에 없다.
2. **이미지 파일명/경로의 날짜를 `released_at` 으로 쓰지 마라.** 김가네에서 **반례를 잡았다** —
   `idx=20` 짜리 오래된 상품의 이미지 날짜가 어제다(§3-2). 스쿨푸드도 같은 종류다.
3. **gnuboard 목록의 `MM-DD` 에는 연도가 없다.** 달콤왕가탕후루에서 "최신 07-11"로 읽히는 게 실제로는
   **2024-07-11** 이고 진짜 최신은 **2025-01-07** 이었다(§3-6). **갱신 주기를 목록으로 판단하지 마라. 상세를 한 건 열어라.**
4. **얌샘김밥은 REST API 를 써라.** 화면 파싱이 필요 없다.
   `GET /wp-json/wp/v2/yumsem-menu?per_page=100&orderby=date&order=desc` 1요청에 100건,
   `date`·`link`·`menu_categories`·`featured_media` 가 다 들어 있다. `X-WP-Total` 로 전체 건수(154)도 온다.
   **`modified` 가 아니라 `date` 를 써라** — `modified` 는 사진만 바꿔도 갱신된다.
5. **김가네·토마토도시락은 CMS 가 같다.** 둘 다 `/board/index.php?board=menu_01&sca=…` 다.
   신메뉴 `sca` 값만 다르다(김가네 `newmenu`, 토마토도시락 `new`). **어댑터 하나로 묶을 수 있다.**
6. **포케올데이는 `/poke` 를 빼라.** 52건이 상품이 아니라 조합 구성기 부품(베이스·토핑·소스)이고
   NEW 배지의 절반이 소스에 붙어 있다. `/protein_poke`·`/rice_bowl`·`/side`·`/drink` 만 써라.
7. **슬로우캘리는 메뉴가 아니라 소식을 읽어라.** 메뉴 페이지의 `data-wr_9` 에 `best`/`hot`/`비건` 은 있어도
   **`new` 는 0건**이다(§3-4). 신호는 `bo_table=main_news` 의 `[NEW]` 제목 접두사와 상세의 작성일에 있다.
   단 **"스프 신메뉴 3종"처럼 묶음 단위**라 1글=1상품이 아니다.
8. **상품별 URL 이 있는 건 얌샘김밥과 슬로우캘리(소식) 둘뿐이다.**
   스쿨푸드·김가네·토마토도시락·포케올데이는 전부 `href` 가 없거나 `#` 다. `SITES` 폴백을 걸어라.
9. **한솥은 약관 판단이 끝나기 전에 붙이지 마라.** 1차 경고 그대로다. 신호(월별 신메뉴 카테고리)는
   이 조사 전체에서 제일 좋은데 막는 게 기술이 아니다.
