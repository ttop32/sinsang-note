### 3. `collect.py is_fresh()` — 신제품 판정 (서비스의 핵심)

| | 건수 | 본 샘플 |
|---|---|---|
| 거짓 양성(신상 아닌데 신상으로) | **구조적으로 다수** — 아래 | 홈 300 전건 + 브랜드별 비율 전수 |
| 거짓 음성(신상인데 안 뜸) | **구조적으로 다수** — 아래 | 전수 집계 |

**근거 분포(홈 300건 전건).** `released_at` 5건 · `uploaded_at` 40건 · **배지만 255건**.
즉 화면의 **85%가 "브랜드가 NEW 라고 했고 날짜는 없다"** 한 가지 근거로 올라간다.

**거짓 양성 — 날짜 없는 배지는 영원히 안 늙는다.**
`is_new is True` + 날짜 없음 → 무조건 `return True`. 만료 장치가 없다.
그 결과:

| 브랜드 | is_fresh 통과 / 전체 |
|---|---|
| CU | **614 / 666 (92%)** — 666건 전부 `is_new=True`, 날짜 0건 |
| 스시로 | **46 / 46 (100%)** |
| 팔도 | 46 / 102 (45%) — 46건 전부 배지, 날짜 0건 |
| 파리바게뜨 | 312 / 530 (59%) |

CU·스시로는 **카탈로그 전체가 영구히 신제품**이다. 파리바게뜨는 `uploaded_at` 이 근거인데

### 7. `web/pages.py _sweep()` — 더 이상 안 만드는 페이지 삭제

| | 결과 |
|---|---|
| 현재 상태에서 과잉 삭제 | **0장** |
| 현재 상태에서 미삭제(고아) | **0장** |

`docs/` 를 스크래치로 복사해 `pages.build()` 를 통째로 다시 돌려 before/after 를 비교했다.
생성 경로 650개(중복 0), 삭제 0, 추가 0 — **지금 `docs/` 는 데이터와 정확히 일치하고
`_sweep` 은 멱등이다.** 접두 `p/` 비교 사고는 재발하지 않았다.

다만 **실패 모드 두 개를 실제로 터뜨려 봤다**(스크래치 사본에서):
1. **삭제량 하한 가드가 없다.** `_sweep(out, [])` 를 부르면 `p/b/c` 를 전부 지우기 시작한다.
   수집 쪽에는 `FLOOR = 0.7` 급감 가드가 있는데 **지우는 쪽에는 대응물이 없다.**
   `pick()` 이 어떤 이유로든 빈 리스트를 돌려주는 순간 사이트가 통째로 사라진다 —
   과거 337장 사고와 같은 모양이고, 그때 넣은 처방(경로 비교 교정)은 **방향만 고쳤지
   규모는 안 막는다.**
2. **군더더기 파일 하나가 빌드를 죽인다.** 상세 디렉터리에 `index.html` 말고 다른 파일이
   하나라도 있으면 `child.rmdir()` 가 `OSError: [Errno 66] Directory not empty` 로 터진다.
   예외를 안 잡아서 `pages.build()` 가 거기서 죽는데, **그 시점엔 이미 앞쪽 디렉터리를
   지운 뒤다**(내 실험에서 115장 삭제 후 중단). 부분 삭제 + 크래시가 겹친다.

재현:
```

./.venv/bin/python -c "
import json,collect,pathlib;from datetime import date;from web import pages
ps=json.load(open('data/products.json'))['products'];t=date.today().isoformat()
o=pathlib.Path('/tmp/docs_t')
b={str(p.relative_to(o)) for p in o.rglob('index.html')}
pages.build(collect.pick(ps,t), ps, o, goods=collect.pick(ps,t,goods=True))
a={str(p.relative_to(o)) for p in o.rglob('index.html')}
print(sorted(b-a), sorted(a-b))"
```

## §4 구조적 한계 — 고친다고 없어지지 않는 것

1. **이름으로 술·굿즈를 가르는 건 끝이 없다.** 단어를 넣으면 한국어에 단어 경계가 없어
   식품을 물고(스텔라→카스텔라 19건), 안 넣으면 샌다. `막걸리` 는 지금 데이터에서
   **오탐 2 : 정탐 2** 라 「오탐 0만 넣는다」 규칙으로는 결론이 안 난다.
   브랜드가 분류(`주류`/`생활용품`)를 주는 곳(CU·교촌 일부)만 안정적으로 맞고,
   안 주는 곳(이마트24·세븐일레븐)은 영구적으로 샌다. 이건 단어목록의 버그가 아니라
   **입력에 분류가 없다는 사실**이다.
2. **같은 상품 부류가 브랜드마다 반대로 분류된다.** 숙취해소제·활기력샷을 CU 는 `생활용품`,
   이마트24 는 식품으로 준다. 우리 규칙은 브랜드 분류를 우선하므로 **일관성이 원천적으로 없다.**
   "먹는 것"의 경계(건강기능식품·의약외품·펫푸드)를 우리가 정의하지 않는 한 남는다.
3. **날짜 없는 NEW 배지는 늙지 않는다.** CU 666건·스시로 46건처럼 카탈로그 전체에 배지를
   다는 브랜드가 있고, 그런 브랜드에서는 "신제품"과 "메뉴판"이 구분 불가능하다.
   `STALE` 같은 만료 규칙을 켜도 **언제부터 배지가 붙었는지를 모르므로** 기준점이 없다.
   (우리가 처음 본 날 = 합류일이라 쓸 수 없다.)
4. **합류 첫날 기준선은 되살릴 방법이 없다.** 날짜도 배지도 없는 브랜드는 합류 시점
   메뉴판 전체가 `baseline` 이 되고, 그 안에 섞여 있던 진짜 신상은 영구히 묻힌다
   (이마트24 981건 전부가 이 상태). 내일부터의 diff 로만 복구된다.
5. **세트/단품 구분은 이름으로 안 된다.** `drop_sets` 가 버린 24건 **전부 본품이 없었다** —
   "본품 있는 변형은 merge 가, 없는 조합은 drop 이" 라는 분담 자체가 데이터에서 성립하지 않는다.
   선물세트(상품)와 할인세트(구성)는 이름이 구분해주지 않는다.
6. **GS25 는 보도자료가 유일한 입구다.** 본사가 보도자료를 낸 상품만 들어오고(300일 74건 →
   11건), 제목이 상품을 안 쓰면 못 집는다. 수집량이 CU·세븐일레븐과 두 자릿수 차이나는 건
   파서 문제가 아니다.
7. **할리스 배지는 "브랜드가 그려준 것"까지만 정확하다.** 픽셀 판정 자체는 오차 0이지만,
   할리스가 배지를 안 붙인 신제품은 원리적으로 보이지 않는다.
8. **`_sweep` 은 "이번에 만든 것"을 정본으로 삼는다.** 생성 쪽이 조용히 비면 삭제 쪽이
   조용히 전부 지운다. 비교 대상이 바깥 기준(사이트맵·전일 스냅샷)이 아니라 같은 실행의
   출력이라, **생성과 삭제가 같은 버그를 공유한다.**
