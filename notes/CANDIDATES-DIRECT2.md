# 브랜드 후보 조사 2차 — 직영 대형 F&B · 식품 제조사 (1차가 못 간 영역)

`docs/CANDIDATES-DIRECT.md` 의 후속이다. **어댑터는 없다.** 조사 결과일 뿐이다.

- 조사일: **2026-10-01**
- 조사 방법: 브랜드당 HTTP 5회 이내, 요청 간 2.2초, `collectors/base.py` 의 `client()` / UA (`sinsang-note/1.0`).
  JS 렌더 여부가 걸리는 곳만 브라우저로 실제 열어서 화면과 원본 HTML을 **대조**했다.
- **HTTP 전에 `dig` + TLS 핸드셰이크(SAN·발급자·만료·체인깊이)로 먼저 걸렀다.** 둘 다 HTTP 요청이 아니다.
  이 단계에서만 파킹 1건·호스팅사 기본 인증서 2건을 요청 0회로 잡아냈다(§4).
- robots 는 **원문을 눈으로 읽고** 판정했다. `can_fetch()` 는 대조용으로만 썼고,
  이번에 1차가 적어 둔 **쿼리 와일드카드 구멍의 실사례**를 잡았다(§5).
- 추측으로 채운 칸은 없다. 못 본 것은 "확인 못 함"이라고 적었다.

조사 대상은 `CANDIDATES-DIRECT.md` §9 가 "착수 못 했다"고 남긴 구멍이다 —
**음료(RTD)·유제품·조미료·유통 PB·호텔/백화점 식품관**. `PRODUCT-PLAN.md` §5-5 ② 가

## 2. 채택 5곳 — 왜 이것들인가

판정 기준은 운영자 지시대로 **"신제품 전용 페이지/섹션이 있는가"** 를 1차 관문으로 뒀다.
그 관문을 통과한 곳이 둘(롯데칠성·hy프레딧)뿐이라, **"보도자료에 출시 기사가 실제로 자주 올라오는가"**
를 2차 관문으로 두고 셋(샘표·아워홈·동서식품)을 더 넣었다. 1차는 **실측으로 통과**했고
2차는 **최근 10여 건을 직접 읽어 출시 기사 비율을 센 결과**다.

### 2-1. 신제품 전용 페이지가 실재하는 2곳

| | 롯데칠성음료 | hy 프레딧 |
|---|---|---|
| URL | `/kor/product/newprdt/list.do` | `/product/main-tab-menu?keyword=main&ctgId=C10000001001` |
| `<title>` | `신제품 \| 롯데칠성음료` | `신제품 \| hy프레딧(hyFredit)` |
| 건수 | **18** | **159** (화면 "총159개") |
| 원본 HTML | 72,925B — 상품명 **포함** | 1,654,516B — 상품명·가격·"총159개" **포함** |
| 상품명 소스 | `<p class="tit">펩시 엑스트라 피즈</p>` | 카드 텍스트 |
| 설명 | `<p class="txt">오래 즐기고 싶은 너만의 짜릿함</p>` | 있음 |
| 날짜 | 이미지 경로에만 — `/image/2026/9/202609220615531610.png` → **2026-09-22 06:15:53** | 확인 못 함 |
| robots | `*: Allow: /` | `*` + 로그인·장바구니·검색결과 5개만 금지 |

**롯데칠성 날짜를 어떻게 쓸지가 유일한 판단거리다.** 이미지 파일명의 타임스탬프는
`BRAND-CANDIDATES.md` §6-5 / `CANDIDATES-DIRECT.md` §6-2 가 경고한 바로 그 함정이다.
다만 여기는 **상품 카드마다 자기 이미지가 하나씩** 붙어 있어 구조적으로 1:1 이다.
그래도 그건 **이미지 업로드 시각이지 출시일이 아니다.** `Item` 에 마침 그 구분이 있다 —
`uploaded_at` 에 넣고 `released_at` 은 비워라. 반대로 넣으면 틀린 날짜를 공개하게 된다.

**hy프레딧은 쇼핑몰이라 혼입이 심하다.** 159건 중 첫 화면에만
`실리만 사각 만능찜기`·`실리만 양손 주방 가위`·`실리만 하모니 조리도구 거치대`·`바이오리브 치약` 이 섞였다.
`base.is_nonfood()` 의 `NONFOOD_WORDS` 에 **`찜기`·`조리도구`·`플레이팅팬`·`주방 가위` 가 없다.**
붙이기 전에 단어를 보강하고, 보강 후 **기존 전체 데이터에 대고 식품 오탐 0인지 먼저 세라**
(그게 `base.py` 주석이 요구하는 절차다). 외부 브랜드(`청년떡집`·`끼리`·`비비드키친`)도 섞이는데,
이건 hy 제품이 아니라서 브랜드 축이 어긋난다. 걸러낼지 그대로 둘지는 운영자 판단이다.

> 이 문서 초판에 `nttSj` 로 잘못 적혀 있었다 — 검수에서 잡혀 2026-10-01 정정했다.

## 3. 근거 (실측 조각)

### 3-1. TLS 체인이 깨진 곳 3곳 — **`verify=False` 로 풀 일이 아니다**

`CRAWLING-POLICY.md` §6-1 의 표에 **칸이 하나 더 필요하다.**
`CANDIDATES-DIRECT.md` §3-1 이 농심에서 "인증서는 정상인데 암호군이 구형" 칸을 추가했는데,
이번엔 **"인증서는 정상인데 서버가 체인을 제대로 안 보낸다"** 가 3곳 나왔다.

증상은 셋 다 똑같다. 우리 클라이언트가 이렇게 죽는다:

```
ConnectError: [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed:
              unable to get local issuer certificate
```

`openssl s_client -showcerts` 로 **서버가 실제로 몇 장을 보내는지** 세 보면 원인이 갈린다:

| 호스트 | 서버가 보낸 인증서 | 리프 인증서 소유자 | 진단 |
|---|---:|---|---|
| `www.seoulmilk.co.kr` | **1장** | `O=Seoul Dairy Cooperative` | **중간 인증서 누락** |
| `www.shilla.net` | **1장** | `O=HOTEL SHILLA CO.,LTD.` | **중간 인증서 누락** |
| `company.lottechilsung.co.kr` | 3장 | `CN=*.lottechilsung.co.kr` | ⚠️**엉뚱한 중간 인증서** — 리프 발급자는 `GlobalSign GCC R3 DV TLS CA 2020` 인데 서버는 `GlobalSign Domain Validation CA - SHA256 - G2` 를 보낸다 |
| `www.daesang.com` (대조군) | 3장 | `O=DAESANG CORPORATION` | `Verify return code: 0 (ok)` |

**중요한 건 세 가지다.**

1. **내 환경 문제가 아니다.** 같은 프로세스·같은 `certifi` 번들로 대조군 대상(`www.daesang.com`)은
   **200** 이 떨어진다. 실패하는 3곳만 실패한다.
2. **인증서 자체는 멀쩡하고 소유자도 진짜다.** 리프의 `O=` 가 각각 서울우유협동조합·호텔신라다.
   이건 "깨진 인증서"(탐앤탐스·커피스미스 사례)와 **다르다.**
3. **브라우저로는 멀쩡히 열린다.** 브라우저는 AIA(Authority Information Access) 로
   빠진 중간 인증서를 **자기가 받아서 메운다.** `httpx`/OpenSSL 은 그걸 안 한다.
   **그래서 "브라우저에서 되는데요"가 반증이 되지 못한다.**

**4. ⚠️ `http://` 우회는 세 곳 다 안 된다 — 실측했다.**
`CRAWLING-POLICY.md` §6-1 은 "인증서 문제인데 평문 HTTP 가 열려 있으면 `http://` 로 수집" 을 허용한다
(노티드가 그 경로를 썼다). **여기선 그 탈출구가 없다.** 셋 다 http 를 https 로 강제로 넘긴다:

```
http://company.lottechilsung.co.kr/kor/product/newprdt/list.do
    → 302  https://company.lottechilsung.co.kr:443/kor/product/newprdt/list.do
http://www.seoulmilk.co.kr/robots.txt   → 302  https://www.seoulmilk.co.kr/robots.txt
http://www.shillahotels.com/robots.txt  → 301  https://www.shillahotels.com/robots.txt
```

**즉 중간 인증서를 보충하는 것 말고는 길이 없다.**

> **처리 방침 제안**: 올바른 중간 인증서를 받아 클라이언트 `SSLContext` 에
> `load_verify_locations()` 로 **보태는** 방식이면 **검증을 끄지 않고** 풀린다.
> `set_ciphers("DEFAULT@SECLEVEL=1")`(농심 사례)과 같은 계열의 해법이다 —
> 체인·호스트명 검증은 그대로 돈다. `verify=False` 와 혼동하면 안 된다.
> 롯데칠성이 채택 1순위인데 **`http://` 우회가 막혀 있으므로 이 건은 반드시 먼저 풀려야 한다.**

### 3-2. 코카콜라음료 — 신제품 페이지는 있는데 글자가 없다

원본 HTML(euc-kr, 17,497B)에 **날짜가 커스텀 속성으로** 박혀 있다. 보기 드문 형태다:

```html
<li><img id="cate6" src="/images/product/monsterzero.gif" alt=""
         date="2026-07-06"
         link1="/product/subIndex.jsp?select_code=401"></li>
<li><img id="cate4" src="/images/product/spritezerotea.gif" alt=""
         date="2026-06-02" ...></li>
```

`alt` 가 **비어 있다.** 상품명이 어디에도 텍스트로 없고 본문은 큰 홍보 이미지 한 장이다.
브라우저로 직접 열어 확인했다 — 화면에 보이는 `NEW / 보라색의 새로운 기준 / 제로 슈거 / ULTRA VIOLET`
이 **전부 이미지 안의 픽셀**이다. `CRAWLING-POLICY.md` §6-4 "메뉴가 이미지뿐 → 불가(OCR 은 범위 밖)" 다.

⚠️ 같은 페이지 하단에 `<p class="date">작성일 : <span>2015-04-20</span></p>` 가 있다.
정규식으로 날짜를 주우면 **2015년을 집는다.** §6-2 경고 그대로다.

> **그래도 적어 두는 이유**: 날짜를 `<img date="...">` 속성으로 주는 사이트는 처음 봤다.
> 상품명만 어디선가 얻을 수 있으면 날짜 소스로는 쓸 만하다. 5건·최신 2026-07-06 이라 회전은 느리다.

### 3-3. 푸르밀 — 화면과 원본이 어긋난다

브라우저 화면에는 빨간 `NEW` 배지가 2개 붙어 있다
(`푸르밀 요거스푼 혼합(플레인/딸기)`, `검은콩이 들어있는 아이스크림`).
그런데 **원본 HTML의 NEW 는 전부 주석 처리돼 있다**:

```html
<div class="ns-icon clearfix">
  <!--<span class="new bg-brand">NEW</span>-->
  <div class='prod_icon text-danger icon_default best'>BEST</div>
</div>
```

`BEST` 는 살아 있고 `NEW` 만 주석이다. 실제 배지는 런타임에 주입된다:

```js
// 렌더된 DOM 기준
{"count":2, "totalCards":24,
 "samples":[{"tag":"DIV","cls":"prod_thumbnail_badge","card":"푸르밀 요거스푼 혼합(플레인/딸기)"}, ...]}
```

`CANDIDATES-BAKERY2.md` 가 노티드에서 적어 둔 **"NEW 배지 41개가 전부 주석"** 과 **같은 아임웹 패턴**이다.
배지 데이터를 주는 XHR 은 못 찾았다(`/products_all` 재요청 823KB 안에 badge 키 없음).

**상품명·상품코드는 SSR 로 깨끗하게 있다:**

```html
<h2 class="shop-title">푸르밀 스노우 크랜베리</h2>
<div class="shop-item" data-product-properties='{"idx":196,"code":"s202502180fb2e968917aa","name":"푸르밀 커피", ...}'>
```

⚠️ `code` 가 `s` + `20250218` + 해시 꼴이라 **등록일이 들어 있는 것처럼 보인다.**
의미를 확인하지 못했으므로 **추측으로 쓰지 마라.**

⚠️ **페이지네이션이 서버에서 안 먹는다.** `?&page=2&sort=recent` 를 줘도
1페이지와 **같은 24개 idx** 가 돌아온다(823,025B vs 822,496B). 전체 목록을 HTTP 로는 못 받는다.

### 3-4. 신라호텔 — 화면엔 있고 원본엔 없고 XHR 도 안 잡힌다

화면(`get_page_text`)에서는 이게 다 보인다:

```
상품안내  [프리미엄 케이크] [스페셜 케이크] [카스테라&파운드] [디저트] [선물 세트]
  녹차 초콜릿   80,000원   명품 녹차 산지에서 공수한 녹차 가루로 만든 케이크로 …
  밀푀유        70,000원   겹겹이 쌓은 패스트리에 바닐라 마스카르포네 치즈 크림을 …

  Amber Harvest Fig Shortcake  무화과와 흑당 시트가 어우러진 깊은 가을의 맛  2026.09.01 ~ 2026.10.18
  Autumn, Refined              깊고 진한 밤의 풍미를 담은 마롱 벨루어        2026.08.18 ~ 2026.10.31
```

**이벤트의 기간 표기가 사실상 시즌 신메뉴 신호다.** 그런데 같은 URL 을 `fetch()` 로 받으면(212,198B):

```
hasCake(녹차 초콜릿): false    hasPrice(80,000): false
hasEvent(Amber):      false    eventRanges:      []
'스페셜 케이크' 문자열: true   (= 안내문구에만 등장)
```

**네트워크 탭에도 데이터 XHR 이 안 잡혔다** — 잡힌 건 `/hbcimages/...` 이미지뿐이다.
세션·헤더 조건부 렌더일 수도 있고 버퍼에서 밀렸을 수도 있다. **어느 쪽인지 확인하지 못했다.**
그래서 채택이 아니라 **보류**다.

> 참고: 이미지 경로가 `/hbcimages/260827/20260827191701_....jpg` 꼴로 **업로드 시각을 담는다**.
> 롯데칠성과 같은 성격의 신호다(출시일 아님).

## 5. robots 관련 — 1차 기록에 보탤 것

### 5-1. 쿼리 와일드카드 구멍의 **실제 피해 사례**를 찾았다

`CRAWLING-POLICY.md` §6-2 가 "`Disallow: /?mode*` 를 `can_fetch()` 가 놓친다"고 적어 뒀다.
**조선호텔 e-shop 에서 그게 실제로 수집 가부를 뒤집는다.**

`josuntns.josunhotel.com/robots.txt` (3,921B, Disallow 112줄):

```
User-agent: *
Disallow: /admin
Disallow: /api
Disallow: /*?cate_no=          ← 카테고리 목록 전면 금지
Disallow: /*&cate_no=
Disallow: /product/detail.html?product_no=1209
Disallow: /product/detail.html?product_no=1210
... (product_no 개별 금지가 100줄 넘게)
```

`can_fetch()` 결과:

```
can_fetch('/product/list.html?cate_no=45')            = True   ← 원문은 금지. 구멍
can_fetch('/product/detail.html?product_no=1209')     = False  ← 정상
can_fetch('/api/x')                                   = False  ← 정상
```

**중요한 정정**: 구멍은 **`*` 가 `?` 앞에 올 때만** 터진다.
`/product/detail.html?product_no=1209` 처럼 **와일드카드 없는 리터럴 쿼리는 정상 동작**한다.
1차 문서가 "쿼리스트링을 놓친다"고 뭉뚱그려 적었는데 **그보다 좁다.**

**그리고 이게 조선호텔을 탈락시킨 이유다.** 상세(`?product_no=`)는 대부분 허용인데
**목록(`?cate_no=`)이 전면 금지**라, 규칙을 지키면 **상품을 발견할 경로 자체가 없다.**
`can_fetch()` 만 믿은 어댑터는 금지된 목록을 긁으면서 "허용받았다"고 생각하게 된다.

> 운영자가 **개별 상품 100여 개를 하나씩 Disallow** 로 적어 둔 사이트다.
> 이 정도로 명시적인 의사표시를 구멍 뚫린 파서로 우회하는 건 §6-4 취지에 어긋난다.

### 5-2. `User-agent: *` 그룹에 **규칙이 0줄**인 경우 — 새 유형

`www.daesang.com/robots.txt` 는 **13바이트**다. 전부 이것뿐이다:

```
User-Agent: *
```

`Disallow` 도 `Allow` 도 없다. RFC 9309 상 **규칙 없는 그룹 = 제한 없음**이라 형식상 허용이다.
`CANDIDATES-DIRECT.md` §7-① 의 블루보틀(지시문 0개, 전부 주석)과 **다른 유형**이다 —
블루보틀은 `User-agent:` 줄 자체가 없었고, 대상은 **그룹은 있는데 안이 비었다.**

### 5-3. 사내 작업 메모가 그대로 공개된 robots

`www.shillahotels.com/robots.txt` (1,062B)는 지시문 대부분이 주석 처리돼 있고,
주석에 **내부 산출물 경로와 담당자 이름**이 들어 있다:

```
# robots.txt — The Shilla Hotels & Resorts (PRODUCTION)
# Spec: deliverables/qa-handoff/2026-07-07_robots-and-sitemap-spec_v1.1.md

User-agent: *
# Member-only / transactional (login-gated, no SEO value)
# ↓ 9.15 반영 후 4~6주 뒤에 seo 임명재 대표님에게 확인 후 주석 해제
# Disallow: /*/shillahotels/hub/login.do
...
Disallow: /*?alertMsgCode=
Disallow: /*?redirect=
```

**판정에는 영향이 없다**(살아 있는 규칙은 쿼리 트랩 3줄뿐 = 콘텐츠 경로 허용).
적어 두는 이유는 **주석 해제 예고가 명시돼 있어서**다. "9.15 반영 후 4~6주 뒤" 면
**지금(10월 초)이 그 시점이다.** 어댑터를 붙이면 곧 규칙이 바뀔 수 있다.

### 5-4. robots.txt 자리에 HTML 을 주는 곳이 **5곳 더**

1차가 5곳(롯데웰푸드·크라운·신세계푸드·남양유업·해태제과식품)을 적어 놨다. 추가분이다.

| 브랜드 | 상태코드 | Content-Type | 본문 |
|---|---|---|---|
| 동서식품 | **404** | `text/html` | 홈 HTML 1,245B |
| 웅진식품 | **404** | `text/html; charset=UTF-8` | 에러 HTML 1,103B |
| 서울우유 | **404** | `text/html; charset=UTF-8` | 에러 HTML 614B |
| 샘표 | **404** | `text/html` | 에러 HTML 1,839B |
| `dept.galleria.co.kr` | ⚠️ **200** | `text/html; charset=UTF-8` | **"페이지를 찾을 수 없습니다 \| 갤러리아백화점"** |

**갤러리아가 이번 건 중 제일 나쁘다** — 200 인데 본문이 404 안내 페이지다.
1차가 제안한 `text.lstrip().startswith('<')` 검사로 걸린다.

**반대 사례도 있다.** `www.ourhome.co.kr/robots.txt` 는 **404 + `text/plain` + 0바이트**다.
이건 HTML 이 아니라 **진짜 부재**다 — 규칙 없음 = 허용으로 깨끗하게 판정된다.
이번 조사에서 가장 다루기 쉬운 robots 였다.

### 6-4. 루트가 한 줄짜리 JS 리다이렉트인 사이트

`/` 만 받고 "빈 셸"로 판정하면 **멀쩡한 사이트를 버린다.** 이번에 4곳 걸렸다.

| 호스트 | 루트 크기 | 본문 |
|---|---:|---|
| `www.ccbk.co.kr` | **54B** | `<script> location.href = "/index.jsp"; </script>` |
| `www.htb.co.kr` | **80B** | `document.location.href="index.jsp";` |
| `www.ourhome.co.kr` | **75B** | `document.location.href="/index.do";` (Content-Type 이 `ISO-8859-1`) |
| `www.hyfresh.co.kr` | **219B** | `<META HTTP-EQUIV="refresh">` + `self.location.href="https://m.fredit.co.kr/main.do"` |

네 곳 다 **리다이렉트 끝에 진짜 사이트가 있다.**
`CRAWLING-POLICY.md` §6-5 의 파킹 지문("200인데 본문 0바이트")과 **헷갈리기 쉽다.**
구분법은 간단하다 — **본문에 `location.href` 가 있으면 따라가 본다.**

### 6-5. 리다이렉트를 켜 두면 TLS 실패 원인을 못 본다

`http://www.lottechilsung.co.kr/robots.txt` 를 `follow_redirects=True` 로 받으면
**`SSLCertVerificationError`** 가 뜬다. "평문 HTTP 도 안 되네" 로 읽힌다. **틀렸다.**
`follow_redirects=False` 로 바꾸면 진짜 원인이 보인다:

```
302  loc=https://company.lottechilsung.co.kr:443/robots.txt
```

**http 는 멀쩡했고** 서버가 https 로 넘긴 다음 거기서 체인이 깨진 것이다.
`CRAWLING-POLICY.md` §6-1 이 "인증서 깨짐 + 평문 HTTP 열림 → http 로 수집" 을 허용하는데,
**리다이렉트를 켜 두면 그 판정 자체를 못 한다.** TLS 문제를 만나면 **리다이렉트를 끄고 다시 봐라.**

## 7. 판단이 필요한 것 (운영자 몫)

> **결정에도 급이 있다 — 착수를 막는 것과 안 막는 것을 먼저 갈라라.**
> 아래 7건을 한 덩어리로 보면 "결정 날 때까지 전부 대기"가 돼 버린다. 실제로는 이렇게 갈린다.
>
> | 미결정 | 무엇이 바뀌나 | 이것 때문에 착수를 미뤄야 하나 |
> |---|---|---|
> | ⑤ robots 가 HTML (샘표·동서식품) | **요청 간격 상수 하나** | ⭕ **아니다.** 어댑터 로직이 안 바뀐다. 보수적 값으로 먼저 짜고 나중에 조이면 된다 |
> | ④ hy프레딧 비식품·외부브랜드 혼입 | `NONFOOD_WORDS` 보강 — **어댑터 바깥** | ⭕ **아니다.** 수집 범위 논쟁이 아니다 |
> | ② 롯데칠성 날짜를 `uploaded_at` 으로 쓸지 | 필드 하나 | ⭕ 아니다 |
> | ③ 아워홈 급식·컨세션을 넣을지 | **수집 대상 자체** — 뒤집히면 필터 재작성 | ❌ **그렇다** |
> | ① 롯데칠성 TLS | **붙을 수 있느냐** | ❌ **착수 불가** |
>
> (이 구분은 PM 쪽 배정 논의에서 정리된 것을 가져왔다. 조사 결과 자체는 아니다.)

**① 롯데칠성 TLS 체인을 어떻게 처리할 것인가 (§3-1).** 채택 1순위인데 우리 클라이언트가 못 붙는다.
인증서는 유효하고 소유자도 진짜다. `verify=False` 는 §6-1 이 금지한다.
**그리고 `http://` 우회도 막혀 있다 — 세 곳 다 http 를 https 로 강제 리다이렉트한다(§3-1 실측).**
올바른 중간 인증서를 `SSLContext` 에 보태는 방식이면 **검증을 켠 채로** 풀린다.
`CRAWLING-POLICY.md` §6-1 표에 **"서버가 중간 인증서를 빠뜨리거나 틀리게 보냄"** 칸을 추가할지 결정이 필요하다.
같은 건이 서울우유·신라호텔까지 **3곳**이다. **채택 1위 착수의 선행조건이다.**

**② 롯데칠성 날짜를 `uploaded_at` 으로 쓸 것인가 (§2-1).** 이미지 파일명 타임스탬프뿐이다.
`Item` 에 `uploaded_at`/`released_at` 구분이 이미 있으니 전자에 넣으면 거짓말은 아니다.
다만 **18건 중 몇 건이나 실제 출시일과 맞는지는 검증하지 않았다.**

**③ 아워홈 신메뉴를 화면에 섞을 것인가 (§2-2).** 출시 기사 밀도는 높은데
상당수가 **급식·컨세션·호텔 레스토랑 신메뉴**다. 소비자가 편의점에서 살 수 있는 물건이 아니다.
`BRANDS` 의 `FRANCHISE`/`MAKER` 어디에도 잘 안 맞는다.

**④ hy프레딧의 외부 브랜드 상품 (§6-2).** 159건에 `청년떡집`·`끼리`·`비비드키친` 이 섞인다.
`hy프레딧` 브랜드로 올리면 귀속이 틀리고, 걸러내면 건수가 줄어든다.

**⑤ robots 판정 불가 4곳 (§5-4).** 동서식품·웅진식품·서울우유·샘표 — robots.txt 가 HTML 이다.
이 중 **샘표(채택 3순위)·동서식품(채택 5순위)** 이 포함돼 **실제로 결정이 필요하다.**
1차 §7-③ 과 같은 건이고, `BRAND-CANDIDATES.md` §6-2 기준대로 **더 보수적인 간격**을 잡아야 한다.

**⑥ 신라호텔 robots 가 곧 바뀐다 (§5-3).** 주석에 "9.15 반영 후 4~6주 뒤에 … 주석 해제" 라고
적혀 있고 **지금이 그 시점**이다. 보류 상태라 당장은 영향이 없지만, 착수 전에 다시 받아 봐야 한다.

**⑦ 이용약관을 한 건도 못 읽었다.** 1차와 같은 사유다 — 브랜드당 5요청 예산을
robots·홈·목록·상세에 다 썼다. **채택 5곳은 약관 확인이 남아 있다.**

## 8. 확인 못 한 것

> ### ⭐ 다음 라운드에서 먼저 볼 것 — **코카콜라음료** (단, 기대치를 낮춰 잡아라)
>
> §1-1 에서 **탈락**으로 적었다. 탈락 근거는 유효하다. 다만 열린 질문이 남아 있어 여기 따로 세워 둔다.
>
> **2026-10-01 추가 실측으로 기대치를 낮췄다.** 초판에 "카테고리 탭에 텍스트 상품명이 있으면 판정이 바뀐다"고
> 적었는데, 그 뒤 검수자가 1장, 내가 2장(`select_code=101` 스파클링 · `401` 에너지 음료)을 실제로 열었다.
> **둘 다 반대 방향이었다:**
>
> ```
> GET /product/subIndex.jsp?select_code=101   200  16,395B
> GET /product/subIndex.jsp?select_code=401   200  16,454B
>   date 속성  : []          ← 신제품 페이지엔 있는 그 속성이 여기엔 없다
>   p.tit      : []
>   비어있지 않은 alt : ['로고','사이트맵','코카-콜라', '…고객상담실 080-024-5999…']   ← 전부 UI 문구
>   한글 텍스트 노드  : 제품정보·신제품·스파클링·주스·스포츠…  ← 전부 내비게이션
> ```
>
> **벽이 하나가 아니라 둘이다.**
> 1. 카테고리 탭에도 **텍스트 상품명이 없다**(2/9 표본). 신제품 페이지와 같다.
> 2. 더 나쁜 건 **카테고리 탭엔 `date` 속성조차 없다**는 것이다.
>    즉 **이름이 있을지 모르는 쪽과 날짜가 있는 쪽이 서로 다른 페이지**다.
>    설령 남은 탭에서 이름을 찾아도 **신제품 페이지의 `date` 와 무엇으로 이을지**가 또 남는다
>    (이미지 파일명? 표시 순서? 둘 다 약하다).
>
> - **남은 미확인**: 7장 (`201`·`301`·`501`·`802`·`901`·`905`·`906`). 표본 2장이 둘 다 비었으니 기대는 낮다.
> - **그래도 적어 두는 이유**: 신제품 페이지가 `<img date="2026-07-06">` 로 **날짜를 속성으로 준다.**
>   1차 실측 기준 24개 브랜드 중 `released_at` 을 주는 곳이 **3개**뿐이라, 혹시라도 풀리면 값이 크다.
> - **비용**: 요청 7회. robots 는 `*: Allow: /` 로 깨끗하다.
>
> **판정을 뒤집으려면 "이름 발견"만으로 부족하고 "이름 + 날짜 연결"까지 풀려야 한다.**
> 다음 사람이 7장을 다 열고 나서야 이 벽을 발견하는 일이 없도록 여기 적어 둔다.

1. **신라호텔 상품 데이터 소스** — 화면엔 있고 원본 HTML엔 없는데 **XHR 도 못 잡았다**(§3-4).
   보류를 채택으로 올리려면 이것부터다.
2. **푸르밀 NEW 배지의 XHR** — `.prod_thumbnail_badge` 를 채우는 요청을 못 찾았다(§3-3).
   그리고 **전체 상품 목록을 HTTP 로 받을 방법을 못 찾았다**(페이지네이션이 서버에서 안 먹는다).
3. **워커힐 다이닝 경로** — `/grandwalkerhillseoul/dining` 이 404. 실제 경로를 못 찾았다.
   robots 는 허용이라 경로만 찾으면 조사 가능하다.
4. **사조대림** — `www` 가 DNS 로는 해석되는데 80·443 둘 다 타임아웃이다.
   사명 변경·사이트 통합 가능성이 있는데 **대체 도메인을 추측하지 않았다.**
5. **연세우유** — 도메인 2개 다 NXDOMAIN. 공식 사이트가 있는지 자체를 모른다.
   (편의점 '연세우유 생크림빵'은 유명한데 그건 CU PB라 이미 CU 에 들어온다.)
6. **홈플러스 PB '시그니처' 상품군** — 사이트 전체에 `신상`·`신제품`·`NEW` 토큰이 **0개**라
   신상 축이 없다고 판정했는데, **검색·카테고리 안쪽은 안 봤다.**
   robots 가 `Content-Signal: ai-train=yes` 까지 선언한 드문 사이트라 아깝다.
7. **롯데칠성 `/kor/company/news/list.do`** — 보도자료 목록이 있고 `view.do?detailsKey=1680` 까지 봤는데
   **열어 보지 않았다.** 신제품 페이지가 날짜를 안 줘서 **여기가 날짜 보완처가 될 수 있다.**
   ⚠️ robots 가 **Googlebot 에게만** 이 경로를 금지한다(`*` 는 `Allow: /`). 의도가 모호하다.
8. **동서식품 `POST /api/product/mainListData`** — 응답 구조는 확인했는데(`prodName`·`brandNm`)
   **신제품 플래그가 있는지 안 봤다.** 있으면 보도자료보다 상품 축이 깔끔해진다.
9. **대상 `POST /proc/boardListJson.jsp` 의 응답 스키마** — 호출되는 건 봤는데 본문을 안 열었다.
10. **태극당 제품 목록의 렌더 경로** — JS 라는 것만 확인했고 **번들을 안 열어 봤다.**
    1차 §9-3 과 같은 미해결이다.
11. **hy프레딧 상품의 등록일** — 159건 목록에 날짜가 보이지 않는다. 상세를 안 열었다.

## 9. 어댑터를 쓸 사람에게

1. **TLS `unable to get local issuer certificate` 를 만나면 `verify=False` 로 가지 마라(§3-1).**
   `openssl s_client -showcerts` 로 **서버가 보낸 인증서 장수를 먼저 세라.**
   1장이면 중간 인증서 누락, 3장인데도 실패면 **엉뚱한 중간 인증서**다(롯데칠성). 둘 다 보충으로 풀린다.
   그리고 **"브라우저에선 되는데"는 반증이 아니다** — 브라우저는 AIA 로 알아서 메운다.
2. **TLS 문제를 볼 땐 리다이렉트를 꺼라(§6-5).** 켜 두면 `http://` 요청의 실패가
   https 단계에서 난 것인지 구분이 안 된다. 롯데칠성이 그 경우다.
3. **원본 HTML 에서 `NEW` 를 문자열로 세지 마라(§6-1).** 푸르밀은 원본 120개 / 실제 2개다.
   **주석 처리된 배지**가 범인이다. 브라우저로 렌더 DOM 과 대조하고 시작해라.
   **아임웹 사이트면 이 검사를 먼저** — 노티드도 같은 건이었다.
4. **`can_fetch()` 의 쿼리 구멍은 `*` 가 `?` 앞에 올 때만이다(§5-1).** 1차 기록보다 좁다.
   리터럴 쿼리(`?product_no=1209`)는 정상 판정된다. 조선호텔은 **목록이 막혀** 탈락이지
   파서 구멍 때문에 탈락이 아니다 — 구멍은 그걸 **못 보게 가린다.**
5. **루트가 54~219바이트라고 죽은 사이트가 아니다(§6-4).** 본문에 `location.href` 가 있으면 따라가라.
   코카콜라음료·해태htb·아워홈·hy프레딧 넷 다 이 경우다.
6. **보도자료를 쓸 거면 역필터에 '기계'를 넣어라(§2-3).**
   `동서식품, 캡슐커피 머신 '카누 바리스타 오아시스' 출시` 가 '출시' 정필터를 통과하는데 먹는 게 아니다.
   `NONFOOD_WORDS` 에 `머신` 류가 없다.
7. **hy프레딧을 붙이기 전에 `NONFOOD_WORDS` 를 보강해라(§6-2).**
   `찜기`·`조리도구`·`플레이팅팬`·`주방 가위` 가 없다. 보강 후 **전체 데이터에 식품 오탐 0인지 먼저 세라.**
8. **롯데칠성 날짜는 `released_at` 이 아니라 `uploaded_at` 이다(§2-1).**
   `/image/2026/9/202609220615531610.png` 는 **이미지 업로드 시각**이다. 같은 성격이 신라호텔
   `/hbcimages/260827/20260827191701_...` 에도 있다.
9. **코카콜라음료 신제품 페이지에서 날짜를 정규식으로 줍지 마라(§3-2).**
   같은 페이지 하단에 `작성일 : 2015-04-20` 이 있다. `<img date="...">` 속성으로 좁혀야 한다.
   (어차피 상품명이 없어 탈락이지만, 날짜 패턴은 재사용 가치가 있다.)
10. **태극당은 `http://` 로만 붙는다(§4).** HTTPS 는 `*.gabia.io` 호스팅 기본 인증서다.
    §6-1 의 "인증서 불일치 + 평문 열림 → http 허용" 칸에 해당한다. 모듈 docstring 에 이유를 적어라.
11. **동서식품은 POST 다.** `GET /api/news/listData/1` 이 아니라
    `POST` + `Content-Type: application/json` + 빈 바디 `{}` 다. robots 에 `/api/` 금지가 없다
    (애초에 robots 가 HTML 이라 규칙이 없다 — §5-4, 그래서 **보수적 간격**이 필요하다).
12. **동서식품 제목 필드는 `sj` 다(§2-2).** `nttSj` 가 아니다. 본문은 `cn`/`cnHtml`, 날짜는 `regDt`.
    키 전체 목록을 §2-2 에 실어 뒀으니 **거기서 베껴라.**
13. **탐색 코드의 폴백 체인을 그대로 문서에 옮기지 마라.** 이 문서 초판의 `nttSj` 오류가 그렇게 났다 —
    조사할 때 `n.nttSj || n.title || n.sj` 처럼 후보를 늘어놓고 돌렸는데, **실제로 값을 낸 건 `sj`** 인데
    체인의 **첫 이름**을 받아 적었다. 폴백은 조사 단계에선 편하지만 **어느 키가 맞았는지를 가린다.**
    기록할 땐 `Object.keys(row)` 를 찍어 **실존 키를 확인하고 적어라.**
    틀린 키는 `KeyError` 로 안 터지고 `.get()` 이 `None` 을 돌려주므로
    **어댑터가 예외 없이 조용히 0건을 낸다** — 이 레포가 가장 여러 번 데인 실패 모양이다.
