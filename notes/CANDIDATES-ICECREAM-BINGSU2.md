## 2. 아이스크림 K1 하위 33곳

### 2-1. 🔴 먼저: **"가맹점 수 미확인"이 풀렸다. 그리고 거의 전부 0개다**

HANDOFF 는 "33곳은 가맹점 수가 미확인이라 순위를 못 매겨 뒤로 밀렸다"고 적었다.
**가맹점 수는 받을 수 있다.** 공정위 정보공개서를 재게시하는 창업 포털이 업종
통계를 통째로 깔아 둔다(2차 출처 — 공정위 원본이 아니다. 표에 그렇게 표시했다):

```
GET https://pchasignal.kr/category/아이스크림%2F빙수      200 / 127,249B
    → "공정위 등록 102개 · **가맹점 보유 53개 브랜드**" + 53곳 전부의 가맹점 수
GET https://startuplus.kr/brands/<브랜드명>               200 또는 404(미등재)
```

**읽는 법이 핵심이다. 공정위 K1 등록 102개 중 가맹점이 1개라도 있는 건 53개뿐이다.**
나머지 49개는 **직영만 있거나 정보공개서만 올려 둔 곳**이다.
→ **내 33곳 중 가맹점이 잡히는 건 5곳뿐이고, 최대가 39개다**:

## 3. 🔴 냉동피자 0곳 — **진짜 원인은 `brand_sub` 구조가 아니다**

HANDOFF §5 는 이렇게 적었다:

> 상위 15 전부 조사했고 **상위 3사(약 83%)가 전부 어댑터로 덮여 있다** …
> `brand_sub` 를 상품별로 둘 수 있게 되기 전까지 해결이 안 된다. **더 조사해도 안 바뀐다.**

**두 문장 다 틀렸다.** 코드와 데이터로 재확인했다.

### 3-1. 반증 ① — 상품별 분류 기능은 **이미 있다**. 만들 필요가 없다

`taxonomy.sub_of()` 는 `brand_sub` 를 **마지막에** 본다. 그 앞에 **상품별 분기**가 있다:

```python
# taxonomy.py sub_of()
mapped = vendor_sub(r.get("brand", ""), r.get("category", ""))   # ← 상품별
if mapped and mapped != NONFOOD:
    return mapped
...
return r.get("brand_sub", "")                                     # ← 브랜드 단위(최후)
```
`vendor_sub()` 는 `VENDOR_SUBS[브랜드][업체분류]` 표를 본다. 지금 그 표에
**`hy프레딧` 한 곳만** 들어 있을 뿐, 구조는 브랜드를 안 가린다.

**실행해서 확인했다**(`taxonomy.py` 는 읽기만 했고, 아래는 런타임에 가짜 행을 넣어 본 것이다):
```
VENDOR_SUBS['오뚜기'] = {'냉동피자': '피자'}
sub_of({brand:'오뚜기', brand_type:'제조사', brand_sub:'라면',
        category:'냉동피자', name:'오뚜기 콤비네이션피자'})  → '피자'      ✅
sub_of({brand:'오뚜기', brand_type:'제조사', brand_sub:'라면',
        category:'',       name:'진라면'})                  → '라면'      ✅ (안 망가진다)
primary_of(…)                                               → '식품'
```
→ **오뚜기를 통째로 `피자` 로 찍을 필요가 전혀 없다.** 어댑터가 그 상품에만
`Item.category="냉동피자"` 를 달고 `VENDOR_SUBS` 에 한 줄 넣으면 **그 상품만** `피자` 로 간다.
HANDOFF 가 말한 "거짓 분류" 딜레마는 **애초에 존재하지 않는다.**
(이 기능은 hy프레딧이 세제·양말까지 '냉동식품'이 됐던 사고를 고치며 들어왔다.
 `taxonomy.py` 주석이 그 경위를 그대로 적어 두고 있는데, 냉동피자 조사 때 안 읽은 것으로 보인다.)

### 3-2. 반증 ② — **분류 문제가 아니라 애초에 한 건도 안 들어온다**

분류를 따지려면 상품이 먼저 있어야 한다. **없다.**

```
data/products.json  전체 13,958건
  이름에 '피자' 가 든 상품        104건
  그중 brand_type == '제조사'      0건   ← 🔴
```
104건은 전부 CU(12)·네네치킨(8)·맘스터치(7)·파리바게뜨(6)·탐앤탐스(6)·BBQ(6)…
즉 **편의점·치킨·카페·외식 프랜차이즈**다. 오뚜기·CJ제일제당·풀무원·신세계푸드가
지금 내놓는 전체 31건은 이렇다:

```
오뚜기(14)     레몬진저샷 · 흑미밥 · 일품 떡갈비 · 한강라면 · 열찐만두 · 카레콘볼 …
CJ제일제당(4)  햇반 여주쌀밥 · 햇반 부드러운 미니밥 · 해찬들 옛장 · 비비고 김부각
풀무원(7)      저당 통현미 크런치볼 · 식감혁신 본격 떡볶이 · 생만두 · ORGA 저염 육수 …
신세계푸드(6)  보앤미 프리미엄 건강빵 · 멜론 디저트 · 생과일 한가득 케이크 …
```
**피자가 한 줄도 없다.** `brand_sub` 를 뭘로 바꾸든 분류할 대상이 없다.

### 3-3. 진짜 원인 — **소스 종류가 안 맞는다**(보도자료 축의 구조적 사각)

네 어댑터는 전부 **보도자료 피드**를 읽는다. 그 피드를 오늘 직접 받아 봤다:

| HANDOFF §5 | 실측 |
|---|---|

**지금 이 레포가 쓰는 유일한 제조사 소스 유형(보도자료)에 구조적으로 안 걸린다.**
