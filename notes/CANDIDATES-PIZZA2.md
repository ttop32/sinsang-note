## 1. 피자스쿨 — 워드프레스 REST API 가 열려 있다

### 1-1. 받는 곳

```
GET http://pizzaschool.net/wp-json/wp/v2/portfolio?per_page=100&_embed=wp:featuredmedia
→ 200 application/json, X-WP-Total: 63 / X-WP-TotalPages: 1, 710KB
GET http://pizzaschool.net/wp-json/wp/v2/portfolio_entries?per_page=100
→ 200, 분류 6종
```

**요청 2회로 끝난다.** 메뉴는 `portfolio` 커스텀 포스트 타입 하나에 전부 있다.
다른 post_type 에는 메뉴가 없다(`/wp-json/wp/v2/types` 실측) —
`banner` 34건은 홈 배너, `post` 267건은 매장 오픈·기부 소식, `page` 43건은 공지·알레르기 안내다.

⚠️ **https 를 쓰면 안 된다.** 1차 노트가 적어둔 대로이고 오늘 재확인했다.

```
https://pizzaschool.net/... → ConnectError [SSL: CERTIFICATE_VERIFY_FAILED] self-signed certificate
http://pizzaschool.net/...  → 200, https 리다이렉트 없음
```

`verify=False` 로 뚫지 않고 http 로 간다(스쿨푸드·퀴즈노스와 같은 칸).

### 1-3. 🔴 `modified` 는 쓰면 안 된다

```
2026-01-07 15건 · 2025-03-14 10건 · 2025-12-18 9건 · 2024-10-27 7건 · 2023-12-21 6건 …
```

63건 중 15건(24%)이 한 날짜에 찍혀 있고 **그 안에 2015년 치즈피자·페퍼로니피자가 들어 있다.**
가격 개정·이미지 교체 때 일괄 편집한 자국이다. `modified` 를 썼으면 11년 된 메뉴판이
통째로 신상이 됐다. 그래서 `date` 만 쓴다.

`치킨스틱&#038;윙` 처럼 HTML 엔티티가 든 이름이 있어 `html.unescape()` 로 푼다.

### 2-6. `released_at` 이 아니라 `uploaded_at` 에 넣는다

CMS 행 생성 시각이지 브랜드가 발표한 출시일이 아니고, 일괄 등록 자국이 한 번 있다 —
**81건 중 2020-08-21 밤 21:33~23:38 에 20건(25%)** 이 몰려 있다(지금 사이트를 세운 날이다.
푸터는 `COPYRIGHT © 2015` 지만 그 20건이 전부 그 밤에 찍혔다).
`uploaded_at` 에 두면 `rules.untrust_bulk_dates()` 가 그런 묶음을 한 번 더 걸러준다.
`rules.is_fresh()` 는 `released_at` 과 `uploaded_at` 을 같은 자격으로 보므로 판정력 손해는 없다.

날짜 분포(수집 결과 62건 기준):

```
2020-08-21 20 · 2023-06-13  9 · 2026-05-18  6 · 2023-02-21 3 · 2026-10-01 3
2022-03-03  2 · 2023-07-13  2 · 2024-07-03 2 · 2024-11-12 2 · 2025-04-03 2 · 2026-01-19 2
나머지(2020-09-02 · 2021-07-06 · 2021-07-23 · 2022-04-19 · 2022-06-23 · 2022-09-08 ·
2024-02-26 · 2025-04-02 · 2025-12-02) 각 1
```

몰린 두 날은 **라인 단위 등록**이라 거짓이 아니다 — 2020-08-21 사이트 개장,
2023-06-13 퍼스널(마루업) 라인 신설. 2020-08-21 은 20/62(32%)로 가드(1/2)에 안 걸리고,

### 2-8. 나머지

- `is_new` 는 **전건 `None`** 이다. 배지가 없고 신메뉴 칸도 못 믿으니 '모른다'가 정직하다.
  판정은 `uploaded_at` 과 60일 창이 한다. 오늘(2026-10-08) 기준 창 안에 드는 건
  2026-10-01 피자설기 3종뿐이고, 그게 맞는 답이다.
- 카테고리 10개를 다 받고 `/menu/10`(신메뉴)만 **맨 뒤로 돌린다.** 이름이 겹칠 때 상설 카테고리
  이름이 `category` 에 들어가고 '신메뉴' 라는 선반 이름이 상품에 눌러붙지 않는다.
  그래도 신메뉴 칸에만 있는 6건(피자설기 3종·혼밥박스·닭꼬치 4종 세트·불닭 치즈폭탄피자 세트)은
  거기서만 들어오므로 빼지 않는다.
- `<li class="soldout">` 가 41건 붙는데 **품절이 아니다.** 설명이 전부 `※일부 매장 한정 판매` 이고
  품절 오버레이(`.sold_t`) 마크업은 안 들어온다. 온라인 주문 대상이 아니라는 표시로 보여 안 거른다.
- 설명(`p.t2`)에 전 상품 공통 안내문이 붙어 있다 — `(본 사진은 이미지컷…)` 73건 ·
  `(본 가격은 포장…)` 62건 · `※일부 매장 한정 판매` 15건. 떼고 넣는다.
- 상세 `/product/<id>` 는 **날짜가 없고** 원산지 표만 길다(118KB). 받지 않는다.
- 가격(`p.t3`)은 `Item` 에 자리가 없어 버린다. 영문명은 사이트에 없다.
- http·https 둘 다 200 이고 apex·www 둘 다 열린다. https 를 쓴다.
- ⚠️ 이용약관 제9조가 복제·상업적 이용을 금지한다. 운영자 승인으로 수집하되 삭제 요청이 오면
  즉시 내린다(이마트24·도미노피자와 같은 칸).
- 주류·비식품은 없다. 상품 62건을 전부 눈으로 읽었다.
