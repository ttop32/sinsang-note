## 1. 직접 써본 소감

**데스크톱(748px)에서 5분**

첫인상은 나쁘지 않다. 사진이 크고 어두운 배경에 음식이 잘 뜬다. 그런데 스크롤을 시작하면
바로 이상해진다. 프랭크버거 3장 → 파파존스 6장 → 커피빈 **28장** → 설빙 14장 → 빽다방 11장.
커피빈 구간에서만 화면 7개를 넘긴다. "오늘 뭐 나왔나" 보러 온 사람이 커피빈 음료 28잔을
연속으로 보게 되는 건 신제품 피드가 아니라 커피빈 메뉴판이다. 전체 페이지 길이가
**54 화면**(57,716px)이고, 끝까지 가면 7월 8일 상품이 나온다. 그런데 푸터는 "최근 21일"이라고 써 있다.

카드를 눌렀다. 설빙 카드를 누르든 커피빈 카드를 누르든, **그 브랜드의 메뉴 목록 페이지**로 간다.
24개 브랜드에 링크가 정확히 24개뿐이다(브랜드당 1개). 즉 "브랜드에서 보기 →"는
항상 "브랜드 메뉴판 첫 페이지에서 보기"다. 방금 본 상품을 거기서 다시 찾아야 한다.
그런데 정작 우리가 만들어 둔 상품 페이지(`/p/...` 337장)는 **홈에서 단 한 개도 링크가 없다.**
홈에 있는 내부 링크는 스킵 링크 `#g` 하나가 전부다.

**모바일(375px)에서 5분**

첫 화면에 상품 이름이 **하나도 안 보인다.** 헤더 130px + 검색 56px + 탭 59px 을 지나면
바로 이미지가 오는데, 그 이미지 한 장이 164×400px 세로 직사각형이다(정사각형이어야 하는데
`height="400"` 속성이 CSS `aspect-ratio:1` 을 이겨서 400px 로 고정됐다). 버거가 위아래로
잘려 있고, 이름을 보려면 한 번 스크롤해야 한다. 카드 하나가 586px 이라 한 화면에 1.4장이다.
탭도 8개 중 4개(전체·편의점·카페·햄버거)만 보이고, 옆으로 밀리는 줄 알려주는 표시가 없어서
피자·치킨·디저트·분식이 있는 줄 모른다.

**상품 페이지 / 브랜드 페이지**

여기가 제일 잘 만들어져 있다. `/p/스타벅스-찰떡콩떡-베이글/` 은 빵 부스러기 내비게이션,
큰 사진, 설명, 브랜드·유형·카테고리·등록일 표, "스타벅스의 다른 신제품" 5장까지 깔끔하다.
`/b/스타벅스/` 도 "스타벅스 전체 메뉴 316건 중 최근 등록분입니다" 라는 정직한 문장이 있다.
**문제는 아무도 여기 못 온다는 것이다.** 검색엔진으로 들어온 사람만 본다.
그리고 이 좋은 상세 페이지에는 정작 브랜드 공식 사이트로 나가는 링크가 없다.
홈은 나가는 링크만 있고, 상세는 나가는 링크가 없다. 정확히 반대로 돼 있다.

## 2. 발견한 결함 (심각도 순)

### S1. 홈 → 우리 상세 페이지로 가는 링크가 0개 (상세 337장 전부 고아)

홈페이지의 `<a>` 257개 중 내부 링크는 스킵 링크 `#g` 하나. 카드 300장 전부 외부 브랜드
사이트로 나간다. `/p/` 337장, `/b/` 24장, `/c/` 5장이 빌드돼 사이트맵(332개)에 들어가 있지만
홈에서 도달할 수 없다. 만들어 놓고 안 쓰는 자산이 전체 페이지의 99%다.

### S2. 카드 클릭 = 브랜드 메뉴판 첫 페이지 (상품 페이지가 아님)

`data/products.json` 4,390건의 `url` 이 **브랜드당 정확히 1개**다.

| 브랜드 | 상품 수 | 고유 URL |
|---|---|---|
| 이마트24 | 984 | 1 |
| CU | 666 | 1 |
| 커피빈 | 166 | 1 |
| 설빙 | 96 | 1 |
| (24개 브랜드 전부 동일) | | 1 |

설빙 14장 전부가 `https://sulbing.com/menu/` 로 간다. 사용자가 "허쉬초코크런치설빙"을 누르면
설빙 전체 메뉴판에 떨어지고, 거기서 그 제품을 다시 찾아야 한다.
스타벅스는 아예 상품 URL이 316건 전부 비어 있어 브랜드 대표 주소로 대체돼 있다.

### S3. 같은 카드에 NEW 뱃지가 두 번 — 300장 중 91장 (30%)

우리가 붙이는 NEW 뱃지와, 브랜드가 준 `labels: ["NEW"]` 를 그대로 출력한 뱃지가 겹친다.

- 파파존스 `불닭 까르보 치킨`, `골든 체다 페퍼` → `NEW NEW 파파존스`
- CU 40장 전부 → `NEW NEW CU`
- 버거킹 17장, bhc치킨 13장, 맘스터치 10장, 도미노피자·피자헛·BBQ·이삭토스트 전부
- 도미노피자 `치즈폴레 무슈스` → `NEW 기간한정 NEW` (NEW 사이에 기간한정이 끼어 있음)
- 교촌치킨 10장 → `NEW 신메뉴` (같은 뜻 두 번)

전체 라벨 출현 빈도: NEW 359, 신메뉴 10, ICE 1, 기간한정 1. NEW가 카드 수(300)보다 많다.

### S4. 푸터가 "최근 21일"이라고 쓰는데 21%가 그보다 오래됐다

300장 중 **63장(21%)** 이 2026-09-09 이전. 가장 오래된 것은 **2026-07-08 (84일 전)** —
bhc치킨 `콰삭감자`, `후라이드 닭똥집 튀김`, `크리스피번(밀크)` 등 9장. 7월 물량이 22장 있다.
화면에 쓰인 숫자와 화면에 있는 내용이 다르다.

### S5. 탭 숫자와 실제 카드 수가 다름 (전체 302 vs 300, 피자 31 vs 29)

`docs/index.html` 에서 `class="c"` 카드는 300개, `data-g="피자"` 는 29개.
그런데 칩은 전체 302, 피자 31로 렌더된다. 다른 6개 탭(편의점 84·카페 108·햄버거 30·
치킨 31·디저트 17·분식 1)은 정확히 일치한다. 피자 탭을 누르면 "31건"이라 써 있는데 29장만 나온다.

### S6. 카테고리 = 브랜드 업종 1:1 (음식 분류가 아님)

브랜드 하나가 정확히 카테고리 하나에 고정돼 있다. 그래서:

- 맘스터치 `불고기페퍼로니 (싱글피자)`, `트리플미트 (싱글피자)`, `더블치즈포테이토 (싱글피자)` → **햄버거** 탭
- 버거킹 `카페라떼`, `아이스 카페라떼`, `해쉬브라운` → **햄버거** 탭
- 굽네치킨 `굽네 순살 시카고 피자 시리즈`, `콤비네이션 시카고 피자` → **치킨** 탭
- bhc치킨 `가래떡 떡볶이`, `파인샤베트`, `허니버터요거트 소스`, `크리스피번(바나나)` → **치킨** 탭
- 미스터피자 `펩시콜라` → **피자** 탭
- 던킨 `피치 아이스티 (R)`, `비타슬러시 레몬(R)` → **디저트** 탭

그리고 이게 빈 탭의 원인이다. 디저트 17 = 던킨16 + 배스킨라빈스1, 분식 1 = 이삭토스트1.
"분식"을 눌렀는데 이삭토스트 토스트 한 장이 나오는 건 분류가 잘못된 게 아니라
분류 이름이 내용과 다른 것이다.

- 교촌치킨 `반반윙콤비[간장+레드]`, `[간장+마라레드]`, `[간장+허니갈릭]`, `[레드+마라레드]`,
  `[레드+허니갈릭]`, `[마라레드+허니갈릭]` — 단품 4종의 조합 6장
- 빽다방 `챔피언스 블랙 벨벳 라떼 HOT` / `ICED` / `디카페인 HOT` / `디카페인 ICED` — 음료 1종에 4장.
  `블랙 벨벳 자바칩빽스치노` 도 일반/소프트/디카페인/디카페인소프트 4장
- 이디야커피 `(L) HOT ~` / `(L) ICED ~` 쌍 5개 = 10장. 이름 앞 사이즈 코드 `(L)` 도 그대로
- 커피빈 `슈크림 라떼`/`아이스 슈크림 라떼`, `바닐라 빈 플랫화이트`/`아이스 ~`,
  `더블 브레베 라떼`/`아이스 ~`, `달고나 크림 라떼`/`달고나 크림 IB`
  (`IB` = Ice Blended 내부 약어)
- 폴바셋 `유자 그릭요거트 아이스크림` 라떼/(콘)/혼합(콘)/(컵)/혼합(컵)/토핑컵 — 6장
- bhc치킨 `크리스피번(바나나)`/`(뿌링클)`/`(밀크)` 3장, `커링클`/`커링클/뿌링클 반반`
- 이디야커피 `딸기 쇼콜라 크런치(박스)`/`(낱개)`
- 설빙 `흑절미설빙`/`팥흑절미설빙`, `인절미설빙`/`팥인절미설빙`

### S11. 모바일 이미지가 정사각형이 아니라 세로로 늘어남

CSS는 `.c img{width:100%;aspect-ratio:1;object-fit:cover}` 인데, HTML에 `height="400"` 속성이
있고 CSS가 `height` 를 지정하지 않아 **속성값 400px 이 그대로 적용**된다. `aspect-ratio` 는 무시된다.

| 뷰포트 | 이미지 실제 크기 | 있어야 할 크기 |
|---|---|---|
| 375px (2열) | 164 × **400** | 164 × 164 |
| 748px (3열) | 226 × **400** | 226 × 226 |

결과: 카드 1장이 586px, 375px 화면에서 첫 화면에 상품 이름이 하나도 안 보이고,
전체 문서가 375px에서 77,400px(95 화면)까지 늘어난다.

### S12. 홈페이지에만 `<head>` 태그가 통째로 빠짐

`404.html`, `/b/*`, `/c/*`, `/p/*` 는 전부 아래를 갖고 있는데 **`index.html` 만 하나도 없다.**

| 태그 | index.html | 다른 모든 페이지 |
|---|---|---|
| `link rel=canonical` | ✗ | ✓ |
| `link rel=icon` / `apple-touch-icon` | ✗ | ✓ |
| `link rel=manifest` | ✗ | ✓ |
| `link rel=alternate` (Atom 피드) | ✗ | ✓ |
| `og:image` / `og:url` / `og:type` / `og:site_name` | ✗ | ✓ |

영향: 홈 링크를 카톡·슬랙에 붙이면 **썸네일 없이 글자만** 뜬다(사진이 주인공인 서비스인데).
브라우저 탭에 파비콘이 없다. iOS "홈 화면에 추가"를 해도 이름·아이콘이 안 붙는다.
`manifest.webmanifest`·`icon-180.png`·`icon-512.png`·`icon.svg` 는 만들어져 배포돼 있는데
홈에서 아무도 안 부른다.

### S13. Atom 피드 50개 항목의 `<updated>` 가 전부 동일

`docs/feed.xml` 의 `<updated>` 51개가 전부 `2026-09-30T00:00:00Z` (피드 자신 + 항목 50개).
상품 날짜가 아니라 빌드 날짜가 들어간다. RSS 리더 입장에서는 **매일 아침 50개 항목이
전부 갱신된 것으로 보인다** → 매일 50건 중복 알림. 지금 있는 유일한 재방문 장치가
오히려 구독을 끊게 만든다. (피드 링크 자체가 홈에 없어서 아직 아무도 구독을 못 한 게 다행이다.)

### S14. 삭제하기로 한 "세트" 상품 페이지 35장이 아직 살아 있음

`docs/p/` 디렉터리 337개 중 사이트맵(302개)에 없는 **35개**가 남아 있다.
실제로 접속하면 HTTP 200 이 떨어진다:

- `https://ttop32.github.io/sinsang-note/p/버거킹-몬스터-맥시멈-라지세트/` → 200, 제목 `버거킹 몬스터 맥시멈 라지세트 — 신제품 | 신상노트`
- `https://ttop32.github.io/sinsang-note/p/bbq-필크런치-소떡-세트/` → 200, 제목 `BBQ 필크런치 소떡 세트 — 신제품 | 신상노트`
- 그 외 `버거킹-데리야킹-크리스퍼-세트`, `버거킹-메종-트러플치즈-버거-라지세트`,
  `맘스터치-싱글피자n버거세트`, `cu-김-닭강정김밥콤보세트1`, `bbq-필크런치-치즈볼-세트` 등

"세트는 신규가 아니잖아" 로 피드에서는 뺐지만 **파일은 지워지지 않아** 여전히
"— 신제품" 이라는 제목으로 공개돼 있다. 이전 사이트맵으로 이미 색인됐다면 검색에도 뜬다.

### 부가 확인 (문제 없었던 것)

- 최신순 정렬 정상: 300장 날짜 역순 위반 0건. 브랜드순 토글도 동작.
- 존재하지 않는 주소 → 404.html 정상 (`/p/없는페이지12345/` → HTTP 404).
- 탭 버튼에 `aria-pressed` 정상. 이미지 `alt` 에 "브랜드 상품명" 들어감. `nav[aria-label="분류"]` 있음.
- 다크/라이트 모드 둘 다 정상 렌더. 이미지 로드 실패는 관찰 범위에서 1건뿐.
- `/b/`, `/p/` 페이지는 빵 부스러기·구조화 데이터(JSON-LD)·og:image 까지 잘 돼 있다.

## 3. 기능 제안

우선순위는 **P0 = 신뢰가 깨지고 있어서 지금 막아야 하는 것**,
**P1 = 재방문을 만드는 것**, **P2 = 그 다음**.

### P0-1. 카드 클릭 → 우리 상세 페이지로

**왜** 지금 카드를 누르면 브랜드 메뉴판 첫 페이지로 나간다(S2). 우리가 가진 가장 좋은 자산인
상세 페이지 337장은 아무도 못 본다(S1). 사용자는 클릭 한 번에 남의 사이트로 튕겨나가고,
우리는 그 사람을 다시 볼 기회를 잃는다.

**어떻게** 빌드 타임. 카드의 `href` 를 `/p/<slug>/` 로 바꾸고, 카드 하단의 "브랜드에서 보기 →"는
상세 페이지로 옮긴다(지금 상세 페이지엔 외부 링크가 아예 없다). 상세 페이지에 있는
"브랜드에서 보기"는 브랜드 메뉴판으로 가더라도, 그 전에 우리 페이지에서 사진·설명·
같은 브랜드 다른 신상까지 보고 나가게 된다.

**우선순위** P0. 이거 하나로 페이지뷰 구조가 바뀐다.

### P0-2. NEW 뱃지 하나만, 근거는 날짜 옆에 한 줄로

**왜** 91장이 NEW를 두 번 달고 있다(S3). 그리고 NEW의 근거가 브랜드마다 다른데 화면은 똑같이 보인다.
데이터를 뜯어보면 근거가 세 갈래다.

| 근거 | 해당 브랜드 | 건수 |
|---|---|---|
| 브랜드가 등록일을 명시 (`released_at`) | 피자헛, 이삭토스트, 배스킨라빈스 | 145 |
| 브랜드 사이트 게시일 (`uploaded_at`) | 스타벅스·이디야·폴바셋·메가·교촌·BBQ·bhc·버거킹·도미노·맘스터치·굽네 | 1,361 |
| 우리가 어제 없던 걸 오늘 봄 (`first_seen` diff) | 이마트24(984), 세븐일레븐 일부, CU, 던킨, 설빙, 커피빈, 빽다방, 미스터피자, 파파존스 | 나머지 |

그리고 `is_new` 는 일부 브랜드에서 **신호가 아니다.** CU 666건 중 666건, 버거킹 54/54,
맘스터치 17/17, 굽네치킨 8/8 이 전부 `is_new: true` 다. 전건이 true 면 아무 뜻이 없는데
화면에는 다른 브랜드의 진짜 NEW와 똑같은 주황 뱃지로 나간다.

**어떻게**
1. 브랜드가 준 `labels` 중 `NEW`·`신메뉴`·`new` 는 빌드 타임에 버린다(우리 뱃지와 중복).
   `기간한정`·`ICE`·`THIN` 처럼 정보가 있는 라벨만 회색 보조 뱃지로 남긴다.
2. 빌드할 때 브랜드별 `is_new` 참 비율을 계산해서 **100%면 그 브랜드의 `is_new` 는 무시**하고
   날짜 근거로만 판단한다.
3. 뱃지로 등급을 나누지 말고(사용자는 "강한 근거/약한 근거" 같은 걸 읽고 싶지 않다),
   **날짜 문구를 두 가지로만** 쓴다.
   - 브랜드 날짜가 있으면 → `9월 28일 출시`
   - 우리가 처음 본 날뿐이면 → `9월 30일 처음 확인`
   숨기지 않고, 기술 용어도 안 쓰고, 문장 하나로 근거가 드러난다.

**우선순위** P0.

### P0-3. 상품명 정리 파이프라인 (편의점 84장)

**왜** `샐)닭가슴살&단호박샐2`, `마즈)스키틀즈젤리(후르츠요거트` 를 읽을 수 있는 사람은 없다(S7).
편의점 탭 전체가 이 상태다. "화면에 신뢰가 안 가면 바로 떠난다"의 가장 노골적인 사례.

**어떻게** 빌드 타임 정규화. 순서대로:
1. 앞쪽 `제조사)` / `분류)` 접두 제거 — 단, 제조사명은 버리지 말고 카드 아래 회색 보조줄
   (`농심`, `CJ`)로 옮긴다. CU의 `도)`·`김)`·`샌)` 은 **음식 카테고리로 승격**시킬 수 있는
   좋은 재료다(P1-3 참고).
2. 끝의 고립된 숫자 1자리 제거 (`정식1` → `정식`). 단 `맥시멈2`, `몬스터3` 처럼
   제품명의 일부일 수 있으니 **한글로 끝난 뒤 숫자 1자리** 패턴에만 적용.
3. 괄호가 열리고 안 닫힌 이름은 **여는 괄호 앞에서 자른다**
   (`동아)가그린 리뉴얼 마일드(제로` → `가그린 리뉴얼 마일드`).
4. 용량·규격(`250ml`, `90g`, `(큰컵)`)은 이름에서 떼서 보조줄로.
5. 정리 후 이름이 3자 미만이 되면 그 상품은 아예 피드에서 제외한다(복구 불가로 판단).

**우선순위** P0.

### P0-4. 음식 아닌 것·주류·굿즈 제외 목록

**왜** 바세린 바디밤과 가그린이 "오늘의 신제품"에 있다(S8). 하나만 보여도 "이 사이트 대충 만들었네"가 된다.

**어떻게** 빌드 타임 제외 규칙 (지금 `promo` 제외 규칙이 붙어 있는 자리에 추가):
- 비식품 키워드: `바세린|가그린|치약|칫솔|샴푸|바디|핸드크림|마스크|건전지|스타킹|파스`
- 굿즈·쿠폰: 이름 또는 설명에 `굿즈|포토카드|키링|아크릴|쿠폰|응모|증정품` (파파존스 쿠키런 건)
- 주류: `소주|맥주|와인|막걸리|위스키|하이볼|750ml.*(레드|화이트)|캔\(\d+입\)` →
  **제외하거나**, 남긴다면 별도 "주류" 탭으로 빼고 기본 탭에서 감춘다. 나는 제외를 권한다.
  음식 신상 보러 온 사람이 와인 6입 캔을 볼 이유가 없다.

**우선순위** P0. 규칙 몇 줄이면 되고 효과는 크다.

### P0-5. "최근 21일" 문구와 실제를 일치시키기

**왜** 21%가 21일 밖이다(S4). 숫자를 쓸 거면 맞아야 한다.

**어떻게** 둘 중 하나. (a) 진짜로 21일로 자른다 → 300장이 237장이 되고 스크롤도 20% 준다.
(b) 문구를 데이터에서 계산해 쓴다 → `최근 12주 신제품 302건` 처럼. **(a)를 권한다.**
"매일 오는 신상 사이트"인데 7월 물량이 끝에 붙어 있을 이유가 없다. 7월 것은 `/b/` 브랜드
페이지에 남겨두면 된다(거긴 "최근 등록분"이라고 정직하게 써 있다).

같은 맥락에서 S5(302 vs 300)도 **카운트를 렌더된 카드에서 세도록** 고쳐야 한다.
지금은 필터 전 목록에서 세고 렌더는 필터 후를 한다.

### P1-1. "마지막으로 본 뒤 새로 올라온 N건" — 재방문의 핵심

**왜** 이게 없으면 매일 올 이유가 없다. 어제 100장을 봤는데 오늘도 같은 300장이 같은 순서로 있다.
어제 본 걸 어디까지 봤는지 알 수 없으니 매번 처음부터 훑어야 하고, 그래서 안 오게 된다.
**"당신이 마지막으로 온 뒤 새로 올라온 게 24건"** 이 딱 하나 있으면 매일 올 이유가 생긴다.

**어떻게** 완전히 브라우저 안에서 된다. 서버 필요 없음.
- 각 카드에 이미 `<time datetime>` 이 있다. 여기에 `data-seen` 용 날짜만 있으면 충분하다.
- `localStorage` 에 마지막 방문 시각을 저장. 페이지 로드 시 그보다 뒤인 카드에
  작은 점(●)을 붙이고, 헤더 문구를 `오늘 107건` → `마지막 방문 이후 24건` 으로 바꾼다.
  (첫 방문이면 지금처럼 `오늘 N건`)
- 헤더에 `새로 올라온 것만 보기` 토글 하나. 켜면 그 24건만 남긴다(기존 필터 로직 재사용).
- 페이지를 떠날 때 방문 시각 갱신. `localStorage` 가 막힌 환경(사생활 보호 창 등)에서는
  조용히 기존 동작으로 떨어지게 `try/catch`.

**우선순위** P1. 기획 과제 "재방문 이유"에 대한 내 답이 이것이다.
알림·구독·찜 중 무엇보다 이게 먼저다. 알림은 보낼 서버가 없고, 찜은 목록을 만들어도
다시 볼 이유가 약한데, 이건 **사용자가 이미 하러 온 일(오늘 뭐 나왔나)을 5초로 줄인다.**

### P1-2. 홈 `<head>` 복구 + PWA 홈 화면 추가

**왜** S12. 지금 카톡에 링크를 던지면 사진이 안 뜬다. 음식 사진이 주인공인 서비스에서
공유 카드에 사진이 없는 건 유입을 통째로 버리는 것이다. 그리고 홈 화면에 아이콘이 남는 것
자체가 강력한 재방문 장치인데, `manifest.webmanifest` 를 다 만들어 놓고 홈에서 안 부른다.

**어떻게** 빌드 타임. 다른 페이지 템플릿이 이미 갖고 있는 `<link>`·`og:*` 블록을
index.html 템플릿에도 넣는다. `og:image` 는 오늘 첫 카드 이미지로 하면 매일 바뀌어서
공유 카드가 항상 신선해 보인다. 피드 자동 발견(`rel=alternate`)도 같이 붙는다.

**우선순위** P1. 코드량 대비 효과가 이 목록에서 가장 크다.

### P1-3. 모바일 카드 높이 절반으로

**왜** S11. 첫 화면에 상품 이름이 0개다.

**어떻게** 순수 CSS·빌드 타임.
1. `.c img{height:auto}` 추가 → 164×400 이 164×164 가 된다. 이것만으로 카드가 586 → 약 350px.
2. 설명을 2줄로 클램프(`-webkit-line-clamp:2`). 지금 3~4줄까지 흐른다.
3. 헤더를 스크롤 시 접는다. 지금 `h1`+부제+리드가 130px 를 먹는데, 스크롤하면
   탭 줄(`nav`, 이미 `position:sticky`)만 남기면 된다.
4. 탭 줄 오른쪽 끝에 배경색 → 투명 그라데이션 12px. 옆으로 밀린다는 걸 알려주는 최소 표시.
   (지금 375px 에서 8개 중 4개만 보이고 힌트가 없다)

결과: 375px 첫 화면에 카드 2장의 **이름까지** 들어오고, 전체 스크롤이 95화면 → 약 55화면.

**우선순위** P1.

### P1-4. 변형 병합 규칙 확장

**왜** S10. "세트"는 걸렀는데 HOT/ICED·사이즈·조합이 남아서 약 60장(20%)이 같은 제품의 반복이다.
운영자가 지적한 몬스터 맥시멈 3장도 그대로다.

**어떻게** 빌드 타임에 "대표 1장 + 변형 N개" 로 접는다. 카드에는 대표만 띄우고
아래 회색 작은 글씨로 `HOT·ICED·디카페인 4종`. 상세 페이지에서 전체 변형을 나열.
병합 키 규칙(적용 순서대로, 브랜드 안에서만 비교):
1. 앞뒤의 `HOT`/`ICED`/`아이스`/`ICE`/`디카페인`/`(L)`/`(R)`/`(K)`/`(S)`/`IB` 제거
2. 끝의 `(콘)`/`(컵)`/`(박스)`/`(낱개)`/`(씬)`/`소프트` 제거
3. `반반`·`콤비`·`[A+B]`·`A/B 반반` 패턴은 **조합으로 보고 대표에 흡수**
4. 끝의 한 자리 숫자 제거 (`몬스터 맥시멈2` → `몬스터 맥시멈`)
5. 남은 문자열이 같으면 같은 제품. 대표는 그중 이름이 가장 짧은 것.

예상 효과: 300장 → 약 240장, 그중 반복이 사라진 만큼 정보 밀도가 올라간다.
빽다방 4장 → 1장, 교촌 10장 → 4장, 이디야 10장 → 5장, 폴바셋 6장 → 1장.

**우선순위** P1.

### P1-5. 카테고리 탭 재설계 → **§5 카테고리 전략** 참조

**왜** S6. `분식 1` 은 분류가 틀린 게 아니라 이름이 틀렸다. 실제로는 "이삭토스트"다.
그리고 지금 구조(브랜드 1개 = 카테고리 1개)는 브랜드가 늘면 탭이 따라 늘어나서 확장이 안 된다.

이 항목은 처음에 "탭 이름을 업종 이름으로 바꾸자"(7개 유지)로 썼다가,
**칩 폭을 실측한 뒤 결론을 바꿨다.** 375px 에서는 탭이 몇 개든 4개만 보이고,
계획된 13~15탭은 데스크톱 최대폭(1,120px)에서도 안 들어간다.

**결론: 탭을 8개 → 4개(`전체 / 편의점 / 카페 / 외식`)로 줄인다.**
근거·실측값·이행 순서는 전부 **§5-1 ~ §5-2** 에 있다. 여기서는 중복해 쓰지 않는다.

**우선순위** P1. (§6 정리표 10번)

### P1-6. Atom 피드 타임스탬프 고치고 홈에서 링크

**왜** S13. 지금 구독하면 매일 50건이 새 글로 다시 뜬다. 고치기 전에 링크를 노출하면
오히려 해롭다. 고치면 **서버 없이 쓸 수 있는 유일한 진짜 구독 채널**이다.

**어떻게**
- 각 `<entry>` 의 `<updated>` 를 그 상품의 날짜(`released_at`/`uploaded_at`/`first_seen`)로.
  피드 자체 `<updated>` 만 빌드 시각.
- `<id>` 는 이미 고유하니 그대로.
- 홈 `<head>` 에 `rel=alternate` (P1-2에 포함) + 푸터에 작은 `RSS` 링크.

**우선순위** P1. P1-2 와 같이 하면 추가 비용이 거의 없다.

### P2-1. 주간 묶음 페이지 `/w/2026-W40/`

**왜** "이번 주 신상" 은 카톡방에 던지기 좋은 단위다. 하루치는 너무 잘고, 전체는 너무 크다.
그리고 홈에 없는 "다시 볼 이유"를 만든다 — 지난주 걸 다시 보러 올 수 있다.

**어떻게** 빌드 타임. `/b/`·`/c/` 페이지 생성기를 그대로 재사용해서 ISO 주 단위로 묶고,
각 주 페이지에 `이전 주 / 다음 주` 링크. 홈 푸터에 최근 4주 링크. og:image 포함.
사이트맵에도 추가. 정적 파일이니 비용 0.

**우선순위** P2. P0·P1 이 끝난 뒤.

### P2-2. 날짜 구분선 + 같은 브랜드 연속 접기

**왜** 커피빈 28장 연속이 화면 7개다. 최신순 자체는 옳은데 같은 브랜드가 통으로 몰려서
"피드"가 아니라 "메뉴판"으로 보인다.

**어떻게** 빌드 타임에 카드 사이에 날짜 헤더(`9월 30일 · 107건`)를 넣고,
같은 브랜드가 6장 이상 연속이면 5장만 두고 `커피빈 23개 더 보기 →` 로 `/b/커피빈/` 에 링크.
이건 스크롤을 줄이는 동시에 **홈 → 브랜드 페이지 내부 링크를 만들어 준다**(S1 해소에도 기여).
필터가 켜져 있을 때는 접지 않는다(필터 결과는 원래 적다).

**우선순위** P2.

### P2-3. 찜 (localStorage)

**왜** "이거 주말에 사러 가야지" 를 담아둘 곳이 없다.

**어떻게** 카드 우상단 하트, `localStorage` 배열, 탭 줄에 `찜 N` 칩 추가(기존 필터와 동일 구조).
기기 간 동기화는 불가능하니 **처음부터 "이 브라우저에만 저장됩니다" 라고 써 둔다.**
말 안 하고 있다가 기기 바꿔서 날아가면 그게 더 큰 배신이다.

**우선순위** P2. P1-1(마지막 방문 이후)이 먼저다. 둘 다 localStorage 를 쓰지만
재방문을 만드는 힘은 P1-1 이 훨씬 세다.

### P3-1. 세트 잔여 페이지 35장 정리

**왜** S14. "몬스터 맥시멈 라지세트 — 신제품" 페이지가 아직 200 으로 살아 있다.

**어떻게** 빌드 스크립트에 `docs/p/` 안에서 이번 빌드가 만들지 않은 디렉터리를 지우는 단계를 넣는다.

다음 주에 삭제하는 쪽이 안전하다(지금 404 페이지가 잘 만들어져 있어서 최종 삭제해도 무해하다).

## 4. 하지 말아야 할 것

**Web Push 알림.** 해볼 만해 보이지만 정적 사이트에서 **불가능하다.** 푸시는 누군가
서버에서 VAPID 키로 발송 요청을 보내야 한다. 서비스 워커만으로는 스스로 못 보낸다.
"브라우저가 열려 있을 때만 뜨는 로컬 알림"은 알림의 의미가 없다.
재방문은 P1-1(마지막 방문 이후 N건) + P1-2(홈 화면 아이콘) + P1-6(RSS)으로 만든다.

**로그인·계정·서버 찜 동기화.** 비용 0 전제가 깨진다. 찜은 localStorage 로 하고
기기 간 동기화가 안 된다는 걸 처음부터 밝힌다.

**댓글·평점·좋아요.** 서버가 필요하고, 그걸 외부 위젯으로 우회해도 초기 트래픽에서는
"댓글 0" 이 300장 깔린다. 빈 상호작용 UI 는 서비스가 죽어 보이게 만든다.

**가격 표시.** 브랜드 사이트에 정가가 없거나 지점마다 다르다(특히 편의점·설빙).
틀린 가격 하나가 이 서비스가 지금까지 쌓은 신뢰를 전부 깎는다. 굳이 넣는다면
브랜드가 명시적으로 표기한 것만, 그것도 상세 페이지에서 "브랜드 표기 기준" 이라고 밝히고.

**AI 요약·추천·"당신을 위한 신상".** 300건 규모에서 추천이 할 일이 없고,
추천이 틀리면 "이 사이트 뭘 보여주는 거지" 가 된다. 지금 필요한 건 똑똑함이 아니라
**정확함**이다.

**무한 스크롤·가상 스크롤.** 300장이 전부 이미 HTML 안에 있고 이미지는 `loading="lazy"` 다.
느려서 문제가 아니라 **양이 많고 반복이 많아서** 문제다. P1-4(변형 병합)·P0-5(21일 컷)·
P2-2(브랜드 접기)로 양을 줄이는 게 맞지, 로딩 방식을 바꾸는 게 아니다.

**브랜드 이미지 자체 호스팅.** 지금 푸터의 "상품 정보와 이미지의 저작권은 각 브랜드에 있습니다"
와 정면으로 충돌한다. 핫링크 상태를 유지하고, 깨진 이미지는 회색 자리표시자로 처리한다.

**전체 카탈로그 다시 노출.** 데이터에 4,390건이 있고 화면에 300건이 있다. 그 차이는 버그가 아니라
"그날 신규만" 이라는 이 서비스의 정의다. 건수가 적어 보인다고 되돌리면 이 서비스가
겪은 문제를 처음부터 다시 겪는다.

**브랜드가 늘 때마다 탭 추가.** 지금 구조가 그렇게 돼 있어서 자연스러워 보이지만,
15탭이면 줄 전체가 1,298px 라 **데스크톱 최대폭(1,120px)에서도 안 들어간다.**
브랜드가 늘어날 자리는 탭이 아니라 브랜드 목록이다(§5-1, §5-2).

**공정위 등록 브랜드 수로 카테고리 고르기.** 한식이 3,773개로 1위인데
업계 1위들의 최신 신메뉴가 2022~2024년이다(`CANDIDATES-MEAT.md`).
브랜드가 많다 ≠ 신제품이 많다. 판단 기준은 **신메뉴 주기** 하나다(§5-5 ④).

**상품명 키워드로 지금 음식 장르 나누기.** 직접 해봤는데 편의점 1,878건 중
**34%가 미분류**로 남고 오분류도 섞였다. 이름이 POS 코드라 그렇다(S7).
**P0-3 정규화가 끝나기 전에는 장르 분류를 시도하면 안 된다**(§5-7).

## 5. 카테고리 전략

운영자 질문: "과자랑 라면 섹션도 파자. 신제품 많이 잡히는 식음료 카테고리 또 뭐 있지?"

먼저 **거꾸로 물어야 한다**는 전제에 동의한다. 지금은 브랜드를 붙일 수 있는 대로 붙이고
그 결과로 탭이 생긴다. 그래서 `분식 1`(이삭토스트 하나) 같은 탭이 생겼다.
아래는 "신제품이 실제로 많이 나오는 곳"을 먼저 정하고 거기에 브랜드를 붙이는 순서로 썼다.

근거는 **우리가 이미 가진 것만** 썼다. 브랜드 사이트는 크롤하지 않았다.
① `data/products.json` 편의점 카탈로그 1,878건, ② 라이브 21일 피드 300장,
③ 기존 조사 문서(`CANDIDATES-*.md`, `FRANCHISE-MASTER.md`)의 실측 판정.

### 5-0. 지금 구조의 한계 — 탭이 브랜드를 따라 늘어난다

§2 S6 에서 확인한 대로 **브랜드 1개 = 카테고리 1개**로 고정돼 있다.
그래서 카테고리는 "음식 종류"가 아니라 **"브랜드 묶음의 다른 이름"**이다.

이 구조의 문제는 확장할 수 없다는 것이다. 브랜드가 24개 → 40개가 되면
탭도 8개 → 15개로 따라 늘어난다. 지금 계획된 13개 탭 중 상당수는
**브랜드 1~2개짜리 탭**이 될 것이 이미 조사 문서에 예고돼 있다.

| 계획된 탭 | 실제로 들어갈 브랜드 | 근거 |
|---|---|---|
| 일식 | 스시로 **1개** | `CANDIDATES-ASIAN.md` — 23곳 조사해 쓸 수 있는 게 스시로·에그드랍·샐러디 3곳뿐 |
| 샌드위치 | 에그드랍 **1개** | 〃 (써브웨이는 약관 제5.2조(b) 명시 금지) |
| 샐러드 | 샐러디 **1개** | 〃 |
| 분식 | 이삭토스트 **1개** | 현재 라이브 |
| 디저트 | 던킨 16 + 배스킨라빈스 1 = **2개** | 현재 라이브 |

**브랜드 하나짜리 탭을 5개 만드는 셈이다.** 사용자가 "일식"을 눌렀을 때 초밥집 한 곳만
나오면, 그건 분류가 아니라 브랜드 바로가기다. 그러면 탭이 아니라 브랜드 목록이어야 한다.

### 5-1. 탭은 더 늘릴 수 없다 — 실측값

라이브 사이트에서 칩 폭을 직접 재고, 계획된 라벨로 칩을 복제해 재봤다
(칩 간격 6px, `nav` 좌우 패딩 32px, 폰트·패딩은 현재 CSS 그대로).

| 칩 하나의 폭 | |
|---|---|
| 전체 302 / 편의점 84 / 카페 108 | 82 / 87 / 80 px |
| 햄버거 30 / 피자 31 / 치킨 31 / 디저트 17 / 분식 1 | 86 / 72 / 72 / 84 / 65 px |
| 베이커리 / 샌드위치 / 샐러드 / 도시락 / 과자 / 라면 | 98 / 91 / 79 / 79 / 74 / 73 px |

| 탭 개수 | 줄 전체 폭 | 375px 뷰포트 대비 | 화면에 보이는 개수 |
|---|---:|---|---:|
| **현재 8개** | **702px** | 1.9배 | **4개** |
| **계획 13개** | **1,139px** | 3.0배 | **4개** |
| **13 + 과자·라면 = 15개** | **1,298px** | **3.5배** | **4개** |
| 16개 (+1) | 1,383px | 3.7배 | 4개 |

읽어야 할 숫자는 두 개다.

1. **375px 에서는 탭이 몇 개든 4개만 보인다.** 칩 폭이 65~98px 이라 물리적으로 그 이상 안 들어간다.
   15개로 늘리면 **11개가 화면 밖**이고, 마지막 탭(라면)은 첫 화면에서 **923px 오른쪽**에 있다.
   엄지 스와이프 한 번이 250~300px 정도니 **3~4번 밀어야 닿는다.**
2. **데스크톱에서도 안 들어간다.** 본문 최대폭이 `max-width:1120px` 인데 15탭이 1,298px 다.
   즉 **어떤 화면에서도 전체 탭을 한눈에 볼 수 없게 된다.**

여기에 §2 에서 확인한 것 하나가 더 붙는다 — 지금 `nav` 는
`overflow-x:auto` + `scrollbar-width:none` + `nav::-webkit-scrollbar{display:none}` 이라
**옆으로 밀린다는 표시가 아예 없다.** 지금도 8개 중 4개가 숨어 있는데 사용자는 모른다.

**결론: 과자·라면을 탭으로 추가하면 안 된다. 오히려 탭을 줄여야 한다.**

### 5-2. 탭을 4개로 줄인다 — "어디서 사느냐"만 남긴다

지금 탭 하나가 두 가지 질문에 동시에 답하려다 실패하고 있다.

- `편의점`·`카페` → **어디서 사느냐**(업태)
- `햄버거`·`피자`·`치킨`·`디저트`·`분식` → **뭘 먹느냐**(음식 종류)

그런데 구현은 전부 전자다. 그래서 버거킹 `카페라떼`가 햄버거 탭에 있다(S6).
**둘 중 하나만 고른다면 "어디서"가 맞다.** 사용자가 신상을 찾는 맥락이
"편의점 갈 건데 뭐 새로 나왔나" / "카페 갈 건데" 이기 때문이고,
무엇보다 **지금 데이터로 "뭘 먹느냐"를 만들 수 없다**(5-7 참고).

제안하는 탭:

| 탭 | 들어가는 것 | 현재 건수 |
|---|---|---:|
| **전체** | | 302 |
| **편의점** | CU · 세븐일레븐 · 이마트24 **＋ 과자·라면 등 제조사** | 84 → (제조사 합류 시 증가) |
| **카페** | 스타벅스 · 커피빈 · 폴바셋 · 이디야 · 빽다방 · 메가 · 설빙 | 108 |
| **외식** | 버거·피자·치킨·도넛·토스트 — 매장에서 먹는 프랜차이즈 전부 | 110 |

칩 폭 실측으로 이 조합이 들어가는지 확인했다.

| 조합 | 줄 전체 폭 | 375px |
|---|---:|---|
| 4탭 + 건수 배지 (`전체 302 / 편의점 84 / 카페 108 / 외식 110`) | **376px** | 1px 초과 — 아슬아슬 |
| 4탭, 건수 배지 없음 | **299px** | 여유 있게 들어감 |
| 5탭 + 건수 (`+ 제조사`) | 469px | 안 들어감 |

**칩 좌우 패딩을 14px → 10px 로 줄이면 4탭 + 건수가 약 345px 가 되어 들어간다.**
건수 배지는 유지하는 게 좋다(어느 탭에 뭐가 있는지 알려주는 유일한 신호다).
탭을 5개로 만드는 순간 다시 가로 스크롤이 생기니 **4개가 상한이다.**

브랜드별로 보고 싶은 사람을 위해서는 탭이 아니라 **브랜드 목록**을 따로 둔다.
`/b/` 페이지가 24장 이미 있으니(§2 S1 — 지금 홈에서 링크가 없다) 푸터나
"브랜드 전체 보기" 링크 하나만 만들면 된다. 브랜드가 40개가 돼도 이 구조는 안 무너진다.

### 5-3. 과자·라면을 어디에 둘 것인가

**둘 값어치는 있다. 다만 별도 탭이 아니라 편의점 탭 안이다.**

**값어치가 있다는 근거** — 우리 데이터가 이미 증명하고 있다.

| 측정 | 값 |
|---|---|
| 편의점 카탈로그 1,878건 중 제과·라면 8사(오리온·해태·롯데·크라운·농심·오뚜기·삼양·팔도) 제품 | **292건 (15.5%)** |
| 라이브 21일 피드 편의점 84장 중 제과·라면 신제품 | **11장** |

편의점 진열의 약 1/6이 이 카테고리이고, 편의점 어댑터가 **부수적으로** 잡은 것만으로도
21일에 11건이 나온다. 제조사를 직접 붙이면 더 는다.
`CANDIDATES-MEAT.md` 가 판정한 족발·보쌈(신메뉴 주기 **연 1건 미만 ~ 2~4년**)과 정반대다.

라이브 피드에 실제로 잡힌 11건:

> 농심 `신라면 툼바` · `신라면 더레드` · `신라면 골드` · `포테토칩 버터갈릭새우맛` /
> 오뚜기 `뿌셔뿌셔 불고기맛` · `뿌셔뿌셔 바베큐맛` · `뿌셔뿌셔 팝콘양념치킨맛` ·
> `열라면 프레첼` · `콕콕콕 참깨란볶이` / 삼양 `삼양라면 1963` · `우지짜르르`

**별도 탭이 아닌 이유** — 5-1 의 폭 계산이 전부다. 그리고 사용자 입장에서
`신라면 툼바`가 세븐일레븐에서 왔는지 농심에서 왔는지는 **상관이 없다.**
어차피 편의점에서 산다. `편의점` 탭은 "사서 집에서 먹는 포장식품" 이라는
하나의 맥락이고 과자·라면은 정확히 거기 속한다.

굳이 구분하고 싶다면 탭이 아니라 **카드의 회색 보조 라벨**로 한다
(`농심` / `세븐일레븐 단독` 처럼). 라벨은 폭을 안 먹는다.

### 5-4. 편의점과 제조사가 겹치는 문제

제조사 어댑터를 붙이면 **같은 상품이 두 장**이 된다. 이건 가정이 아니라 지금 데이터로 확정된다.

세븐일레븐 `농심)신라면툼바봉지` ↔ 농심 어댑터가 가져올 `신라면 툼바` — 같은 라면이다.
위 11장 전부가 이렇게 된다.

**① 화면 원칙: 제조사가 대표, 편의점은 판매처.**

같은 상품이면 제조사 레코드를 카드로 쓰고, 편의점 레코드는 카드 아래
`CU · 세븐일레븐에서 판매중` 한 줄로 흡수한다. 이유:

- 제조사 쪽 이름이 깨끗하다. `신라면 툼바` vs `농심)신라면툼바봉지`
- 제조사 쪽 설명·이미지가 낫다(편의점 POS 는 설명이 없는 경우가 많다)
- **판매처 정보는 중복이 아니라 추가 정보다.** "어디 가면 살 수 있나"는
  사용자가 실제로 궁금해하는 것이고, 지금 카드에 없는 정보다

**② 매칭 키는 `제조사 + 정규화 상품명`.** 그런데 **P0-3(상품명 정규화)이 선행 조건**이다.
지금 상태로는 문자열이 안 맞는다.

```
세븐일레븐:  농심)신라면툼바봉지
농심:        신라면 툼바
정규화 후:   농심 + 신라면툼바      ← 접두·공백·용기(봉지/컵/입)·용량 제거 후 비교
```

**③ 접두만으로는 제조사를 특정할 수 없는 구간이 있다.** `롯데)` 94건이 그렇다.

```
롯데)꼬깔콘고소한맛134g       → 롯데웰푸드 (과자)
롯데)가나초코바아몬드43g       → 롯데웰푸드 (과자)
롯데)클라우드468ml캔(6입)      → 롯데칠성 (맥주)
롯데)옐로우테일오로라팩(까버)   → 롯데칠성 수입 (와인)
롯데)의성마늘통살구이닭갈비(간) → 롯데웰푸드 (육가공)
```

한 접두에 **최소 세 법인**이 섞여 있다. 롯데는 제품 장르까지 봐야 매칭이 된다.
매칭 실패하면 **억지로 합치지 말고 둘 다 남긴다.** 정규화 후 이름이 같은데 못 합친 건
화면에서 "같은 이름 카드 2장"으로 즉시 보이니, 이걸 **QA 신호로 쓰면 된다.**

**④ 제조사 어댑터가 절대 못 잡는 것이 있다 — 편의점 PB.**
접두 빈도 상위에 제조사가 아닌 것들이 대거 올라와 있다.

| PB 접두 | 소속 | 건수 |
|---|---|---:|
| `옐로우` / `성수310` / `포차24` | 이마트24 | 66 / 53 / 30 |
| `All New` / `그린` | 세븐일레븐 | 42 / 21 |
| `PBICK` / `데일리` / `405` | CU | 22 / 17 / 18 |
| **합계** | | **269건** |

거기에 CU 의 신선식품 접두(`도)`·`김)`·`샌)`·`햄)`·`면)`·`삼)`·`핫)`·`샐)`·`빅삼)`)까지 더하면
**편의점 어댑터만의 고유 자산이 상당하다.** 제조사를 붙여도 편의점 어댑터는 그대로 가야 한다.
그리고 PB(가성비·이색 제품)는 관심도가 높은 장르이니 **`PB` 라벨을 따로 붙여 주는 게 좋다.**

### 5-5. 다음에 붙일 카테고리 — 우리 데이터가 가리키는 순서

(동서) `TOP 바닐라라떼`. **제로 음료 경쟁 때문에 신제품 주기가 짧다.**

→ **롯데칠성 · 동서식품 · 광동제약을 "음료(RTD)" 라운드로 묶어 조사할 것을 제안한다.**

**③ 프랜차이즈 쪽에서 아직 안 붙었는데 값어치 있는 곳은 사실상 베이커리 하나다.**
이건 이미 실측돼 있다 (`CANDIDATES-BAKERY.md`).

| 브랜드 | 신호 | 상태 |
|---|---|---|
| **파리바게뜨** | WP REST API `date` 필드, 535건 | ✅ **이 조사의 최대 수확.** 붙이는 날부터 `released_at` 이 찬다 |
| 요거프레소 | 신메뉴 전용 페이지 + 출시 연월 라벨 | ✅ 단 월 단위 |
| 명랑핫도그 | NEW 전용 카테고리 | ✅ |
| 뚜레쥬르 | — | 🔴 robots `Disallow: /` — **붙이면 안 됨** |
| 크리스피크림 | — | 🔴 인증서 만료 + 전 경로 403 |

**반대로 프랜차이즈 아이스크림은 값어치가 없다.** 공정위 `K1 아이스크림/빙수`
등록 브랜드가 **71개로 16개 업종 중 최소**이고, 하겐다즈는 한국 메뉴 페이지가 없고,
나뚜루는 도메인이 없고, 이미 붙어 있는 **배스킨라빈스는 21일 동안 1건**이다.
빙과는 프랜차이즈가 아니라 **제조사(빙그레·롯데웰푸드·해태아이스) 쪽에서** 봐야 한다.
다만 지금이 9월이라 빙과 비수기다 — **여름에 다시 재보는 게 맞고, 지금 판단하면 틀린다.**

**④ 공정위 등록 브랜드 수는 카테고리 근거로 쓰면 안 된다.**
한식이 3,773개로 압도적 1위인데, `CANDIDATES-KOREAN.md`·`CANDIDATES-MEAT.md` 실측 결과
**업계 1위들의 최신 신메뉴가 2022~2024년**이었다(원할머니 족발 2022-01, 한촌설렁탕 2024).
브랜드 수와 신제품 빈도는 상관이 없다. 판단 기준은 **신메뉴 주기 하나**다.

### 5-7. "음식 종류" 탭은 언제 만들 수 있나 — 지금은 못 만든다

탭을 "무엇을 먹느냐"로 바꾸고 싶어도 **지금 데이터로는 불가능하다.**
직접 해봤다. 편의점 1,878건을 상품명 키워드로 10개 장르로 나눠 봤더니
**34%가 미분류**로 남았고, 분류된 것도 오분류가 눈에 띄었다
(`카스테라40g(초코)` → 주류, `햇반버터장조림비빔밥` → 유제품, `고소바삭쌀과자100g(S)` → 라면).
**그래서 그 비율은 이 문서에 싣지 않았다.** 믿을 수 없는 숫자다.

원인은 하나다 — **상품명이 POS 코드라서 분류가 안 된다**(S7).
`샐)닭가슴살&단호박샐2` 에서 "샐러드"를 뽑을 방법이 없다.

그러니 순서는 이렇다.

1. **P0-3 상품명 정규화** — 접두·용량·리비전 숫자 제거
2. 그 과정에서 **CU 접두를 버리지 말고 장르 라벨로 승격**시킨다.
   `도)`=도시락 `김)`=김밥 `샌)`=샌드위치 `면)`=면 `삼)`=삼각김밥 `핫)`=핫도그 `샐)`=샐러드 `빅삼)`=빅삼각.
   **이건 우리 추측이 아니라 CU 가 자기 상품에 붙인 분류다.** 공짜로 얻는 정답지다.
   현재 라이브 84장 중 `도` 13 · `샌` 7 · `햄` 5 · `김` 4 · `면` 3 · `빅삼` 3 · `삼` 2 · `샐` 1 · `핫` 1 = **39장**이 이미 이 라벨을 달고 있다.
3. 카페·프랜차이즈 쪽은 이름 패턴이 깨끗하니 키워드로 잡힌다
   (`라떼|아메리카노|티|블렌디드` → 음료, `케이크|쿠키|도넛|베이글|빵` → 디저트 …)
4. 그때 가서 **탭은 4개 그대로 두고, 그 아래 2차 필터**로 음식 종류를 붙인다.
   탭을 다시 늘리는 게 아니다. 5-1 의 폭 제약은 그때도 그대로다.

### 6-4. Q1 — 냉동식품은 **별도 카테고리로 만들지 않는다.** `간편식` 에 흡수한다

먼저 정직하게 적는다. **냉동식품의 신메뉴 회전 주기를 나는 측정하지 못했다.**
족발·보쌈을 잘라낼 때는 직접 관측값이 있었다(원할머니 상품 이미지 최신 타임스탬프 2022-01,
한촌설렁탕 신메뉴 페이지가 2024 에서 멈춤). 냉동식품에는 그런 값이 없다.
`CANDIDATES-DIRECT.md` 가 본 냉동 3사가 **셋 다 날짜를 못 봤다** —
CJ제일제당 robots 전면 차단, 풀무원 뉴스룸 JS 로드로 "확인 못 함", 동원F&B 상세 날짜 "확인 못 함".
**그러니 회전 주기를 근거로 판정하지 않는다.**

대신 측정된 것 둘로 판정한다.

**① 붙일 소스가 없다.** 냉동식품 상위 3사가 전부 수집 불가 또는 미확인이다.
카테고리를 먼저 만들면 **빈 탭**이 된다. `분식 1건` 과 똑같은 실수를 반복하는 것이다.

**② 보관온도는 우리 데이터에 없다.** 편의점 1,878건 실측:

| 이름에 포함 | 건수 |
|---|---:|
| `냉동` | **1건** (`옐로우)냉동대패목심500g`) |
| `냉장` | 16건 (전부 `(냉장)` 접미 — 허쉬·트윅스·키세스 초콜릿류) |

그런데 **제품군 자체는 이름으로 멀쩡히 잡힌다.**

| 키워드 | 건수 | 예 |
|---|---:|---|
| 햇반 | 42 | `CJ)햇반작은공기130g` |
| 비비고 | 26 | `CJ)비비고삼계탕800g` |

**즉 "무엇인가"는 데이터에 있고 "몇 도에서 보관하나"는 없다.**
없는 축으로 탭을 만들 수는 없다.

**③ 그리고 소비자는 그 축으로 안 나눈다.** 비비고 만두(냉동)·햇반컵반(상온)·CU 도시락(냉장)은
사용자에게 전부 "데워 먹는 밥"이다. 냉동/냉장/상온은 **제조사와 물류의 분류이지 먹는 사람의 분류가 아니다.**

- 2단 세부는 **`간편식`** 하나. 냉동·냉장·상온을 가르지 않는다.
- 구분이 필요하면 탭이 아니라 **카드의 회색 보조 라벨**(`냉동`)로. 단 지금은 데이터에 없으니
  제조사 어댑터가 붙은 뒤에나 가능하다.

> **판단 보류.** 냉동식품 3사의 신메뉴 주기는 **측정되지 않았다.**
> 풀무원 뉴스룸 JS 번들이나 동원F&B SSR 상세가 뚫려 날짜가 나오면 그때 잰다.
> 그 전에 카테고리를 만들면 근거 없이 만드는 것이다.

### 6-5. Q2 — 과자·라면은 **2단에 넣는다.** §5-3 결론을 바꾼다

§5-3 에서 "별도 탭 말고 편의점 안에"라고 쓴 건 **1단만 있던 때**의 판단이었다.
2단이 생겼으니 근거가 바뀐다.

| | 그때 (§5-3) | 지금 |
|---|---|---|
| 구조 | 1단 하나. 탭 추가 = 1단에 추가 | 1단 4개 고정 + 대분류별 2단 |
| 폭 제약 | 15탭 = 1,298px, 데스크톱에서도 초과 | **편의점 2단 4칩 = 357px, 375px 에 들어감** |
| 결론 | 탭 만들지 마라 | **`편의점 > 과자 / 라면` 으로 만들어라** |

**구체안**

```
1단:  전체 | 편의점 | 카페 | 외식
2단(편의점 선택 시):  과자 | 라면 | 음료 | 간편식      ← 4칩, 357px, 375px 에 다 보임
```

- **4칩 상한을 지킨다.** 5칩(냉동식품 추가)은 455px 로 1개가 화면 밖이다. 냉동식품은 6-4 대로 `간편식` 에 흡수.
- 제조사(오뚜기·오리온·롯데웰푸드·팔도)는 **1단 `편의점` 안**에 들어간다. 별도 대분류를 만들지 않는다.
  사용자에게 `신라면 툼바` 는 어디서 왔든 "편의점에서 사는 것"이다. 1단을 5개로 늘리면 §5-2 의 폭 계산이 깨진다.
- 제조사명은 탭이 아니라 **카드 보조 라벨**(`농심`)로.

**⚠️ 순서 조건 — 콘텐츠가 먼저다.**
지금 편의점 탭은 **2건**이다. 이 상태에서 2단 4칩을 만들면 네 칩이 전부 0~1건이 된다.
`분식 1` 로 이미 한 번 겪은 실수다. 순서는 이렇다.

1. 6-3 (a)(b) — `first_seen` 채택 + 브랜드 상한 → 편의점이 수십~수백 건으로 돌아옴
2. 과자·라면 제조사 어댑터 합류
3. 그 결과 각 세부가 **10건 이상**이 되는 것을 확인
4. **그다음에** 2단 칩을 켠다

### 6-6. Q3 — 제조사 ↔ 편의점 중복, 선행 순서

`CANDIDATES-DIRECT.md` §2 가 `make_key` 로 안 걸러진다는 걸 실측했다
(`이마트24:롯데)허쉬쿠키앤크림40g(냉장)` vs `롯데웰푸드:허쉬쿠키앤크림`).
그 결론에 동의하고, 화면 쪽에서 필요한 순서를 붙인다.

| 순서 | 할 일 | 왜 이 순서인가 |
|---:|---|---|
| **1** | **편의점을 화면에 되살린다** (6-3 (a)(b)) | 지금 편의점이 2건이다. **합칠 대상이 화면에 없으면 중복 문제 자체가 없다.** 병합 로직을 먼저 짜면 검증할 데이터가 없다 |
| **2** | **상품명 정규화** (§3 P0-3) | 제조사 접두 `롯데)`, 용량 `40g`, 보관 `(냉장)`, POS 리비전 `정식1` 제거. 이게 없으면 어떤 키도 안 맞는다 |
| **3** | **코어 키를 따로 만든다** — `make_key` 를 고치지 않는다 | `make_key` 는 **브랜드명이 들어가야** 정상이다(같은 이름 다른 브랜드 상품이 합쳐지면 안 됨). 병합용 키는 **브랜드를 뺀** 별도 키여야 한다: `정규화상품명` 단독, 또는 `제조사+정규화상품명` |
| **4** | **제조사는 브랜드가 아니라 날짜 보강 소스로** | `CANDIDATES-DIRECT.md` §2③ 결론을 지지한다. 편의점은 상품 축이 정확하고 날짜가 없다. 보도자료는 날짜가 정확하고 상품 축이 거칠다("2종", "시리즈"). **날짜만 가져오면 중복이 아예 안 생긴다.** 이게 가장 싸다 |
| **5** | **예외: 팔도만 브랜드로 붙인다** | `/product/noodle` 이 카탈로그 SSR 에 `신제품` 배지 12/75. 보도자료가 아니라 카탈로그라 상품 축이 1:1 이다. `is_new` 만 채우고 `released_at` 은 비운다 |
| **6** | **매칭 실패를 QA 신호로 쓴다** | 정규화 후 이름이 같은데 못 합친 건 화면에 "같은 이름 카드 2장"으로 보인다. 숨기지 말고 그대로 두고 주기적으로 센다 |
| **7** | 그다음에 2단 `과자`·`라면` 칩을 켠다 | 6-5 |

**화면 규칙(4번을 쓰는 경우)** — 카드는 편의점 것 하나만 남고, 날짜 문구가 바뀐다.
`9월 30일 처음 확인` → `9월 28일 출시`. 사용자에게 보이는 변화는 이것뿐이고, 그게 정확히 우리가 원한 것이다.

**주의 하나** — 보도자료를 날짜로 쓸 때, `CANDIDATES-DIRECT.md` 가 찾은 함정이 실제 문제다.
`꼬깔콘 야장시리즈 출시 보름만 80만 봉 판매 돌파` 같은 **실적 기사가 "출시"를 포함한다.**
이걸 쓰면 출시일이 보름 밀린다. `출시|선봬|론칭` 정방향 필터에 더해
`돌파|판매|만에|누적|기록` 역필터가 필요하다.

정적 사이트 제약 안에서 가능하고, 지금 정책을 실제로 지킬 수 있게 만든다. **우선순위 P0.**

**② og:image 가 브랜드 하나의 이미지다.**

- **우리 서비스를 공유했는데 할리스 광고처럼 보인다.** 카톡·슬랙 썸네일이 그 브랜드 단독 이미지다.

브랜드 단독 노출이 아니고, 우리 도메인에 있어서 안 깨진다. **우선순위 P1.**

| 편의점 | **54** | CU 52 · 세븐일레븐 2 |
| 외식 | 2 | 스타벅스 2 (→ 7-2 대로 오탐이니 실제 0) |

2단은 **대분류에 종속된 줄**이다. 카페 2단에만 넣으면 CU 54건이 갈 곳이 없고,
양쪽에 다 넣으면 같은 이름의 칩이 두 군데 생겨 "굿즈를 눌렀는데 결과가 다르다"가 된다.
게다가 외식 2단은 이미 **9칩 / 734px / 4-of-9**(7-0 실측)로 한계를 넘었다.
카페 2단이 비어 있는 건 사실이지만, **그 자리는 `음료`·`디저트` 가 들어갈 자리**다(§6-2).

**② 메인 피드에서 빼는 것은 맞다 — 할리스 74건의 정체**

할리스 74건을 보면 **대부분 색상 변형**이다.

> `더 가벼운 텀블러` — 그라데이션핑크 · 그라데이션블루 · 퍼플 · 브라운 · 네이비 · 카키 ·
> 연핑크 · 연블루 · 연보라 · 레드 · 크림 = **11장**
> `슬릿캡 실리콘 텀블러` 3색 · `올데이 텀블러` 3색 · `퓨어 세라믹 텀블러` 3종 ·
> `드라이빙 텀블러` 3색 · `원터치 트라이탄 텀블러` 2색 · `블루밍 텀블러` 2색 …

이걸 섞으면 한 브랜드의 텀블러 색상이 피드를 덮는다.
운영자가 이미 겪은 **"지금 이마트만 있는데?"** 와 같은 사고다.
**§3 P1-4(변형 병합)를 굿즈에 먼저 적용하면 74 → 20건대로 준다.** 굿즈 페이지를 만들 때 같이 한다.

**③ 버리기는 아깝다 — 그래서 페이지는 만든다**

매머드 `몰티즈 인형 키링`, 메가 `캐치!티니핑 하츄핑 랜덤 피규어`, 할리스 `요정 춘식` 시리즈,
메가 `RIIZE 라브돔 텀블러세트` 는 검색 수요가 있는 품목이다.
**정적 사이트에서 `/c/굿즈/` 한 장은 비용이 0 이다** — `/c/` 생성기가 이미 있고 5장 만들고 있다.
사이트맵·og:image·JSON-LD 도 그대로 따라온다.

**④ 순서**

1. `/c/굿즈/` 생성 + 푸터에 링크 한 줄
2. 변형 병합을 굿즈에 적용 (74 → 20건대)
3. 트래픽이 붙으면 그때 1단 노출을 판단한다.
   **1단은 4개가 상한**(§5-2)이므로 굿즈를 1단에 올리려면 무언가를 빼야 한다.
   지금 데이터로는 그럴 근거가 없다. **먼저 만들고, 재보고, 그다음에 정한다.**

### 7-10. Q2 — 신제품의 범위를 "먹는 것"으로 좁힐 것인가

**좁히는 게 맞다. 그리고 그 사실을 화면에 적어야 한다.**

**좁히는 근거**
- 사이트 제목이 `편의점·카페·프랜차이즈 신제품 모아보기`, 설명이
  `편의점·카페·햄버거·피자·치킨 신제품을 매일 자동으로 모읍니다` 다.
  **이미 음식 카테고리만 나열하고 있다.** 비식품을 넣으면 제목이 거짓말이 된다.
- 사용자가 오는 맥락은 "오늘 뭐 새로 나왔지" = **"뭐 먹지"** 다.
  그 목록에 `플레이보이)극초박콘돔3P` · `비비안)26압박스타킹80D` · `템포)탐폰라이트10P` 가
  섞이면 신뢰가 깎인다. 1차 검수 S8 에서 지적한 그대로다.
- **편의점이 비식품을 파는 건 편의점의 사정이지 우리의 범위가 아니다.**
  우리는 편의점 카탈로그를 옮기는 게 아니라 "신제품 중에서 먹는 것"을 고른다.
  이 구분은 이 서비스가 처음부터 겪은 문제("기존 상품 올라온 건 필요 없어")와 같은 종류다.

**다만 반드시 명시해야 한다.** 지금은 167건이 **조용히** 빠진다. 사용자가 CU 신상 목록과
대조하면 "왜 이건 없지?" 가 되고, 그게 바로 신뢰가 깨지는 지점이다.

> 푸터 한 줄 제안: **`먹는 것만 모읍니다. 텀블러·굿즈는 [굿즈]에서 따로 봅니다.`**

이건 §6-8 ①(삭제 요청 창구)과 **같은 자리**에 들어간다. 푸터 두 줄로 둘 다 해결된다.
정적 사이트 제약 안에서 되고 비용이 0 이다.

**⚠️ 주류는 이 규칙으로 안 걸린다.** 술은 "먹는 것"이라 `is_nonfood` 를 통과한다.
1차 검수 S8 의 주류 제외(§3 P0-4)는 **여전히 별도로 필요하다.**
지금 라이브 편의점 2건 중 1건이 `롯데)옐로우테일오로라팩(까버)` = 와인이다.

### 7-11. 원칙 — 오탐이 미탐보다 훨씬 나쁘다

이 판정의 두 실패는 무게가 다르다.

| 실패 | 사용자가 보는 것 | 비용 |
|---|---|---|
| **미탐** — 굿즈가 피드에 남음 | "이건 음식이 아니네" 하고 넘긴다 | 카드 1장 손해. **보이는 실패** |
| **오탐** — 식품이 사라짐 | **아무것도 못 본다** | 신제품 사이트에서 신제품이 빠진다. **침묵하는 실패** |

스타벅스 핸디 젤리 2건이 지금 그 상태다. **사라진 걸 아무도 모른다.**
그래서 **단어를 좁게 잡는 지금 방침이 옳고**, 코디네이터가 `보틀`·`케이스` 를 뺀 판단을 지지한다.

**검증 루틴 제안 (정적 사이트에서 가능)**
빌드할 때 `nonfood=True` 로 **새로 바뀐** 항목만 목록으로 출력한다.
단어 목록을 건드린 날 그 목록을 한 번 훑는 것만으로 오탐이 잡힌다 —
**이번에 167건을 눈으로 훑어서 2건을 찾았다.** 사람이 훑을 분량이면 자동화보다 이게 싸다.
