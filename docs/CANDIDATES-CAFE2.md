## 2. 투썸플레이스 재시도 결과 (요청받은 별도 보고)

**결론: 뚫리긴 뚫렸다. 그런데 붙이면 안 된다.**

우회 시도는 지시받은 **2회를 다 썼고, 더 하지 않았다.**

**(0) 베이스라인 — 우리 UA (`sinsang-note/1.0`), 우회 아님**

```
GET https://www.twosome.co.kr/robots.txt
403  Server: CloudFront
<H1>403 ERROR</H1><H2>The request could not be satisfied.</H2>
Request blocked.
```

**(1) 우회 시도 1/2 — 브라우저 UA + Accept/Accept-Language 헤더** → **200 으로 뚫림**

```
User-agent: Yeti
User-agent: Daum
User-agent: Googlebot
allow: /

#DaumWebMasterTool:63461026460124b0038abe3c1574be6e8060d7bb3975732f50adf18828d3a8d6:…
```

**(2) 우회 시도 2/2 — 브라우저 UA 로 `/menu/menuList`** → 404 (경로가 틀렸다).
다만 응답이 **브랜드 404 페이지(JSP/Spring 서버렌더, `<title>투썸플레이스 │ TWOSOME PLACE…`)** 였다.
이 404 페이지에는 nav 가 없어서 **진짜 메뉴 경로는 끝내 못 찾았다.**

### 판단

robots.txt 자체는 우리를 막지 않는다. `Disallow` 가 **한 줄도 없고**,
`urllib.robotparser.can_fetch("sinsang-note/1.0", "/menu")` 도 **True** 다.
(`User-agent: *` 그룹이 아예 없어서 기본 허용으로 떨어진다. 빕스처럼 명시적으로 막는 것과는 다르다.)

막는 건 robots 가 아니라 **CloudFront WAF** 다. 그리고 그 WAF 가 하는 일이
robots.txt 에 적힌 것과 정확히 같다 — **Yeti·Daum·Googlebot 만 통과시키고 나머지는 전부 403.**
즉 사이트 운영자가 "알려진 검색봇만 받겠다"를 robots 와 WAF **두 겹으로** 일관되게 표현한 것이다.

우리가 통과하는 유일한 방법은 **브라우저 UA 위장**인데, 이건 `collectors/base.py` 의
UA 주석("브라우저를 위장하면 사이트 운영자가 우리를 식별하거나 연락하거나 선별 차단할 방법이 없다")과
`CRAWLING-POLICY.md` §5.3 에 정면으로 어긋난다. 롯데리아를 뺀 것과 같은 이유다.

→ **수집하지 않는다.** 붙이고 싶으면 투썸에 `sinsang-note/1.0` 허용을 문의하는 게 순서다.

## 3. 컴포즈커피 재시도 결과 (요청받은 별도 보고)

**결론: 뚫렸다. 1차 판정 '불가(JS 렌더)'는 오판이었다. 다만 신제품 신호가 없다.**

번들을 받을 필요도 없었다. **함정은 첫 페이지였다.**

`composecoffee.com/` 의 레이아웃 이름이 `opening` 이다. 스플래시 페이지고, 여기 본문이 없다.
본체는 홈에 링크된 **`/index1`** 이하다.

```
<meta name="generator" content="Rhymix">
href="https://composecoffee.com/index1"
```

`/index1` 에서 메뉴 링크가 그대로 나온다. Rhymix(XE 계열) 갤러리 모듈이다.

```
/index.php?mid=compose&act=dispCafemenuGalleryList
/index.php?mid=compose&act=dispCafemenuGalleryList&category_srl=303364
```

카테고리 9개 — 추천메뉴(301298) · 커피ㆍ콜드브루(303364) · 베버리지(303365) ·
프라페ㆍ스무디(303366) · 밀크쉐이크(303367) · 에이드ㆍ주스(303368) · 티(303369) ·
푸드ㆍ디저트(308857) · 아이스크림(303371).

`category_srl=303364` 를 실제로 받아보면 **서버렌더로 상품명이 다 들어있다.**

> 에스프레소 H-아메리카노 I-아메리카노 I-빅포즈 아메리카노 H-카페라떼 I-카페라떼 H-카푸치노
> H-바닐라라떼 … I-바닐라크림라떼 / 첫 페이지 1 2 3 끝 페이지

robots 도 허용이다.

```
User-agent: *
Disallow: /board_xIbz35/   (게시판 8종)
…
Allow:/
```
`can_fetch("sinsang-note/1.0", "/index.php?mid=compose&act=dispCafemenuGalleryList&category_srl=303364")` → **True**

### 그런데 신제품 신호가 하나도 없다

- `NEW` 배지 **없음** (페이지의 `NEW` 는 전부 `NEWS` 메뉴 이름)
- 신메뉴 전용 카테고리 **없음** ("추천메뉴"는 추천이지 신제품이 아니다)
- 날짜 문자열 **0건** (`\d{4}-\d{2}-\d{2}` 패턴 미검출)
- `document_srl` 도 링크에 안 나온다. 이미지가 `/files/attach/images/272857/749/303/<해시>.jpg` 인데
  가운데 숫자(749·751·753…)가 증가하긴 하나 **날짜가 아니다**

→ 수집은 쉽지만 **합류 첫날 신제품 0건**이고 이후에도 diff 에만 의존한다.
파스쿠찌·미스터피자와 같은 처지다. 요청 수는 카테고리 9 × 페이지 ~3 = **약 27회**로 적지 않다.

### 더벤티 — 1차에서 못 찾은 신메뉴 URL 을 찾았다

1차가 `/menu/new.html` 로 시도해 404 가 난 이유는, 실제 사이트가 `/new2022/` 아래 있어서다.
`theventi.co.kr/` 은 `/new2022/main/intro.html` (스플래시)로 가고, 본체는 `/new2022/main/main.html` 이다.
거기 nav 의 `../menu/new.html` 을 풀면 **`https://www.theventi.co.kr/new2022/menu/new.html`** 다.

```
== https://www.theventi.co.kr/new2022/menu/new.html
   200  len=65565   title: 신메뉴 | 더벤티 | theventi
```

**1요청에 180건**이고 전부 서버렌더다. 마크업이 `<li><img src="…_YYYYMMDDHHMMSS.jpg"><p>이름</p></li>` 형태다.

| 이미지 타임스탬프 | 항목 |
|---|---|
| `20260902151409` | 26년 브랜드캠페인_옥수수 |
| `20260901181820` | 26년 브랜드캠페인_포도 |
| `20260810175850` | 26년 제로 음료 3종 |
| `20260701163908` | 26년 젠레스 존 제로 |
| `20260521092102` | 26년 여름 시즌 마시는 빙수 3종 |
| `20251229160000` | 2025년 겨울 스페셜 시즌 전통차 4종 |

**할리스·노브랜드버거와 달리 일괄 재업로드 흔적이 없다.** 시각이 초 단위로 다 다르고,
목록 정렬 순서와도 일치한다. 이건 `uploaded_at` 신뢰도가 높은 쪽이다.

**다만 한 항목이 상품 1건이 아니다.** "26년 제로 음료 3종"처럼 **시즌 묶음**이다.
그대로 `Item.name` 에 넣으면 상품명이 아니게 된다. 개별 상품명은 `/new2022/menu/all.html` 쪽에 있을
것으로 보이나 **요청 5회를 다 써서 확인 못 했다.** 어댑터를 쓰기 전에 이 연결을 먼저 풀어야 한다.

robots 는 깨끗하다.
```
User-agent: *
Allow: /
Sitemap: https://www.theventi.co.kr/sitemap.xml
```

### 커피에반하다 — 신호 형태는 최고, 그런데 페이지가 멈춰 있다

`/main/menu/new.php` 에 전용 페이지 + `NEW` 배지 + 개별 업로드일이 **셋 다** 있다.

```html
<a href='/main/menu/view.php?m_idx=1264'>
  <img src='/data/menu/2024/12/17/1734397104.png' alt='메뉴 이미지'>
  <p class='title'>슈톨렌</p><p class='sub_title'>Stollen</p>
  <div class='badgeContainer'><div class='badge'>NEW</div></div>
```

이미지 경로가 `/data/menu/YYYY/MM/DD/<unix timestamp>.png` 다. `1734397104` → **2024-12-17 09:58**.
경로 날짜와 timestamp 가 서로 맞는다. 상품 상세는 `m_idx` (1142~1264 범위, 증가순).

**그런데 이 페이지 19건의 날짜 분포가 이렇다.**

| 연월 | 건수 |
|---|---|
| 2024-12 | 3 |
| 2024-11 | 2 |
| 2024-09 | 1 |
| 2024-07 | 7 |
| 2024-06 | 6 |

**최신이 2024-12-17 이다. 오늘(2026-09-30) 기준 1년 9개월 전이다.**
신메뉴 페이지가 사실상 방치돼 있다. 붙여도 새 게 안 나올 가능성이 높다.
붙이기 전에 이 페이지가 다시 갱신되는지 한 번 더 확인해야 한다.

**robots.txt 는 HTML 을 허용하지만 이미지를 막는다 — 이삭토스트와 같은 함정이다.**

```
User-Agent: *
Disallow: /admin/
Disallow: /data/
Disallow: /image/
Disallow: /lib/
Disallow: /config/
```
`can_fetch("sinsang-note/1.0", "/main/menu/new.php")` → **True**
그런데 상품 이미지 경로가 `/data/menu/2024/12/17/1734397104.png` 로 **`/data/` 아래**다.
`can_fetch(".../data/menu/…")` → **False**. 파싱은 되지만 **이미지 직접 요청·핫링크는 robots 위반**이다.
`BRAND-CANDIDATES.md` §6-4(이삭토스트 `/admin/data/product2/`)와 같은 건이니 같이 방침을 정해야 한다.

### 할리스 — robots 는 허용인데 약관이 걸린다 (신규 발견)

`hollys.co.kr/customer/policy/serviceTerms.do` 본문이다.

> **제15조 게시물의 저작권과 소유권** … 2. 회원은 서비스를 이용하여 얻은 정보를 회원의 **비영리적인 이용
> 이외의 목적으로 복제, 출판, 방송 등에 사용**하거나 제3자에게 판매하는 등 **상업적으로 사용할 수 없습니다.**

> **제18조** … 9) 회사의 서비스 정보를 이용하여 얻은 정보를 **회사의 사전 승낙없이 복제 또는 유통시키거나
> 상업적으로 이용하는 경우**

**`base.py` 가 폴바셋을 뺄 때 인용한 문구("정보를 회사의 사전 승낙 없이 복제 또는 유통하거나
상업적으로 이용하는 행위")와 사실상 같은 조항이다.** 폴바셋을 뺐으면 할리스도 같이 취급하는 게 일관적이다.

단서 두 가지는 정확히 적어 둔다.
1. 주어가 **"회원"** 이다. 이 약관 제4조가 회원을 "이용계약을 체결하고 아이디를 부여받은 자"로 정의한다.
   우리는 로그인 없는 비회원이라 `CRAWLING-POLICY.md` §4 의 browsewrap 논점이 그대로 적용된다.
2. 그래도 §4 의 결론("법정에서 이기느냐가 아니라 분쟁을 만들지 않는 것이 목표")을 따르면
   **빼는 쪽**이다. 최종 판단은 사용자 몫이다.

원래도 할리스는 신호가 이미지 업로드일뿐이라 순위가 낮았다. 이 건으로 사실상 제외 대상이 됐다.
참고로 이미지 타임스탬프 분포도 메가·노브랜드버거와 같은 **일괄 재업로드** 모양이다
(에스프레소 카테고리 52개 중 30개가 `202504`).

### 주점 3곳 — 연령 게이트는 없었다. 메뉴가 이미지다

셋 다 홈과 메뉴 페이지가 **로그인·연령확인 없이 HTTP 200 으로 바로 온다.**
`성인`·`19세`·`연령`·`본인인증`·`청소년` 문자열이 **한 건도 안 나왔다.**

**투다리** (`tudari.co.kr`, WordPress). 푸터 사업자 확인됨 — `대표자 : 김형택 | 사업자등록번호 : 122-81-21342`.
`/tudari-menu/` 렌더 텍스트에 상품명이 **하나도 없다.** "Menu Book 메뉴북 보기" 버튼뿐이다.
이미지 `alt` 속성도 전부 비어 있어(유니크 alt 0건) 이미지에서 이름을 못 건진다.
`/wp-content/uploads/2024/11/` 에 617건이 몰려 있는데 열어 보면 로고 반응형 변형(`logo_tudari01-300x66.png` …)이다.
robots 는 허용이다(`Disallow: /wp-admin/` 만).

**청담동말자싸롱** (`www.malja.co.kr`, gnuboard). 제목 `스몰비어&치맥 청담동말자싸롱`.
메뉴 3종(`menu_snack.php` 안주 / `menu_drink.php` 주류 / `menu_promotion.php` 프로모션).
안주 페이지에 "신메뉴 / 세트메뉴 / 시그니처 / 치킨 / 국물요리 / 마른안주&디저트" 탭이 있는데,
각 탭의 실체가 **배너 이미지 1장**이다.

```html
<li class="active"><a href="#" data-img="https://www.malja.co.kr/data/banner/1764295606_pc.png">신메뉴</a></li>
```

파일명이 unix timestamp라 **배너 갱신일은 알 수 있다** — `1764295606` → **2025-11-28**,
홈 배너 `1762500776` → 2025-11-07 (alt 가 "25하반기 신메뉴"). 하지만 상품 단위가 아니다.
robots 는 `User-agent: * / Allow:/` 다.

**생활맥주** (`dailybeer.co.kr`, WordPress). 푸터 `상호명 (주)데일리비어 | 대표이사 임상진`.

store / support / legal 로만 구성된 **기업·IR 사이트**다. robots 는 WP 기본값이다.

### TLS 로 막히는 브랜드가 생각보다 많다

우리 클라이언트(`httpx` 기본 검증)로 **인증서 때문에** 못 붙은 곳이다. 우회하지 않았다.

| 호스트 | 오류 |
|---|---|
| `tomntoms.com`, `www.tomntoms.com` | `unable to get local issuer certificate` (중간 인증서 미설치) |
| `www.tomntoms.co.kr` | `Hostname mismatch` |
| `coffeesmith.co.kr` | `Hostname mismatch` |
| `mammothcoffee.co.kr` | `Hostname mismatch` |

`CRAWLING-POLICY.md` 에 검증 우회 방침이 없어서 임의로 정하지 않았다 — **판단이 필요한 항목이다.**

즉 "막혔다"기보다 "우리 쪽 검증을 통과 못 한다"에 가깝다.

## 5. 추천 순위

기준 순서는 지시받은 대로 **(1) 신제품 신호 → (2) 수집 난이도 → (3) 관심도** 다.

| # | 브랜드 | 근거 | 예상 요청 수 |
|---|---|---|---|
| **1** | **매머드커피** | **신메뉴 전용 페이지가 1요청에 24건**을 준다. 이번 조사에서 신호·효율·관심도가 동시에 맞는 유일한 브랜드다. 전국 1,000여 개 지점이라 관심도도 높다. ⚠️ robots.txt 가 **없으니**(404) `CRAWLING-POLICY.md` 기준대로 보수적 간격 | **1~2** |
| **2** | **더벤티** | 신메뉴 전용 페이지 + **일괄 재업로드 흔적 없는 개별 타임스탬프**. 1요청 180건. ⚠️ 다만 항목이 **시즌 묶음**이라 상품명으로 바로 못 쓴다. `all.html` 과 연결하는 설계가 선행돼야 해서 2위 | **2~3** (`new.html` + `all.html`) |
| **3** | **커피에반하다** | 전용 페이지 + `NEW` 배지 + 개별 업로드일. 신호 **형태만 보면 1위**다. ⚠️ **최신이 2024-12-17** 이라 실제로 새 게 안 나올 수 있어서 3위. 붙이기 전 갱신 여부 재확인 필수. ⚠️ robots 가 `/data/`(상품 이미지)를 막는다 | 1~2 |
| **4** | **컴포즈커피** | 수집은 확실히 되고(1차 판정 뒤집음) 브랜드 관심도도 매우 높다. 그러나 **신제품 신호가 0** 이라 합류 첫날 0건이고 요청도 ~27회로 많다. 카테고리 채우기용 | ~27 |
| **5** | **파스쿠찌** | 수집 쉬움 + 신호 없음. 컴포즈와 같은 처지인데 관심도가 아래라 5위 | ~20 |

### 순위에 넣지 않은 이유

- **할리스** — 신호가 업로드일뿐인데, 이번에 **약관 문제까지 확인됐다**(§4). 폴바셋과 같은 조항이다.
  순위 문제가 아니라 **빼는 게 맞다고 본다.** 결정은 사용자 몫이다.
- **투썸플레이스** — robots 는 우리를 안 막지만 WAF 가 막는다. 뚫으려면 UA 위장뿐이라
  **프로젝트 방침상 불가**다(§2).
- **주점 3곳(투다리·말자싸롱·생활맥주)** — **연령 게이트는 없었다.** 대신 메뉴가 통이미지거나
  아예 없다. OCR 없이는 상품명이 안 나온다. **주점 카테고리는 당분간 포기가 맞다.**
- **감성커피·벤티프레소·토프레소** — 브랜드 사이트가 아니라 **가맹 유치 랜딩**이다. 메뉴가 없다.
- **탐앤탐스·커피스미스** — TLS 문제라 내용 자체를 못 봤다. 인증서 검증 방침이 정해지면 재조사 대상.
- **공차·쥬시·역전할머니맥주·999맥주·더리터·커피나무·스무디킹·만동제과** — 도메인을 특정 못 했거나
  연결이 안 됐다. §7 에 남긴다.

## 6. 신제품 신호가 확실한 브랜드 (요약)

붙는 날부터 신제품을 내놓을 수 있는 곳이다. **이번 조사에서는 3곳뿐이다.**

| 신호 종류 | 브랜드 |
|---|---|
| **신메뉴 전용 페이지** | 매머드커피(`/sub/menu/new_list.php`), 더벤티(`/new2022/menu/new.html`), 커피에반하다(`/main/menu/new.php`) |
| **NEW 배지 (`is_new`)** | 커피에반하다 |
| 개별 업로드일 (`uploaded_at`, 일괄 재업로드 흔적 없음) | 더벤티, 커피에반하다 |
| 업로드일만 (일괄 재업로드 흔적 있음 → `released_at` 금지) | 할리스 |
| 배너 갱신일만 (상품 단위 아님) | 청담동말자싸롱 |
| **없음** | 컴포즈커피, 파스쿠찌, 투다리, 감성커피, 벤티프레소, 토프레소, 생활맥주 |

**`released_at` 을 브랜드가 직접 주는 곳은 이번 조사에 하나도 없다.** 이삭토스트가 여전히 유일하다.

## 8. 어댑터를 쓸 사람에게 넘기는 주의사항

1. **스플래시 페이지에 속지 마라.** 이번에 두 번 걸렸다.
   - 컴포즈커피 `/` → 본체는 `/index1` (1차 조사가 여기서 '불가'로 오판했다)
   - 더벤티 `/` → `/new2022/main/intro.html` → 본체는 `/new2022/main/main.html`
   홈이 비어 있으면 **JS 렌더라고 단정하기 전에 홈의 내부 링크부터 확인해라.**
2. **더벤티 신메뉴 항목은 상품이 아니라 시즌 묶음이다.** "26년 제로 음료 3종"을 `Item.name` 에
   그대로 넣으면 안 된다. KFC `/promotion/newMenu` 를 뺀 것과 같은 문제다.
3. **커피에반하다는 신메뉴 페이지가 2024-12-17 에서 멈춰 있다.** 신호가 있다고 바로 붙이지 말고
   갱신 여부부터 확인해라.
4. **매머드커피·파파존스·배스킨라빈스처럼 robots.txt 가 없는 브랜드가 또 늘었다.**
   부재는 금지가 아니지만 허용도 아니다. 보수적 간격을 잡아라.
