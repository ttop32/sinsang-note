# 브랜드 후보 조사 — 직영 대형 F&B · 식품 제조사

`docs/BRAND-CANDIDATES.md` 와 같은 형식이다. **어댑터는 없다.** 조사 결과일 뿐이다.

- 조사일: **2026-09-30**
- 조사 방법: 브랜드당 HTTP 5회 이내, 요청 간 2.2초, `collectors/base.py` 의 `client()` / UA (`sinsang-note/1.0`)
- **HTTP 전에 `dig` + TLS 핸드셰이크(SAN·발급자·만료)로 먼저 걸렀다.** 둘 다 HTTP 요청이 아니다.
  이 단계에서만 파킹 3건을 요청 0회로 잡아냈다(§4).
- robots 는 **원문을 눈으로 읽고** 판정했다. `can_fetch()` 는 대조용으로만 썼고,
  이번에 **세 번째 구멍**을 찾았다(§5). 상태코드와 본문이 HTML 인지도 같이 봤다.
- 추측으로 채운 칸은 없다. 못 본 것은 "확인 못 함"이라고 적었다.

조사 대상은 **공정위 가맹사업 등록에 없는 곳**이다. `docs/FRANCHISE-MASTER.md` §6 이 지적한 구멍 —
100% 직영이라 등록 대상이 아닌 브랜드 — 과 그 문서가 아예 다루지 않는 **식품 제조사**다.
`FRANCHISE-MASTER.md` 의 468개와 `CANDIDATES-*.md` 7종에 이미 있는 브랜드는 다시 조사하지 않았다.

> **조사 중 운영자 지시 변경**: 화면에 **과자 섹션·라면 섹션을 따로** 만들 계획이라
> 제조사가 1순위가 됐다. 표 순서를 그에 맞췄다. 직영 브랜드(§1-3)는 착수했던 만큼만 싣는다.

**총 조사 브랜드 27개** — 제조사 17, 직영 8, 파킹·사망 확인 2.

## 2. 식품 제조사를 넣어야 하는가 — 실측 후 의견

### 결론: **넣는다. 단 "브랜드"가 아니라 "보도자료 소스"로 넣는다.**

`data/products.json` (4,390건, 2026-09-30) 을 실측한 근거다.

**① `released_at` 이 지금 거의 없다 — 이게 진짜 문제다.**

| | 브랜드 수 | 건수 |
|---|---:|---:|
| 전체 | 24 | 4,390 |
| `released_at` 이 있는 브랜드 | **3** | **145** (피자헛 84·이삭토스트 60·배스킨라빈스 1) |
| `is_new` 만 있는 브랜드 | 21 | — |

**24개 중 3개.** 나머지는 `is_new` 배지뿐이라 "언제 나왔는지"를 못 쓴다.
제조사 보도자료는 **날짜가 본문 구조에 박혀 있다** — 오뚜기 `<div class="date">2026.09.28</div>`,
롯데웰푸드 `<em>2026-09-21</em>`, 오리온 `<span class="date">2026.09.29</span>`.
셋 다 **어제·그저께 자**다. 회전이 실제로 빠르다는 증거다.

**② 중복은 생긴다. 그런데 `make_key` 로는 안 걸러진다 — 실측했다.**

편의점 1,878건(CU 666·세븐일레븐 228·이마트24 984) 중 **제조사명이 이름에 드러난 건이 457건(24.3%)** 이다.

| 편의점 | 제조사명 노출 | 비율 |
|---|---:|---:|
| 이마트24 | 272 / 984 | 27.6% |
| 세븐일레븐 | 73 / 228 | 32.0% |
| CU | 112 / 666 | 16.8% |

`base.make_key` 에 실제로 넣어 봤다. **3쌍 전부 키가 다르다:**

```
이마트24:롯데)허쉬쿠키앤크림40g(냉장)   vs  롯데웰푸드:허쉬쿠키앤크림    → 다름
이마트24:농심)보노콘스프3입             vs  농심:보노콘스프              → 다름
이마트24:CJ)햇반작은공기130g            vs  CJ제일제당:햇반작은공기      → 다름
```

이유가 둘이다.
- **키에 브랜드명이 들어간다.** `이마트24:` 와 `롯데웰푸드:` 는 영원히 안 만난다.
- **편의점 이름에 제조사 접두어·용량·보관형태가 붙어 있다.** `롯데)`, `40g`, `(냉장)`.
  `_SIZE` 는 `40g` 은 털지만 `(냉장)` 은 남기고, `롯데)` 접두어는 손대지 않는다.

즉 **제조사를 지금 구조 그대로 새 브랜드로 붙이면 같은 상품이 화면에 두 번 뜬다.**

**⚠️ 그리고 `CU 666건에 오뚜기·CJ 제품이 있다`는 전제는 절반만 맞다.**
CU 이름의 `X)` 접두어는 **제조사가 아니라 분류 코드가 섞여 있다.** 실측한 상위 접두어:

```
삼립 42 · CJ 29 · 도 24 · 롯데 23 · PBICK 22 · 샌 21 · 405 18 · 김 17 · 데일리 17 · 오뚜기 17
```

`도`=도시락, `김`=김밥, `샌`=샌드위치, `햄`=햄버거, `샐`=샐러드 — **CU 자체 간편식(PB)** 이다.
`PBICK`·`데일리` 도 PB 라벨이다. CU 666건의 대다수는 제조사 포장상품이 **아니다**(16.8%만 해당).
중복 위험은 **이마트24·세븐일레븐 쪽이 더 크다.**

**③ 그래서 권하는 방식**

제조사를 **`BRANDS` 에 새 브랜드로 등록하지 말고**, 보도자료를 **기존 편의점 항목의 `released_at` 을
채워 주는 보강 소스**로 쓰는 쪽이 낫다. 근거:

- 편의점 데이터는 **상품 축이 이미 정확하다**(실제 판매 SKU, 용량까지). 없는 건 날짜뿐이다.
- 제조사 보도자료는 **날짜는 정확한데 상품 축이 거칠다**. 한 건이 "2종", "시리즈"를 통째로 말한다.
  (롯데웰푸드 `떡볶이맛 젤리 2종 선봬` — 상품이 2개인데 기사는 1건)
- 두 축을 곱하면 중복이지만, **날짜만 가져오면 손실이 없다.**

매칭 키는 `make_key` 가 아니라 별도로 만들어야 한다. 편의점 이름에서 **제조사 접두어·용량·보관형태를
털어낸 코어 문자열**로 맞추는 방식이다. 이건 어댑터가 아니라 `collect.py` 의 후처리 단계다.

**⚠️ 다만 보도자료를 날짜 소스로 쓸 때 함정이 하나 있다.** 롯데웰푸드 9건을 실제로 읽어 보니
**신제품 기사는 3건뿐**이고 나머지는 수상·CSR·팝업·실적이다. 게다가
`꼬깔콘 야장시리즈 출시 보름만 80만 봉 판매 돌파` 같은 **판매실적 기사가 '출시'라는 단어를 포함한다.**
이걸 그대로 쓰면 **출시일이 보름 밀린다.** `출시`·`선봬`·`론칭` 키워드 필터만으로는 부족하고,
"보름만"·"돌파"·"판매" 류를 빼는 역필터가 같이 필요하다.

**④ 예외: 과자·라면 섹션을 진짜 따로 만들 거라면 팔도는 브랜드로 붙여도 된다.**
팔도 `/product/noodle` 은 **카탈로그 자체에 `신제품` 배지가 SSR** 로 붙는다(75건 중 12건).
보도자료가 아니라 카탈로그라서 상품 축이 1:1 이고, 편의점에 안 들어가는 SKU 도 잡힌다.
날짜는 없으므로 `is_new=True` 만 채우고 `released_at` 은 비운다.

## 3. 근거 (실측 조각)

### 3-1. 농심 — TLS 는 해결됐다. 막은 건 robots 다

`www.nongshim.com` 은 기본 설정으로 핸드셰이크가 깨진다.

```
SSLError: [SSL: SSLV3_ALERT_HANDSHAKE_FAILURE]
```

`CRAWLING-POLICY.md` §6-1 의 "구형 TLS" 칸처럼 보이지만 **인증서 문제가 아니다.**
**검증을 켠 채로** 암호군 보안수준만 낮추면 통과한다:

```python
ctx = ssl.create_default_context()      # 검증 ON 유지
ctx.set_ciphers("DEFAULT@SECLEVEL=1")   # 구형 암호군 허용
→ OK  TLSv1.2  AES256-GCM-SHA384
   notAfter: Jan 22 23:59:59 2027 GMT   issuer: Sectigo   SAN: *.nongshim.com
```

인증서는 **멀쩡하고 유효하다.** 서버가 PFS 없는 RSA 키교환 암호군만 지원해서
요즘 OpenSSL 의 기본 `SECLEVEL=2` 가 거부한 것뿐이다.

> **§6-1 에 칸이 하나 더 필요하다.** "인증서는 정상인데 암호군이 구형" 은
> `verify=False` 없이 `set_ciphers("DEFAULT@SECLEVEL=1")` 만으로 풀린다.
> 이건 **검증을 끄는 게 아니다** — 인증서 체인·호스트명 검증은 그대로 돈다.
> 탐앤탐스·커피스미스(인증서가 깨진 경우)와 **다른 사례**다.

그런데 농심은 **robots 에서 막힌다.** `verify` 를 건드릴 이유 자체가 없어졌다.

## 5. `can_fetch()` 의 **세 번째 구멍** — 규칙 순서

`CRAWLING-POLICY.md` §6-2 가 구멍 둘(403 해석, 쿼리 와일드카드)을 적어 놨다. **하나 더 찾았다.**

앤트러사이트 robots 원문이다:

```
User-agent: *
Allow: /
Disallow: /site_join
Disallow: /login
Disallow: /shop_cart
Disallow: /?mode*
Disallow: /admin
```

`can_fetch()` 결과:

```
can_fetch('/admin')      = True   ← Disallow 가 명시돼 있는데 True
can_fetch('/shop_cart')  = True   ← 마찬가지
can_fetch('/login')      = True   ← 마찬가지
can_fetch('/?mode=policy') = True ← 알려진 구멍 2
```

**Disallow 를 전부 무시한다.** 최소 재현:

```python
"User-agent: *\nAllow: /\nDisallow: /admin\n"   → can_fetch('/admin') = True
"User-agent: *\nDisallow: /admin\nAllow: /\n"   → can_fetch('/admin') = False
```

**같은 규칙인데 줄 순서만 바꾸면 판정이 뒤집힌다.**
`urllib.robotparser` 는 규칙을 **파일에 적힌 순서대로 훑어 첫 매칭**을 쓴다.
`Allow: /` 가 먼저 있으면 모든 경로에 먼저 걸려서 뒤의 Disallow 가 영원히 도달 불가다.
RFC 9309 §2.2.2 는 **가장 긴 매칭이 이긴다**고 정하므로 둘 다 `False` 여야 맞다. 비표준 동작이다.

**이번 조사에서 걸린 곳:** 앤트러사이트 · 카페꼼마 · 풀무원(본체·뉴스룸 양쪽)

**네 번째 구멍도 하나.** 카페꼼마는 `User-agent: *` 그룹이 **두 번** 나온다
(앞엣것은 Disallow 여럿, 뒤엣것은 `Allow:/` 하나). RFC 9309 은 같은 토큰 그룹을 **병합**하라고 하는데
`robotparser` 는 그렇게 하지 않는다.

### 전 파일 감사 결과

| robots 파일 | `*` 그룹 | `Allow:/` 선행 | 쿼리 와일드카드 | `*` 중복 |
|---|---|---|---|---|
| 앤트러사이트 | 있음 | ⚠️ 예 | ⚠️ 예 | 1 |
| 카페꼼마 | 있음 | ⚠️ 예 | ⚠️ 예 | ⚠️ **2** |
| 풀무원 (본체·뉴스룸) | 있음 | ⚠️ 예 | 아니오 | 1 |
| 빙그레·팔도·오리온·동원·삼양·테라로사·프릳츠·나무사이로·아웃백·이랜드이츠·hy | 있음 | 아니오 | 아니오 | 1 |
| 농심·CJ·CJ푸드빌 | 있음 | 아니오 (⛔ `Disallow: /`) | 아니오 | 1 |
| **블루보틀·매일유업·오뚜기** | **없음** | — | — | — |

> 빙그레·팔도는 `Disallow` 가 **먼저** 오고 `Allow: /` 가 뒤라 정상 동작한다. 순서가 전부다.

첫 줄이 이렇다:

> "As a condition of accessing this website, you agree to abide by the following content signals"
> (이 웹사이트에 접속하는 조건으로, 아래 콘텐츠 신호를 따르는 데 동의하는 것으로 본다)

그러고는 **정작 신호를 하나도 선언하지 않았다.** 규칙이 없으니 robots 상으로는 허용이지만,
이 문구는 robots 규칙이라기보다 **browsewrap 약관에 가깝다**. `CRAWLING-POLICY.md` §6-4 의
"robots 는 허용, 약관이 금지" 칸에 넣을지 판단이 필요하다. (신호를 선언 안 했으니 금지도 아니다.)

**② 매일유업·오뚜기·블루보틀은 우리 UA 가 매칭될 그룹이 없다.**
매일유업은 `User-agent: Yeti` **한 그룹뿐**이다. RFC 9309 상 매칭 그룹이 없으면 제한이 없다 —
**형식상 허용**이다. 다만 운영자가 네이버만 상정하고 쓴 티가 난다.
`CANDIDATES-CHICKEN.md` 가 멕시카나(`Yeti` 그룹만 존재)를 **허용**으로 판정했으니
**선례를 따르면 허용**이다. 일관성 차원에서 적어 둔다.

**③ 롯데웰푸드·신세계푸드·크라운·해태는 robots 판정이 불가능하다.**
robots.txt 가 HTML 이라 규칙을 알 수 없다. 부재(404)는 금지가 아니지만 허용도 아니다.
`BRAND-CANDIDATES.md` §6-2 기준대로 **더 보수적인 간격**을 잡아야 한다.
이 중 롯데웰푸드는 §2 추천 1순위라 **판단이 실제로 필요하다.**

**④ 오리온 상품 이미지가 `/upload/` 금지 경로에 있다.**
이삭토스트·커피에반하다와 같은 §6-3 사례다. `Item.image` 에 URL 을 담는 건 괜찮지만
**R2 미러링(이슈 #5) 때 오리온은 빼야 한다.**

## 9. 확인 못 한 것

1. **동원F&B 뉴스 상세의 날짜** — 샘플 1건(`contentno=649`)에 날짜 토큰이 0개였다.
   649건 중 하필 그 건만 그럴 수도 있다. **차점 후보라 이것부터 확인해야 한다.**
2. **이용약관을 한 건도 못 읽었다.** 브랜드당 5요청 예산을 robots·홈·뉴스·제품에 다 썼다.
   표의 `약관` 칸이 전부 "확인 못 함"인 이유다. **§2 추천 5곳은 약관 확인이 남아 있다.**
3. **삼양식품·크라운·해태·풀무원의 내부 API** — 넷 다 JS 렌더인데 번들을 안 열어 봤다.
   피자헛·버거킹·BBQ·본아이에프가 그렇게 풀렸으니 **여기도 풀릴 가능성이 있다.**
   특히 삼양은 불닭 브랜드라 인지도가 높아 값어치가 크다.
4. **hy 의 제품 사이트** — `hyfresh.co.kr`·`fredit.co.kr` 가 인증서 SAN 에 있는데 안 가 봤다.
   코퍼레이트 `hy.co.kr` 은 제품 정보가 0이다.
5. **남양유업 코퍼레이트 사이트** — 쇼핑몰 종료 안내로 리다이렉트돼서 본체를 못 찾았다.
6. **직영 카페 6곳의 콘텐츠 페이지** — 테라로사·프릳츠·앤트러사이트·카페꼼마·나무사이로·블루보틀.
   robots 와 도메인까지만 했다. 운영자 우선순위가 제조사로 바뀌어 중단했다.
   **신제품 신호 유무를 하나도 모른다.**
7. **아웃백 메뉴 경로** — `/menu/menuList.do` 가 404. 실제 경로 못 찾았다.
8. **애슐리·자연별곡 개별 브랜드 페이지** — 이랜드이츠 gnuboard 의 `bo_table=s1_*_*` 중
   어느 것이 어느 브랜드인지 확인 못 했다.
9. **신세계푸드 보도자료 상세** — `news_detail.sf?newsId=1471` 이 있는 건 봤는데 안 열어 봤다.
10. **호텔·백화점 델리, 이마트 피코크** — 착수 못 했다. 우선순위 변경으로 잘렸다.

## 10. 어댑터를 쓸 사람에게

1. **`can_fetch()` 에 구멍이 하나 더 있다(§5).** `Allow: /` 가 Disallow 보다 **먼저** 나오면
   모든 Disallow 가 무시된다. 앤트러사이트·카페꼼마·풀무원이 이 경우다. **원문을 읽어라.**
2. **robots.txt 본문 첫 글자가 `<` 인지 봐라(§6).** 해태는 200 + `text/plain` 인데 HTML 이다.
   상태코드도 Content-Type 도 못 믿는다.
3. **날짜를 정규식으로 줍지 마라(§6-2).** 신세계푸드는 293개가 전부 이미지 경로였고
   크라운은 담당자 스크린샷 파일명이었다. **DOM 위치를 특정하고 월·일 범위를 검증해라.**
4. **보도자료를 날짜 소스로 쓸 거면 역필터가 필요하다(§6-3).**
   `출시 보름만 80만 봉 판매 돌파` 가 '출시' 키워드에 걸린다. 그대로 쓰면 날짜가 보름 밀린다.
5. **제조사를 `BRANDS` 에 새로 등록하기 전에 §2 를 읽어라.** `make_key` 로는 편의점 중복이
   **안 걸러진다**(실측 3쌍 전부 키 불일치). 브랜드로 붙일지 보강 소스로 쓸지가 먼저다.
6. **오뚜기는 목록이 아니라 홈에서 긁어야 한다.** `/pr/news` 는 JS 라 링크가 0개인데
   홈에 최신 6건이 SSR 로 있다. `idx` 가 순번이라 역순 순회도 가능하다.
7. **동원F&B 는 SSR 경로만 써라.** robots 가 `/services/api/`·`/*Ajax*`·`/*json*` 을 전부 막는다.
   번들에서 내부 API 를 찾아 쓰는 수법이 **여기서는 명시적 위반**이다.
8. **농심 TLS 는 `verify=False` 없이 풀린다(§3-1).** 다만 robots 가 막으니 쓸 일이 없다.
   같은 증상을 다른 사이트에서 만나면 `set_ciphers("DEFAULT@SECLEVEL=1")` 를 먼저 시도해라.
9. **`dig` 로 `76.223.54.146` / `13.248.169.48` 이 나오면 파킹이다(§4).**
   이 파킹 서비스는 도메인 이름 그대로 인증서를 발급해서 **SAN 검사로는 안 걸린다.**
