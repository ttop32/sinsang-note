## 2. 1단을 5개로 늘릴 수 있는가 — 실측

`collect.py:PRIMARY` 주석에 **"375px 화면에서는 탭이 몇 개든 4개까지만 보인다"** 고 적혀 있다.
라이브에서 실제 칩(`.t`)을 복제해 다시 쟀다. 쓸 수 있는 폭은 **343px**(375 − 좌우 패딩 16×2).

### 2-1. 🔴 먼저 — **지금 4탭도 이미 넘친다**

| 조합 | 총 폭 | 343px 대비 |
|---|---:|---|
| **현재 4탭 + 건수** (`전체483 편의점127 카페175 외식181`) | **352px** | 🔴 **−9px (이미 초과)** |

주석이 쓰인 때는 건수가 2자리였다(`전체302 편의점84`). **건수가 3자리가 되면서 넘어갔다.**
즉 "4개가 상한"은 더 이상 사실이 아니고, **이미 상한을 넘긴 상태로 운영 중**이다.

### 2-2. 5탭 조합 전수 측정

| # | 조합 | 총 폭 | 여유 | 판정 |
|---|---|---:|---:|---|
| A | 5탭 + 건수, 패딩 14px | 428 | −85 | ❌ |
| B | 5탭 + 건수, 패딩 10px | 388 | −45 | ❌ |
| C | 5탭 + 건수, 패딩 8px + 간격 4px | 360 | −17 | ❌ (패딩 8px 은 터치가 좁다) |
| D | 5탭 + 건수(10px 글씨), 패딩 10px | 375 | −32 | ❌ |
| E | **5탭 건수 없음, 패딩 14px** (`가공식품`) | **331** | **+12** | 🟡 들어가지만 아슬아슬 |
| **F** | **5탭 건수 없음, 패딩 10px** (`가공식품`) | **291** | **+52** | 🟢 **채택** |
| G | 5탭 건수 없음, 패딩 10px (`마트`) | 267 | +76 | 🟢 (이름은 §3 에서 탈락) |
| H | `전체` 칩 제거 + 4탭 + 건수, 패딩 10px | 307 | +36 | 🟠 "전체로 돌아가기"가 사라진다 |
| I | 6탭 건수 없음, 패딩 10px (`+음료`) | 344 | **−1** | ❌ **6번째는 못 들어간다** |

### 2-3. 🟢 건수 배지를 떼도 되는 이유 — 같은 정보가 이미 두 곳에 있다

PRODUCT-PLAN §5-2 는 "건수 배지는 유지하는 게 좋다(어느 탭에 뭐가 있는지 알려주는 유일한 신호)"
라고 썼다. **그때는 `편의점 2건` 처럼 비어 있는 탭이 있었다.** 지금은 다르다.

1. **칩을 누르면 바로 아래 `#cnt` 가 `80건` 을 띄운다** — `collect.py` 의
   `cnt.textContent = (kind || sub || term) ? n + '건' : ''` 가 이미 그렇게 동작한다.
2. **빈 1단은 애초에 안 그려진다** — `for i,(label,key) in enumerate(PRIMARY) if not key or pcount.get(key)`.
   그러니 "눌렀더니 0건"이 생기지 않는다.
3. **푸터가 총계를 적는다** — `최근 60일 신제품 483건 — 이 화면에 최신 300장`.

→ **1단 건수는 중복이다. 2단 건수는 유지한다** — 2단은 칩이 5~9개라 어느 걸 고를지 고르는
신호가 실제로 필요하고, 어차피 가로 스크롤이라 폭 제약이 1단만큼 세지 않다.

### 2-4. 2단은 전부 가로 스크롤이다 (피할 수 없다)

| 2단 줄 | 총 폭 | 343px 대비 |
|---|---:|---|
| 카페 5칩 + 건수 (패딩 12px) | 428 | −85 |
| 편의점 5칩 + 건수 | 424 | −81 |
| 외식 9칩 + 건수 | **713** | −370 |

→ **2단에서 가로 스크롤은 전제다.** 그래서 `WORK-ORDERS WO-6`(건수 내림차순 + 스크롤 힌트)이
이 개편의 **선행조건**이다. 외식 9칩 중 375px 에 보이는 건 4~5개뿐이고,
지금처럼 선언 순서대로 두면 가장 큰 `치킨 337`·`한식 288` 이 뒤로 밀릴 수 있다.

## 3. 대분류 이름 — `가공식품` 으로 한다

과자·라면·음료·냉동식품을 묶는 한국어 한 단어를 네 개 놓고 쟀다.

| 후보 | 폭(pad10) | 판정 |
|---|---:|---|
| **`가공식품`** | 70px | 🟢 **채택** |
| `마트` | 46px | ❌ **이마트24가 `편의점` 에 있다.** "마트를 눌렀는데 이마트24가 없다"는 3초 혼란이 생긴다 |
| `간식` | 54px | ❌ **라면·냉동식품이 간식이 아니다.** 사용자가 요구한 네 가지 중 둘을 설명 못 한다 |
| `식품` | 46px | ❌ 전부 식품이다. 아무것도 구분하지 못한다 |

**`가공식품` 의 약점과 그 보완.** 기관 용어 냄새가 난다. 그런데
① 식약처 표기·마트 매대 표기로 일반인이 읽을 수 있는 말이고,
② **바로 아래 2단에 `라면`·`과자`(앞으로 `음료`·`냉동식품`)가 붙어 뜻이 즉시 보강된다.**
③ `마트`·`간식` 과 달리 **틀린 말이 아니다.**

🟠 **알고 가는 비용 — 축이 섞인다.** `편의점·카페·외식` 은 *어디서 사느냐*인데
`가공식품` 은 *무엇이냐*다. PRODUCT-PLAN §5-2 가 "둘 중 하나만 고른다면 어디서"라고 했고
그 원칙을 여기서 한 번 깬다. **그래도 이게 낫다** — 농심 `신라면 툼바` 의 구매처는
편의점이기도 마트이기도 해서 *어디서* 축으로는 어디에도 못 넣는다.
사용자가 이 넷을 묶어 달라고 한 것 자체가 "이건 구매처가 아니라 종류다"라는 뜻이다.

## 4. 매핑 규칙

### 4-1. 카페 · 외식 · 가공식품 — **브랜드 단위. `BRANDS` 하나만 보면 된다**

`collectors/base.py:BRANDS[brand] = (brand_type, brand_sub)` 가 정본이고
**코디네이터가 이미 반영했다.** 추가로 할 일은 `collect.py` 두 군데뿐이다.

```python
# collect.py — 1단
PRIMARY = [("전체", ""), ("편의점", "편의점"), ("카페", "카페"),
           ("외식", "외식"), ("가공식품", "가공식품")]

def primary_of(r: dict) -> str:
    t = r.get("brand_type", "")
    if t == "프랜차이즈":
        return "외식"
    if t == "제조사":
        return "가공식품"      # ← 지금은 "편의점" 으로 접히고 있다
    return t                   # 편의점 / 카페
```

```python
# collect.py — 2단. 건수 내림차순 정렬은 WO-6 이 담당한다
SUBS = ["커피", "베이커리", "도넛", "빙수", "아이스크림",      # 카페
        "치킨", "한식", "피자", "햄버거", "분식",              # 외식
        "샌드위치", "도시락", "샐러드", "일식",
        "라면", "과자", "음료", "냉동식품",                    # 가공식품
        "간편식"]                                             # 편의점 (§6, 보류)
```

🔴 **`디저트` 를 `SUBS` 에서 뺀다.** 던킨 → `도넛`, 배스킨라빈스 → `아이스크림` 으로
갈라져 이 값을 쓰는 상품이 0 이 된다. 남겨두면 영영 안 그려지는 죽은 상수다(§7).

### 4-2. 편의점 — 🔴 **상품별 분류축이 지금 데이터에 없다**

카페·외식은 브랜드 하나가 곧 한 분류인데 편의점은 한 브랜드 안에 다 들어 있다.
그래서 상품의 `category` 필드를 봐야 한다. **전수로 뽑았다.**

| 브랜드 | `category` 실제 값 | 쓸 수 있나 |
|---|---|---|
| **CU** (680) | `식품 236` · `과자류 204` · `간편식사 122` · `생활용품 51` · `음료 36` · `아이스크림 28` · `즉석조리 3` | 🟢 **절반은 진짜 분류다** |
| **세븐일레븐** (228) | `Fresh Food 135` · `신상품 93` | 🟠 `Fresh Food` 만 분류. `신상품` 은 매대 이름 |
| **이마트24** (1,341) | `행사 상품 842` · `차별화 상품 475` · `Fresh Food 24` | 🔴 **거의 전부 판매채널**이지 분류가 아니다 |
| **GS25** | *(빈 문자열)* — 보도자료에서 이름만 뽑는다 | 🔴 없음 |

**매핑 규칙 (`category` 완전일치. 부분일치·이름 단어 금지)**

```python
CVS_SUB = {
    "간편식사":    "간편식",
    "즉석조리":    "간편식",
    "Fresh Food": "간편식",
    "과자류":      "과자",
    "음료":        "음료",
    "아이스크림":  "아이스크림",
    # 아래는 매핑하지 않는다 — 분류가 아니다
    #   식품(CU 236)       반찬·정육·채소·부리또가 섞여 있다
    #   신상품(세븐 93)     매대 이름. 과자·음료·라면·주류 혼재
    #   행사 상품/차별화 상품(이마트24 1,317)  판매채널

```

🔴 **이름 단어로 분류하지 마라.** 이 레포에서 그걸로 세 번 사고가 났다
(`핸디`→스타벅스 핸디 젤리 / `카스`→카스테라 / `럼`→쿠키크럼블).
내가 이번 조사에서도 주류 정규식으로 같은 사고를 재현했다
(12건 중 10건이 식품 오탐). **단어를 쓸 거면 전수 오탐 0 확인이 설계의 일부다.**

**접두도 쓸 수 없다.** 써볼까 해서 쟀는데 **접두는 분류가 아니라 제조사다.**

| 브랜드 | 상위 접두 | |
|---|---|---|
| CU | `삼립 42` · `CJ 29` · `도 28` · `롯데 23` · `샌 22` · `PBICK 22` · `김 20` | 분류 접두(`도)`·`샌)`·`김)`·`햄)`·`면)`·`샐)`)는 **680건 중 약 130건**뿐 |
| 세븐일레븐 | `All New 42` · `롯데 40` · `그린 19` · `삼립 12` | 🔴 **분류 접두 0** (PB·제조사뿐) |
| 이마트24 | `(없음) 230` · `CJ 126` · `옐로우 67` · `성수310 53` | 🔴 **분류 접두 0** |

## 6. 매핑 안 되는 1,697건 — "미분류"를 어떻게 할 것인가

편의점 2,249건 중 **매핑되는 건 552건(24.5%)뿐**이다.

| 중분류 | 카탈로그 | 화면(300장) |
|---|---:|---:|
| 간편식 | 284 | **40** (CU 전량) |
| 과자 | 204 | 0 |
| 음료 | 36 | 0 |
| 아이스크림 | 28 | 0 |
| **(미분류)** | **1,697** | **40** (세븐일레븐 전량) |

### 6-1. 🟢 먼저 확인한 것 — **미분류 상품이 사라지지는 않는다**

`collect.py` 의 필터 동작을 읽었다.

```js
const ok = (!kind || c.dataset.p === kind)
        && (!sub  || c.dataset.s === sub)     // sub 가 빈 문자열이면 이 조건은 통과
        && (!term || c.dataset.q.includes(term));
```

- **2단 칩을 아무것도 안 골랐을 때(`sub === ''`)** → 미분류 상품도 전부 보인다. ✅
- **2단 칩을 골랐을 때** → 미분류 상품은 숨는다. 이건 필터로서 올바른 동작이다.
- `syncSub()` 가 그 대분류에 실제로 있는 칩만 남기므로 **빈 칩은 안 그려진다.** ✅

→ **대분류 화면에서 상품이 사라지는 사고는 없다.**

### 6-2. 🔴 결론 — **편의점 2단을 지금 켜지 않는다**

지금 켜면 화면에 뜨는 칩이 **`간편식 40` 하나**다. 그리고 그 하나를 누르면 **CU 40장만 남고
세븐일레븐 40장이 사라진다.** 사용자는 "편의점 신상 80개 중 40개가 어디 갔지"를 겪는다.
칩이 하나뿐이라 그게 *필터*인지도 알기 어렵다.

**대신 이 순서로 간다.**

| 단계 | 할 일 | 조건 |
|---|---|---|
| ① | `CVS_SUB` 매핑을 **데이터에 먼저 넣는다**(`brand_sub` 를 채운다). 화면에는 안 띄운다 | 지금 |
| ② | `/c/간편식/` 같은 **유형 페이지만 먼저 만든다** — SEO 유입("편의점 간편식 신상")은 칩 없이도 받는다 | ① 직후 |
| ③ | **중분류 하나가 화면에서 10건을 넘기면** 그때 칩을 켠다 | 데이터가 자란 뒤 |

이건 PRODUCT-PLAN §6-5 F **"세부 건수가 10건을 넘으면 칩 — 콘텐츠 먼저, 탭 나중"** 과 같은 원칙이다.

### 6-3. `기타` 칩은 만들지 않는다

`기타 1,697` 은 **최대 분류가 된다.** 누르면 그 안에 반찬·정육·채소·주류·라면이 다 섞여 나온다.
분류의 목적(원하는 걸 좁히기)을 정반대로 수행한다. **미분류는 칩 없이 둔다.**

### 6-4. 🟢 커버리지를 올리는 길은 하나뿐 — 상품명 정규화

`CU 식품 236` · `세븐 신상품 93` · `이마트24 1,317` 을 가르려면 결국 상품명을 봐야 하는데,
지금 이름이 **`CJ)얼큰우동221g(큰컵)`** 같은 POS 코드다(화면 300장 중 **92장**).
→ **PRODUCT-PLAN P0-3(편의점 상품명 정규화)이 편의점 2단의 선행조건이다.**
PRODUCT-PLAN §5-7 이 이미 "정규화 전에 장르 분류를 시도하면 안 된다"고 결론냈고,
이번 측정이 그걸 다시 확인했다.

## 7. 위험

### 7-1. 🔴 `/c/디저트/` 가 죽는다 — 색인된 주소다

`docs/c/` 현재 16종: `과자 굿즈 도시락 디저트 라면 베이커리 분식 샌드위치 샐러드 일식 치킨 카페 편의점 피자 한식 햄버거`

| | |
|---|---|
| **사라짐** | **`/c/디저트/`** — 던킨 → `도넛`, 배스킨라빈스 → `아이스크림` 으로 갈라져 0건이 된다 |
| 새로 생김 | `/c/커피/` · `/c/도넛/` · `/c/빙수/` · `/c/아이스크림/` · `/c/가공식품/` (+ §6 ② 이후 `/c/간편식/`) |
| 그대로 | 나머지 11종 |

**SEO 피해.** `/c/디저트/` 는 `sitemap.xml` 에 올라가 있었다. 지워지면 **404** 가 되고,
`web/pages.py:374-387` 의 프루너가 **생성되지 않은 경로를 지우므로 파일도 사라진다.**
정적 호스팅(GitHub Pages)이라 **301 리다이렉트를 쓸 수 없다.**

**완화책 — 리다이렉트 스텁을 생성 목록에 넣는다.**

```
docs/c/디저트/index.html  ← 프루너가 지우지 않도록 "생성한 것"으로 등록
  <link rel="canonical" href=".../c/도넛/">
  <meta name="robots" content="noindex">
  <meta http-equiv="refresh" content="0;url=/sinsang-note/c/도넛/">
  본문: "디저트 분류는 도넛 · 아이스크림 · 빙수로 나뉘었습니다." + 세 링크
```

`noindex` + `canonical` 로 색인을 새 주소로 넘기고, 사람에게는 **세 갈래를 보여준다**
(디저트를 찾던 사람이 셋 중 무엇을 원했는지는 우리가 모른다).
🟠 **최소 8주 유지**한 뒤 지운다. 바로 지우면 들어오던 검색 트래픽이 404 로 떨어진다.

### 7-2. 🟠 `음료` · `냉동식품` 은 **빈 분류다**

제조사가 오뚜기 · 팔도 · 오리온 셋뿐이고 전부 라면 · 과자다.
가공식품 2단 실측: **`라면 117` · `과자 10` · 음료 0 · 냉동식품 0.**

**빈 칩은 안 그린다**(`for k in SUBS if scount.get(k)`). 그러니 **`SUBS` 에 미리 넣어두면
수집원이 붙는 날 자동으로 켜진다.** 분류를 숨길 코드를 따로 쓸 필요가 없다.

→ **`음료`·`냉동식품` 을 `SUBS` 에 넣어두되, 그게 "준비됐다"는 뜻은 아니다.**
수집원은 `docs/CANDIDATES-DIRECT2.md` 채택분(롯데칠성음료 · 동서식품 · hy프레딧)이고
그건 PM 의 W10 ② 영역이다.

🔴 **다만 `가공식품` 1단 자체는 비지 않는다** — 화면에 41건(라면 40 + 과자 1)이 있다.
탭을 눌렀더니 0건인 사고는 안 난다.

### 7-3. 🟠 `일식 40` 이 통째로 스시로 한 곳이다

외식 2단에서 `일식` 은 카탈로그 46건인데 화면에는 40장이고 **전부 스시로**다
(`cap_per_brand` 상한 40에 딱 걸려 있다). 분류를 눌렀는데 브랜드 하나만 나오면
그건 분류가 아니라 브랜드 바로가기다 — PRODUCT-PLAN §5-0 이 지적한 그 모양이다.
**이번 개편에서 건드리지 않는다**(지금 구조 그대로다). 브랜드가 늘면 자연히 풀린다.

### 7-4. 🔴 선행조건 — WO-6 이 먼저다

외식 2단이 **9칩 713px**(343px 가용)이다. 지금처럼 선언 순서대로 그리면
가장 큰 `치킨 337`·`한식 288` 이 화면 밖으로 밀릴 수 있고, **밀린다는 표시도 없다.**
→ **`WORK-ORDERS WO-6`(2단 건수 내림차순 + 가로 스크롤 힌트)을 이 개편보다 먼저 머지해라.**
안 하면 분류를 늘린 만큼 사용자가 못 찾는다.

### 7-5. 🟡 1단 건수 배지 제거의 되돌림 조건

§2-3 의 근거는 "지금은 빈 탭이 없고 `#cnt` 가 같은 정보를 준다"이다.
**브랜드가 줄어 어떤 1단이 한 자릿수가 되면 이 판단을 다시 봐라** — 그때는
"눌러보기 전에 비었다는 걸 알려주는" 신호가 다시 필요해진다.
